Как устроен поиск по своим заметкам

Пять ступеней по порядку: как режут текст, как ищут по смыслу, как склеивают поиск по словам и смыслу, как пересортировывают куски и как отвечают только по найденному. Это разбор шага RAG без новых новостей.

Все дорожки — /put.

1 Кусок текста

Зачем это тебе. Чтобы понимать, почему поиск не читает твою длинную заметку целиком, а берёт короткие отрывки.

Заметку режут на куски: короткие отрывки по абзацу или по нескольким предложениям. Кусок текста — это такой отрывок. Его удобно искать и потом показать модели.

Если отдать модели всю книгу сразу, она может не влезть в запрос или потерять нужное место. Куски помогают найти именно то место, где есть ответ, а не «всю папку целиком».

Куски чуть перекрывают друг друга: конец одного и начало следующего совпадают. Так мысль, разрезанная посередине, всё равно попадет в какой-то кусок целиком.

Пример. Из вечерней сводки берут три абзаца про поиск. Каждый абзац — отдельный кусок. Вопрос «что такое гибридный поиск» может попасть именно во второй.

Кусок текста. Короткий отрывок заметки, который хранят и ищут отдельно.

Нарезка. Деление длинного файла на такие отрывки до поиска.

Перекрытие. Небольшой повтор между соседними кусками, чтобы не разрезать мысль пополам.

Заметка. Твой файл или сводка, из которых берут куски.

Длинный файл. Текст, который целиком неудобно класть в один запрос к модели.

Нужное место. Тот кусок, где лежит ответ на вопрос, а не вся папка.

2 Сходство смысла

Зачем это тебе. Чтобы вопрос своими словами находил заметку, даже если в ней другие формулировки.

Сходство смысла — это когда два текста про одно и то же, хотя слова разные. «Как искать по файлам» и «поиск по своим документам» для человека близки. Для обычного поиска по словам — нет: общих слов мало.

Программа переводит кусок в набор чисел, который отражает смысл. Такой набор называют вектором. Похожие по смыслу куски получают близкие наборы чисел. Вопрос тоже переводят в такой набор и ищут ближайшие куски.

Это не чтение «как человек». Это сравнение близости этих наборов. Поэтому иногда рядом окажется кусок с похожей темой, но не с точным ответом — его потом отсеют другие шаги.

Пример. Вопрос «зачем резать текст на куски» находит абзац про нарезку заметок, хотя в абзаце слово «резать» не написано.

Сходство смысла. Близость двух текстов по теме, а не по совпадению слов.

Вектор. Набор чисел, которым программа кодирует смысл куска или вопроса.

Близость. Насколько два вектора похожи: чем ближе, тем кусок скорее подходит.

Вопрос своими словами. Формулировка без точных слов из заметки.

Похожая тема. Кусок рядом по смыслу, но ещё не обязательно с ответом.

Обычный поиск по словам. Ищет совпадения букв, а не смысл.

3 Поиск слов и смысла вместе

Зачем это тебе. Чтобы не терять ни точное имя, ни близкий по смыслу абзац.

Поиск только по словам хорошо ловит точные названия: HarnessPAI, LIBERO, имя файла. Но пропускает пересказ другими словами. Поиск только по смыслу ловит пересказ, но может промахнуться по редкому имени.

Поэтому часто делают оба сразу и потом склеивают результаты. Так называют гибридный поиск: и совпадение слов, и сходство смысла в одном запросе. Сверху можно оставить фильтр — только сводки за октябрь или только один тег.

На выходе получается короткий список кусков-кандидатов. Это ещё не ответ. Это «что показать дальше», прежде чем писать текст человеку.

Пример. Вопрос «что такое OpenShell» находит и карточку, где слово OpenShell написано прямо, и абзац, где его назвали «внешней песочницей для агента».

Гибридный поиск. Один запрос сразу ищет и по словам, и по смыслу.

Поиск по словам. Совпадение точных названий и редких терминов.

Поиск по смыслу. Близкие по теме куски без совпадения формулировок.

Кандидат. Кусок из короткого списка, который ещё будут отбирать.

Фильтр. Ограничение вроде «только октябрь» или «только один тег».

Склейка результатов. Объединение двух списков в один перед следующим шагом.

4 Пересортировка

Зачем это тебе. Чтобы сверху оказался кусок, который реально отвечает на вопрос, а не просто «рядом по теме».

После гибридного поиска у тебя есть десяток кандидатов. Пересортировка — отдельный шаг: программа ещё раз смотрит на вопрос и каждый кусок и ставит лучшие выше. Слабые уходят вниз или выпадают.

Первый поиск широкий и быстрый. Пересортировка уже более внимательная, но только по короткому списку. Так экономят время: не перечитывать всю базу второй раз.

Если этот шаг пропустить, модель может получить кусок «про агентов вообще», хотя ты спрашивал про журнал действий. Тогда ответ будет гладким и мимо.

Пример. Из десяти кусков про агентов вверх поднимают тот, где есть фраза про журнал allow/deny, а общий обзор агентов опускают ниже.

Пересортировка. Повторная расстановка короткого списка кусков от лучшего к худшему.

Кандидат сверху. Кусок, который после пересортировки считают самым полезным.

Широкий поиск. Первый быстрый отбор по всей базе.

Короткий список. Несколько кусков, которые уже можно внимательно сравнить.

Мимо. Кусок рядом по теме, но без ответа на твой вопрос.

Общий обзор. Текст «про всё сразу», который часто мешает точной сверке.

5 Ответ только по найденным кускам

Зачем это тебе. Чтобы можно было открыть абзац и проверить фразу, а не верить уверенному тону.

Найденные куски кладут в запрос к модели и просят ответить только по ним. Если в кусках нет факта, модель должна сказать, что в найденном этого нет, а не дописывать «из общей памяти».

Рядом с ответом полезно держать ссылку на кусок или на сводку. Ты открываешь абзац и смотришь: совпало или ответ что-то приукрасил. Этот приём — и есть RAG: сначала поиск по своим заметкам, потом ответ по найденному.

Без ссылки остаётся только ощущение «звучит умно». Со ссылкой появляется проверка. Если куски плохие, сначала чинят поиск и пересортировку, а не «просят модель ответить увереннее».

Пример. Вопрос по одной вечерней сводке. В ответе — ссылка на абзац. Ты открываешь абзац и видишь, что цифра взята оттуда, а не выдумана.

Ответ по найденному. Текст модели только из тех кусков, которые поиск уже выбрал.

Ссылка на кусок. Указание, какой абзац открыть и сверить.

RAG. Сначала поиск по своим файлам, потом ответ только по найденным кускам.

Общая память. То, что модель «помнит» из обучения; для проверки твоих заметок ей нельзя доверять одной.

Проверка. Ты читаешь исходный абзац и сравниваешь его с ответом.

Плохие куски. Не те отрывки; сначала чинят поиск, а не тон ответа.
