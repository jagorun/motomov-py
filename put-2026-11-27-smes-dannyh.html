Из чего и в каком порядке учить модель: доли источников данных, перемешивание и повторы

Серия про обучение уже разобрала оптимизатор, расписание шага, размер пакета, удаление дублей и вчера — обрезку градиента. Все они отвечают на вопрос «как учить». Сегодня узкий вопрос «на чём и в каком порядке»: большую модель учат не на одном наборе текстов, а на смеси источников — веб-страницы, код, книги, статьи, диалоги. Смесь данных (data mixture) — это правило, по которому при сборке каждого пакета решается, сколько примеров взять из каждого источника. От этого правила зависит, что модель будет уметь хорошо, а что — едва-едва, и ошибку в нём не исправить ни оптимизатором, ни шагом обучения. Испытательный стенд — игрушечная «языковая модель» на numpy: она предсказывает следующий токен по текущему, а каждый источник — своя таблица вероятностей переходов с общей частью и своей частью. Модель нарочно узкая, чтобы источникам было тесно. Это не большая модель, зато каждую цифру можно повторить у себя за минуту. Все числа ниже — игрушечные замеры из наших запусков с указанными зёрнами; на настоящих моделях они будут другими, переносится способ проверки.

Все дорожки — /put. Прошлая — обрезка градиента.

1 Доли источников: как смесь делит ограниченную ёмкость модели

Зачем это в работе. Когда модель плохо пишет код или путается в редком языке, первая мысль — «мало параметров» или «не дообучили». Часто причина проще: в смеси, на которой её учили, этого источника было мало, и при каждом обновлении весов он проигрывал соседям. Доля источника (mixture weight) — вероятность, с которой очередной пример пакета берётся из этого источника. Доли решают, на что модель потратит свою ограниченную ёмкость, и понимать эту механику нужно и тем, кто учит свои модели, и тем, кто выбирает готовую под задачу.

Как это устроено. Обучение уменьшает среднюю потерю по пакету. Если в пакете 90% примеров из источника A, то градиент на 90% состоит из «пожеланий» источника A, и веса двигаются прежде всего туда, где лучше A. Пока модель достаточно велика, чтобы выучить всё сразу, пожелания не мешают друг другу. Когда ёмкость ограничена, модель вынуждена выбирать, и доли превращаются в курс обмена: сколько качества на одном источнике она отдаст за качество на другом.

Важно, что этот курс нелинейный. Первые проценты источника дают больше всего: модель с нуля узнаёт его основную структуру, а платит за это другой источник совсем немного. Последние проценты почти ничего не добавляют своему источнику, зато заметно отнимают у соседей. Поэтому оптимум обычно лежит не на краю, а в широкой плоской середине, где сдвиг долей на десяток процентов почти незаметен.

Источники редко полностью чужие друг другу. У разных текстов общая грамматика, у кода и математики общие привычки рассуждать. Общая часть означает перенос (transfer): обучение на одном источнике помогает другому. Поэтому источник, которого в смеси нет совсем, всё равно не стартует с нуля — но и не получит свою собственную часть структуры.

Отличие от соседнего понятия: удаление дублей и фильтры качества решают, какие документы вообще попадут в данные, а доли — как часто модель будет видеть каждый источник из уже отобранных. Можно иметь идеально чистые данные и всё равно плохую смесь.

Пример. Сначала общий код стенда. Словарь из 48 токенов; каждый источник — таблица вероятностей «какой токен идёт следующим» с общей для всех частью (60%) и своей частью. Вход модели — пара «токен, источник»: в настоящих текстах источник обычно угадывается по контексту, здесь мы просто даём его меткой. Модель переводит вход в вектор размера d и из него — в оценки следующего токена; выходной слой общий для всех источников. Лишние потери — насколько потеря модели выше лучшей возможной (энтропии источника); ноль значит «выучено идеально».

import numpy as np
# Игрушечная «языковая модель»: предсказывает следующий токен по текущему (биграммы).
# Источник данных = своя таблица переходов P[x, y] над общим словарём из V токенов.
# Модель узкая: вход -> вектор размера d -> логиты, поэтому все источники делят одну ограниченную ёмкость.
V = 48
def softmax(z):
    z = z - z.max(-1, keepdims=True); e = np.exp(z); return e / e.sum(-1, keepdims=True)
def raw(seed, rank):
    r = np.random.default_rng(seed)
    return (r.normal(size=(V, rank)) @ r.normal(size=(rank, V))) / np.sqrt(rank)
def make_source(seed, rank=4, sharp=2.5, shared=0.6, noise=0.0):
    # shared — доля общей для всех источников структуры (как общая грамматика у разных текстов);
    # noise — разбавление равномерным шумом (как мусорные страницы: выучить там нечего)
    lg = np.sqrt(shared) * raw(999, 4) + np.sqrt(1 - shared) * raw(seed, rank)
    P = softmax(sharp * lg)
    return (1 - noise) * P + noise / V
def floor(P):  # лучшая возможная потеря = условная энтропия (входы равновероятны)
    return float(-(P * np.log(P + 1e-12)).sum(1).mean())
def sample(P, n, rng, src=0):  # возвращает вход уже со сдвигом на номер источника
    x = rng.integers(0, V, n)
    c = P[x].cumsum(1); u = rng.random((n, 1))
    y = np.minimum((u > c).sum(1), V - 1)
    return x + V * src, y
class Model:
    # Вход — пара (токен, источник): в настоящих текстах источник обычно угадывается по контексту
    # (код, диалог, статья), здесь мы просто даём его меткой. Выходной слой O общий для всех источников.
    def __init__(self, d=6, seed=0, nsrc=4):
        r = np.random.default_rng(seed)
        self.p = {"E": r.normal(0, 0.3, (V * nsrc, d)), "O": r.normal(0, 0.3, (d, V)), "b": np.zeros(V)}
        self.m = {k: np.zeros_like(v) for k, v in self.p.items()}
        self.v = {k: np.zeros_like(v) for k, v in self.p.items()}; self.t = 0
    def logits(self, x): return self.p["E"][x] @ self.p["O"] + self.p["b"]
    def step(self, x, y, lr):
        h = self.p["E"][x]; pr = softmax(h @ self.p["O"] + self.p["b"])
        pr[np.arange(len(y)), y] -= 1; pr /= len(y)
        g = {"O": h.T @ pr, "b": pr.sum(0), "E": np.zeros_like(self.p["E"])}
        np.add.at(g["E"], x, pr @ self.p["O"].T)
        self.t += 1
        for k in self.p:  # Adam
            self.m[k] = 0.9 * self.m[k] + 0.1 * g[k]; self.v[k] = 0.999 * self.v[k] + 0.001 * g[k] ** 2
            mh = self.m[k] / (1 - 0.9 ** self.t); vh = self.v[k] / (1 - 0.999 ** self.t)
            self.p[k] -= lr * mh / (np.sqrt(vh) + 1e-8)
    def true_loss(self, P, src):  # точная потеря на источнике (по всей таблице, без выборки)
        q = softmax(self.logits(np.arange(V) + V * src))
        return float(-(P * np.log(q + 1e-12)).sum(1).mean())
    def loss_on(self, x, y):
        q = softmax(self.logits(x)); return float(-np.log(q[np.arange(len(y)), y] + 1e-12).mean())

Что видно. Без A вообще лишние потери на A равны 1,711 — даже хуже равномерной догадки (3,871 − 2,333 = 1,538): строки входа для A не обучались, и общий выходной слой с ними не справляется. Всего 10% A срезают лишние потери до 0,407, а B при этом не теряет ничего (0,095 → 0,094). Сумма почти не меняется от 30% до 70% (0,373; 0,354; 0,381) — это та самая плоская середина. Это игрушечный замер; на настоящих моделях форма кривой похожа, числа — нет.

Где обычно ошибаются.

  • Делают доли пропорциональными объёму источников «по-честному». Тогда большой веб-источник съедает почти весь пакет, а маленькие ценные источники получают крохи; объём — это предложение, а не ценность.
  • Смотрят на одну среднюю потерю по всей смеси. Средняя может улучшаться, пока потеря на маленьком нужном источнике стоит на месте; потери надо вести отдельно по каждому источнику.
  • Тонко настраивают доли в плоской середине, где разница меньше разброса между зёрнами, и тратят на это запуски, вместо того чтобы проверить края.

Словарь ступени.

Смесь данных (data mixture). Правило, сколько примеров из каждого источника попадает в пакеты обучения.

Доля источника (mixture weight). Вероятность, что очередной пример пакета взят из этого источника.

Ёмкость модели (capacity). Сколько разной структуры модель может удержать одновременно; зависит в первую очередь от числа параметров.

Перенос (transfer). Улучшение на одном источнике благодаря обучению на другом, если у них есть общая структура.

Лишние потери (excess loss). Разница между потерей модели и лучшей возможной потерей на этих данных.

Энтропия источника. Неустранимая неопределённость следующего токена; ниже неё потерю не опустить никакой моделью.

Потери по источникам. Отдельная потеря на проверочных примерах каждого источника вместо одной средней.

2 Порядок подачи: почему данные перемешивают и что ломает «сначала одно, потом другое»

Зачем это в работе. Данные почти всегда хранятся по источникам: отдельные файлы с кодом, с книгами, с вебом. Самый простой способ их читать — подряд, файл за файлом. Тогда при тех же долях модель видит долгие отрезки одного источника, и это меняет результат так же сильно, как сами доли. Понимание этого механизма объясняет, зачем в каждом загрузчике данных стоит перемешивание и почему его размер имеет значение.

Как это устроено. Градиентный спуск помнит не данные, а только текущие веса. Если тысячу шагов подряд приходят примеры только из B, каждый шаг двигает веса туда, где лучше B, и ничто не тянет их обратно к A. Общая для источников часть весов перестраивается под B, и качество на A падает. Это то же катастрофическое забывание (catastrophic forgetting), что и при дообучении: новое обучение стирает старое, если старое больше не встречается.

Насколько сильно забывается, зависит от длины отрезка по сравнению со «скоростью памяти» обучения. Если отрезок одного источника короче, чем нужно оптимизатору, чтобы заметно сдвинуть веса, модель не успевает забыть, и чередование почти не отличается от полного перемешивания. Если отрезок длинный, модель каждый раз успевает переучиться, и качество на источнике качается: высокое в конце его отрезка, низкое в конце чужого.

На практике перемешивают в два слоя. Сначала заранее перемешивают порядок документов и разбивают данные на куски (шарды, shards), в каждом из которых уже есть все источники в нужных долях. Потом загрузчик держит буфер перемешивания (shuffle buffer) — запас из нескольких тысяч примеров, из которого берёт случайные. Буфер помогает, только если он больше отрезков одного источника: если файлы лежат по источникам и в буфере помещается кусок одного файла, буфер перемешивает примеры внутри одного источника, и это ничем не лучше чтения подряд.

Отличие от соседнего понятия: учебный план (curriculum learning) — намеренный порядок, например от простого к сложному. Перемешивание — его противоположность: оно убирает любой порядок, чтобы каждый пакет был похож на всю смесь. Намеренный порядок разберём на пятой ступени; здесь видно, сколько стоит порядок случайный и неосторожный.

Пример. Те же два источника, та же узкая модель, всего 3000 шагов, у всех вариантов ровно половина шагов отдана A и половина B. Меняется только порядок: сначала всё A, потом всё B; блоки по 500, 100 и 10 шагов; полное перемешивание в каждом пакете. Кроме итога, печатаем, как менялись лишние потери на A каждые 500 шагов.

# Ступень 2: те же данные (половина A, половина B), меняем только порядок подачи
from lib import *
A, B = make_source(1), make_source(2); fA, fB = floor(A), floor(B)
STEPS, BS = 3000, 128
def run(order, seed):
    rng = np.random.default_rng(20 + seed); m = Model(seed=seed); trace = []
    for s in range(STEPS):
        xs, ys = order(s, rng)
        m.step(xs, ys, 0.01)
        if (s + 1) % 500 == 0: trace.append(round(m.true_loss(A, 0) - fA, 2))
    return m.true_loss(A, 0) - fA, m.true_loss(B, 1) - fB, trace
def blocks(L):  # L шагов подряд только A, потом L шагов только B, и так далее
    def f(s, rng):
        return sample(A, BS, rng, 0) if (s // L) % 2 == 0 else sample(B, BS, rng, 1)
    return f
def mixed(s, rng):
    n = rng.binomial(BS, 0.5); xa, ya = sample(A, n, rng, 0); xb, yb = sample(B, BS - n, rng, 1)
    return np.r_[xa, xb], np.r_[ya, yb]
for name, order in [("сначала всё A, потом всё B", blocks(1500)), ("блоки по 500 шагов", blocks(500)),
                    ("блоки по 100 шагов", blocks(100)), ("блоки по 10 шагов", blocks(10)), ("перемешано в каждом пакете", mixed)]:
    r = [run(order, seed) for seed in range(3)]

Что видно. При «сначала A, потом B» к шагу 1500 модель знала A почти идеально (0,06), а к концу растеряла до 0,965 — хуже, чем у модели, которая видела A всего в 10% пакетов (0,407 на первой ступени). При блоках по 500 шагов качество на A качается между 0,07 и 0,62, и итог зависит от того, каким блоком закончили: у нас последним был B, отсюда 0,584. Блоки по 100 шагов уже близки, а блоки по 10 неотличимы от полного перемешивания (0,187 и 0,186 на A). Мерили на игрушке с шагом обучения 0,01 и Adam; при другом шаге граница «сколько шагов подряд безопасно» сдвинется, способ проверки тот же.

Где обычно ошибаются.

  • Включают буфер перемешивания и считают вопрос решённым, хотя файлы лежат по источникам и буфер меньше одного файла. Проверка простая: посчитать долю каждого источника в нескольких сотнях подряд идущих пакетов.
  • Оценивают модель в произвольный момент длинного блочного обучения. Результат зависит от того, какой блок был последним, и два соседних замера могут отличаться в разы.
  • Продолжают прерванное обучение с начала файла, а не с того места, где остановились. Модель снова видит те же примеры, а часть данных не видит никогда; позиция загрузчика должна сохраняться в чекпойнте вместе с весами.

Словарь ступени.

Перемешивание (shuffling). Случайный порядок примеров, чтобы каждый пакет был похож на всю смесь.

Катастрофическое забывание (catastrophic forgetting). Потеря выученного на старых данных после долгого обучения только на новых.

Шард (shard). Кусок обучающих данных, который читается целиком; хорошо собранный шард уже содержит смесь.

Буфер перемешивания (shuffle buffer). Запас примеров, из которого загрузчик берёт случайные; перемешивает только то, что в нём помещается.

Блочный порядок. Подача данных отрезками по одному источнику; безопасен, только если отрезки короткие.

Учебный план (curriculum learning). Намеренный порядок подачи данных, например от простого к сложному.

Позиция загрузчика. Где в данных остановилось чтение; сохраняется в чекпойнте, чтобы продолжение не повторяло и не пропускало данные.

3 Маленький источник: температурная выборка и сколько повторов он выдерживает

Зачем это в работе. Самые ценные источники обычно самые маленькие: редкий язык, учебники, проверенные решения задач, документация вашего продукта. Если брать их пропорционально объёму, модель их почти не увидит. Если поднять их долю, модель увидит каждый пример много раз. Где граница между «увидела достаточно» и «вызубрила наизусть», и как вообще выбирать долю маленького источника — вопрос, который встаёт в любом обучении на смеси, от большой предобучки до дообучения на своих данных.

Как это устроено. Эпоха (epoch) — один полный проход по источнику. Доля и объём связаны простой арифметикой: число эпох по источнику равно его доле, умноженной на общее число примеров обучения и делённой на размер источника. Поднимая долю маленького источника, мы не добавляем знаний — мы показываем те же примеры чаще.

Компромисс между «по объёму» и «поровну» задают температурной выборкой (temperature sampling): доля источника берётся пропорционально его размеру в степени α. При α = 1 доли пропорциональны объёму, при α = 0 все источники равны, промежуточные значения поднимают маленькие источники, не уравнивая их полностью. Этот приём широко применяли в многоязычных моделях: в XLM брали α = 0,5, в XLM-R и mT5 — α = 0,3.

Повторы сначала почти так же полезны, как новые данные: модель ещё не выучила общую структуру источника, и второй-третий проход её уточняет. Потом модель начинает подстраиваться под случайные особенности именно этих примеров — это переобучение (overfitting). Признак — растущий разрыв между потерей на своих примерах и на новых примерах того же источника. В исследовании Muennighoff и соавторов (2023) об обучении языковых моделей при нехватке данных до примерно четырёх эпох повторённые данные давали почти то же, что новые, а дальше польза от повторов быстро падала. Это их измерение на их моделях, а не универсальная константа: граница зависит от размера модели и разнообразия источника.

Отличие от соседнего понятия: отсев и затухание весов мешают модели вызубрить данные, но не создают новых. Они сдвигают границу допустимых повторов, а не отменяют её.

Пример. Часть (а) — чистая арифметика: три источника на миллион, сто тысяч и десять тысяч примеров, обучение видит 384 тысячи примеров. Часть (б) — обучение: большой источник A со свежими примерами без ограничений и маленький источник C с фиксированным набором примеров. Меряем лишние потери на новых примерах C (то, что нам нужно) и на его собственных примерах (то, что модель могла вызубрить). Два случая: 3000 примеров C и модель d=8; 500 примеров C и модель пошире, d=16, которой проще вызубрить.

# Ступень 3: маленький источник. (а) арифметика температурной выборки; (б) что делают повторы
from lib import *
sizes = {"большой": 1_000_000, "средний": 100_000, "маленький": 10_000}
TOTAL = 384_000  # столько примеров увидит обучение (3000 шагов по 128)
n = np.array(list(sizes.values()), float)
print("(а) доли источников при p_i ~ n_i^alpha и сколько раз пройдём каждый (эпохи) за", TOTAL, "примеров")
for a in (1.0, 0.5, 0.3, 0.0):
    p = n ** a / (n ** a).sum(); ep = p * TOTAL / n
    print(f"  alpha={a}: доли " + ", ".join(f"{k} {v:.3f}" for k, v in zip(sizes, p)) +
          "; эпохи " + ", ".join(f"{v:.2f}" for v in ep))
A, C = make_source(1), make_source(3); fA, fC = floor(A), floor(C)

    for wC in shares:
        rows = []

              f"на своих примерах C {r[1]:+.3f}, разрыв {r[0]-r[1]:.3f}; на A {r[2]:.3f}")

Это игрушечный замер: здесь граница одна, на вашей модели — другая, но признак переобучения тот же.

Где обычно ошибаются.

  • Поднимают долю маленького источника и смотрят на потерю на обучающих примерах. Она только падает; судить надо по отложенным примерам этого источника, которых модель не видела.
  • Считают, что раз большой модели проще вызубрить, то ей нужно больше повторов. Чаще наоборот: более ёмкая модель переобучается на маленьком источнике раньше.
  • Забывают, что повторы бывают и скрытые: один и тот же текст в нескольких источниках. Без удаления дублей реальное число эпох больше расчётного.

Словарь ступени.

Эпоха (epoch). Один полный проход обучения по источнику или набору данных.

Температурная выборка (temperature sampling). Доли источников пропорциональны их размеру в степени α; меньшее α поднимает маленькие источники.

Параметр α. Ручка температурной выборки: 1 — по объёму, 0 — поровну.

Повторы (repetition). Многократный показ одних и тех же примеров, когда доля источника больше его объёма.

Переобучение (overfitting). Подстройка под случайные особенности обучающих примеров в ущерб новым.

Отложенные примеры (held-out). Примеры источника, которые не участвуют в обучении и служат для честной проверки.

Нехватка данных (data-constrained). Режим, когда уникальных данных меньше, чем могла бы с пользой съесть модель, и приходится повторять.

4 Как подбирают доли: малые пробные запуски и почему наивный подбор тянется к мусору

Зачем это в работе. Полное обучение большой модели запускают один раз, и перебирать на нём доли невозможно. Поэтому доли выбирают заранее, на маленьких пробных моделях, и переносят на большую. Нужно понимать, что такой подбор надёжно ловит, что он не ловит, и в какую ловушку попадает самый очевидный автоматический способ.

Как это устроено. Прямой способ — сетка: обучить много маленьких моделей с разными долями и сравнить потери по источникам на отложенных примерах. Сначала надо решить, что считать «лучше»: сумму лишних потерь, худший источник, качество на конкретных задачах. Разные цели дают разные победители, и выбирать цель надо до запусков, а не после.

Автоматические способы меняют доли по ходу пробного обучения. Очевидная идея — давать больше той области, где потеря выше. Она ломается на шумных источниках: у мусорных страниц потеря высокая всегда, потому что в них нечего учить, и такой подбор будет кормить модель мусором. Высокая потеря — не то же, что «есть чему научиться».

Поэтому разумнее смотреть на лишние потери: насколько текущая модель хуже того, что вообще достижимо на этом источнике. Лучшую возможную потерю на настоящих данных не знает никто, поэтому вместо неё берут опорную модель (reference model) — такую же модель, обученную на простых долях. Так устроен метод DoReMi (Xie и соавторы, 2023): маленькая пробная модель учится, и доли источников, где она сильно отстаёт от опорной, растут; итоговые доли переносят на большую модель. Авторы сообщали об улучшениях на своих данных; ниже мы проверим упрощённую версию идеи на игрушке.

Отличие от соседнего понятия: законы масштабирования предсказывают, как потеря падает с размером модели и данных при фиксированной смеси. Подбор долей решает другой вопрос — какая смесь, — и переносится на большую модель тоже не гарантированно: с ростом ёмкости источникам становится менее тесно, и оптимум может сдвинуться.

Пример. Три источника: A чистый; N наполовину разбавлен случайным шумом (так выглядят мусорные страницы — высокая энтропия, мало структуры); H сложный, с большим числом своей структуры. Первый скрипт сравнивает равные доли, «наивный» подбор по величине потерь, упрощённый подбор по превышению над опорной моделью (точные потери вместо пакетных, раз в 20 шагов, с подмешиванием 10% равных долей) и ручной вариант. Второй скрипт перебирает сетку из 36 вариантов долей на узкой модели d=4 и проверяет лучшие и худший на модели d=12.

# Ступень 4: подбор долей по малым запускам. Три источника:
# A — чистый, N — наполовину мусор (равномерный шум), H — сложный (больше своей структуры)
from lib import *
S = [make_source(1), make_source(4, noise=0.6), make_source(5, rank=10, sharp=3.0)]
names = ["A чистый", "N шумный", "H сложный"]; F = [floor(P) for P in S]
print("нижние границы потерь:", {n: round(f, 3) for n, f in zip(names, F)})
STEPS, BS = 3000, 128
def batch(w, rng):
    k = rng.multinomial(BS, w); xs, ys = [], []
    for i, P in enumerate(S):
        x, y = sample(P, k[i], rng, i); xs.append(x); ys.append(y)
    return np.concatenate(xs), np.concatenate(ys)
def train(w, seed, d=6, every=None, update=None):
    rng = np.random.default_rng(40 + seed); m = Model(d=d, seed=seed); w = np.array(w, float); hist = []
    for s in range(STEPS):
        m.step(*batch(w, rng), 0.01)
        if update and s % every == 0:
            w = update(m, w, s); hist.append(w)
    return m, (np.mean(hist, 0) if hist else w)
def report(tag, w, d=6):
    all_ = np.array([[train(w, seed, d)[0].true_loss(P, i) - F[i] for i, P in enumerate(S)] for seed in range(3)])
    ex = all_.mean(0); sums = all_.sum(1)
    print(f"{tag:34s} доли {np.round(w, 2)} -> лишние потери {np.round(ex, 3)}, худший {ex.max():.3f}, сумма {ex.sum():.3f} (по зёрнам {sums.min():.3f}–{sums.max():.3f})")
uni = np.ones(3) / 3
# 1) опорная модель на равных долях, её потери по источникам — ориентир «что достижимо»
ref, _ = train(uni, 0); ref_loss = np.array([ref.true_loss(P, i) for i, P in enumerate(S)])
print("потери опорной модели (равные доли):", np.round(ref_loss, 3))
# 2) «наивно»: веса пропорциональны текущей потере — тянутся к шумному источнику, где потеря высокая всегда
def naive(m, w, s):
    l = np.array([m.true_loss(P, i) for i, P in enumerate(S)]); return l / l.sum()
# 3) по превышению над опорной моделью (идея DoReMi, упрощённо: точные потери вместо пакетных)
def excess(m, w, s, eta=1.0):
    l = np.array([m.true_loss(P, i) for i, P in enumerate(S)])
    w = w * np.exp(eta * np.maximum(l - ref_loss, 0)); w /= w.sum()
    return 0.9 * w + 0.1 * uni  # подмешиваем равные доли, чтобы ни один источник не обнулился
_, w_naive = train(uni, 7, every=20, update=naive)
_, w_ex = train(uni, 7, every=20, update=lambda m, w, s: excess(m, w, s))
report("равные доли", uni)
report("наивно: по величине потерь", w_naive)
report("по превышению над опорной", w_ex)
report("вручную: шумному меньше", np.array([0.3, 0.1, 0.6]))
print("перенос долей на модель пошире (d=12):")
for tag, w in [("равные доли", uni), ("по превышению над опорной", w_ex)]:
    report("  " + tag, w, d=12)

Игрушечный вывод: пробные запуски надёжно отсекают плохие смеси, но тонкие различия возле оптимума — шум.

Где обычно ошибаются.

  • Повышают долю источников с высокой потерей. Высокая потеря может означать «шум», а не «недоучено»; сравнивать надо с тем, что на источнике достижимо.
  • Выбирают победителя по разнице меньше разброса между зёрнами. Перед тем как верить разнице, повторите запуск с другими зёрнами.
  • Подбирают доли по тем же примерам, на которых потом отчитываются о качестве. Доли подстраиваются под проверочный набор, и отчёт становится завышенным; проверку для подбора и для отчёта держат раздельно.

Словарь ступени.

Пробный запуск (proxy run). Обучение маленькой модели, чтобы дёшево сравнить варианты перед большим обучением.

Сетка (grid search). Перебор заранее заданных вариантов долей с отдельным запуском на каждый.

Опорная модель (reference model). Модель, обученная на простых долях; её потери служат ориентиром «что достижимо».

DoReMi. Метод подбора долей, где растут доли источников, на которых пробная модель сильнее отстаёт от опорной.

Шумный источник. Источник с высокой неустранимой неопределённостью, например мусорные страницы; потеря на нём высокая всегда.

Худший источник. Цель подбора, при которой важен самый слабый источник, а не сумма.

Разброс по зёрнам. Насколько меняется результат при другом случайном начале; разницы меньше него не значат ничего.

5 Когда показывать нужное: источник в конце обучения на спаде шага

Зачем это в работе. Даже при удачных долях остаётся вопрос, когда показывать нужный источник. Одно и то же количество примеров из нужной области можно размазать по всему обучению, дать в начале или собрать в конец. В современных отчётах о больших моделях всё чаще описывают последнюю стадию на отобранных качественных данных; полезно понимать, почему она работает и где из неё получается самообман.

Как это устроено. Работает сочетание двух механизмов. Первый — забывание из второй ступени: то, что показано давно и больше не встречается, постепенно стирается следующими шагами. Значит, нужное показанное в начале к концу обучения в значительной мере потеряется. Второй — расписание шага: в конце шаг обучения обычно уменьшают до нуля. На спаде шага модель окончательно «оседает», и данные этой стадии сильнее всего влияют на итоговые веса, а стереть их уже некому.

Поэтому последнюю стадию обучения с уменьшающимся шагом и повышенной долей качественных данных называют отжигом (annealing). В отчёте о Llama 3 (2024) так описана завершающая стадия: шаг обучения уменьшают до нуля и одновременно повышают долю небольшого набора отобранных данных, в том числе кода и математики; там же отжиг используют как дешёвый способ оценить, полезен ли новый набор данных. Подробности и числа — в самом отчёте; здесь важен механизм.

Ограничение: отжиг поднимает качество на нужной области за счёт остального, только поменьше, чем при той же доле на всё время. И он не заменяет основной смеси: если нужной области не было в основной части обучения, короткая концовка не успеет построить её общую структуру. Кроме того, чем меньше набор для концовки, тем больше повторов и тем ближе переобучение из третьей ступени.

Отличие от соседнего понятия: дообучение — отдельная стадия после обучения, часто на другой задаче и с другими данными, и в ней легко забыть общее. Отжиг — часть того же обучения: та же задача предсказания следующего токена, общий источник продолжает идти в смеси, меняются только доли и шаг.

Пример. Общие источники A и B и нужная нам область Q. 3000 шагов; последние 600 шагов шаг обучения линейно спадает до нуля. У всех планов одинаковое общее число примеров Q — 5% от всего обучения; меняется только, когда их показывают: равномерно, только на спаде шага, только в начале, в первой половине. Для сравнения — без Q вообще. По три зерна.

# Ступень 5: когда подавать нужный источник — равномерно, в конце (на спаде шага) или в начале
from lib import *
A, B, Q = make_source(1), make_source(2), make_source(6)  # A и B — «общие» данные, Q — нужная нам область
fA, fB, fQ = floor(A), floor(B), floor(Q)
STEPS, BS, TAIL = 3000, 128, 600            # последние 600 шагов шаг обучения линейно спадает до нуля
def lr(s): return 0.01 if s < STEPS - TAIL else 0.01 * (STEPS - s) / TAIL
def run(qshare, seed):
    rng = np.random.default_rng(50 + seed); m = Model(seed=seed)
    for s in range(STEPS):
        q = qshare(s); k = rng.multinomial(BS, [(1 - q) / 2, (1 - q) / 2, q]); xs, ys = [], []
        for i, P in enumerate((A, B, Q)):
            x, y = sample(P, k[i], rng, i); xs.append(x); ys.append(y)
        m.step(np.concatenate(xs), np.concatenate(ys), lr(s))
    return m.true_loss(Q, 2) - fQ, (m.true_loss(A, 0) - fA + m.true_loss(B, 1) - fB) / 2
plans = {  # у всех планов одинаковое общее число примеров Q: 5% от всего обучения
    "Q 5% всё время": lambda s: 0.05,
    "Q 25% только на спаде шага (последние 20%)": lambda s: 0.25 if s >= STEPS - TAIL else 0.0,
    "Q 25% только в начале (первые 20%)": lambda s: 0.25 if s < TAIL else 0.0,
    "Q 10% в первой половине, 0 во второй": lambda s: 0.10 if s < STEPS / 2 else 0.0,
    "без Q вообще": lambda s: 0.0,
}
for name, f in plans.items():
    r = np.array([run(f, seed) for seed in range(3)])
    print(f"{name:44s}: лишние потери на Q {r[:,0].mean():.3f} (по зёрнам {r[:,0].min():.3f}–{r[:,0].max():.3f}), на общих A+B {r[:,1].mean():.3f}")

Q 25% только на спаде шага (последние 20%)  : лишние потери на Q 0.336 (по зёрнам 0.319–0.345), на общих A+B 0.185
Q 25% только в начале (первые 20%)          : лишние потери на Q 0.618 (по зёрнам 0.564–0.673), на общих A+B 0.167
Q 10% в первой половине, 0 во второй        : лишние потери на Q 0.464 (по зёрнам 0.454–0.484), на общих A+B 0.163

Что видно. То же количество примеров Q, собранное на спад шага, дало лучший результат на Q: 0,336 против 0,393 при равномерной подаче, и разбросы по зёрнам не пересекаются (0,319–0,345 против 0,379–0,418). Плата — общие источники чуть хуже (0,185 против 0,177). Q в самом начале — худший вариант из тех, где Q был (0,618): модель выучила и забыла. Первая половина — посередине (0,464). Без Q вообще — 2,018, то есть даже 5% нужной области важнее любых тонкостей порядка. Игрушечный замер на одной модели; величина выигрыша на настоящих моделях другая, направление объясняется теми же двумя механизмами.

Где обычно ошибаются.

  • Кладут в концовку данные, похожие на проверочные задачи, или прямо их куски. Качество на этих задачах растёт, а настоящая способность — нет; это загрязнение проверки (contamination), и концовку надо сверять с проверочными наборами на совпадения.
  • Делают концовку из очень маленького набора и повторяют его десятки раз. На спаде шага модель особенно легко запоминает конкретные примеры.
  • Сравнивают модель после концовки с промежуточным чекпойнтом без спада шага. Часть выигрыша даёт сам спад, а не данные; честное сравнение — такой же спад на обычной смеси.

Словарь ступени.

Отжиг (annealing). Завершающая стадия обучения, где шаг обучения уменьшают до нуля и повышают долю отобранных данных.

Спад шага (decay). Часть расписания, в которой шаг обучения уменьшается; данные этой части сильнее всего влияют на итоговые веса.

Нужная область (target domain). Тип данных, качество на котором важнее всего для задачи модели.

Многостадийное обучение. Обучение, разбитое на стадии с разными смесями, например основная часть и концовка.

Загрязнение проверки (contamination). Попадание проверочных примеров или их близких копий в обучение; оценка становится завышенной.

Промежуточный чекпойнт. Сохранённые веса в середине обучения, до спада шага; сравнивать его с итогом после спада нечестно.

Подача по времени. Решение не только сколько, но и когда показывать каждый источник.
