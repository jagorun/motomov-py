00. Введение и шесть умений оркестратора

Дата сборки: 11 октября 2026
Для кого: человек, который идёт от технического документа (РЭ, ТУ, ПМ) к роли оркестратора AI-систем.
Что такое оркестратор в этой методичке: человек, который задаёт цель так, чтобы её можно было провалить; собирает схему связей; смотрит след (а не вкус); ставит потолок (шаги, деньги, повтор); улучшает систему по дыре, а не по моде.

Документы — временный зал. Глаз, который видит, чего в тексте нет, переносится на любую систему агентов и знаний.

Эта методичка — подробная карта Python-знаний, необходимых, чтобы пройти лестницу оркестратора своими руками. Не «выучить язык программирования», а получить мышцы контроля: контракт, отказ, след, потолок.

Что оркестратор делает руками в коде

Ниже шесть умений мастера. Для каждого — что это значит простыми словами, почему без него система врёт или раздувается, и как это выражается в Python.

1. Цель, которую можно провалить

Что это.
Цель сформулирована так, что есть чёткий вход, чёткий запрет, признак «готово» и заранее известное поведение, если источника нет или условие не выполнено. Не «сделай хорошо», а «если в папке нет файла с ответом — верни строку „не знаю“ и не выдумывай имя файла».

Почему важно.
Без этого агент всегда «успешен»: красиво отвечает, даже когда данных нет. Оркестратор умеет поставить задачу, которую система может честно провалить.

Как выглядит в Python.
Функция с явным контрактом:

  • принимает конкретные аргументы;
  • возвращает либо ожидаемый результат, либо явное значение отказа (None, специальная строка, исключение);
  • не глотает ошибку молча.
def answer(query: str, sources: list[str]) -> str:
    if not sources:
        return "не знаю"          # цель можно провалить
    # ... иначе работаем

2. Схема

Что это.
Один понятный лист: какие узлы есть, из какого узла в какой можно перейти, где сидит человек, что нельзя менять. Армия без схемы — толпа.

Почему важно.
Чат не управляется. Управляется схема: откуда ход пришёл, куда имеет право перейти, где остановиться.

Как выглядит в Python.
Словарь состояния + цикл с условиями, или граф (LangGraph). Даже простой while с явными ветками уже схема.

state = {
    "step": 0,
    "max_steps": 5,
    "found": False,
    "log": []
}
# узлы: поиск → проверка → генерация или отказ

3. Контракт связи

Что это.
Инструмент (функция, API, поиск по файлам) имеет право прочитать вот это и не имеет права изменить вот это. Молчание инструмента — тоже ответ, который надо зафиксировать.

Почему важно.
Без контракта инструмент «чуть-чуть» меняет данные или молчит, и след ломается.

Как выглядит в Python.
Type hints, Pydantic-валидация, чёткий return, документация функции (что принимает, что возвращает, когда отказывает).

4. Проверка следа, не вкуса

Что это.
Смотрим не «красиво ли получилось», а какой шаг был сделан, с каким аргументом, в каком порядке. Итог сошёлся, а дорога врёт — это слабое место.

Почему важно.
Красивый ответ без источника или с выдуманным файлом — обман. След позволяет поймать это повторно.

Как выглядит в Python.
Логирование каждого шага + тесты на три обязательных случая:

  • пустой поиск → «не знаю»;
  • битый ответ модели → отказ;
  • «не знаю» не проходит молча.

5. Потолок

Что это.
Жёсткие ограничения: максимум шагов, максимум токенов/денег на задачу, максимум повторов при ошибке. Масштаб без потолка — это счёт, а не система.

Почему важно.
Без потолка агент может крутиться бесконечно или сжечь бюджет за один вопрос.

Как выглядит в Python.
Счётчики в цикле, класс Budget, проверка перед каждым дорогим вызовом, break при достижении лимита.

6. Улучшение по дыре, не по моде

Что это.
Сначала делаем одну ветку, которая врёт предсказуемо (и ловим это тестом). Потом вторую. Четыре агента «для вида» прячут слабость.

Почему важно.
Красивый README с пятью агентами, которые молча выдумывают, хуже одного простого графа с честным отказом.

Как выглядит в Python.
Один рабочий контур (скрипт → поиск → вызов → граф), тесты, которые падают, если отказ сломался. Мультиагентность только после того, как один граф стабилен.

Доработка: шесть умений в одном маленьком примере

Шесть умений выше легко прочитать как шесть отдельных правил. На деле они всегда работают вместе, и проще всего это увидеть на одной функции на 30 строк. Ниже «вопрос к файлам» без всякой модели — только словарь с текстами. Найди в коде каждое из шести умений: они помечены комментариями [1]…[6].

DOCS = {
    "re_kamera.md": "Камера включается кнопкой POWER. Аккумулятор держит 90 минут.",
    "tu_shtativ.md": "Штатив выдерживает до 5 кг.",
}

def ask(query: str, docs: dict[str, str], max_steps: int = 3) -> dict:
    """[3] Контракт: читает docs, НЕ меняет их; всегда возвращает dict
    с ключами answer, source, log. При отсутствии источника answer == "не знаю"."""
    log = []                                    # [4] след
    words = [w.lower() for w in query.split() if len(w) > 3]
    step = 0
    for name, text in docs.items():             # [2] схема: поиск -> проверка -> ответ/отказ
        step += 1
        if step > max_steps:                    # [5] потолок
            log.append(f"шаг {step}: потолок {max_steps}, останавливаюсь")
            break
        hit = any(w in text.lower() for w in words)
        log.append(f"шаг {step}: {name} -> {'есть' if hit else 'нет'}")
        if hit:
            return {"answer": text, "source": name, "log": log}
    return {"answer": "не знаю", "source": None, "log": log}   # [1] цель можно провалить

r1 = ask("сколько держит аккумулятор", DOCS)
r2 = ask("какая гарантия на объектив", DOCS)
print(r1["source"], "|", r1["answer"])
print(r2["answer"], r2["log"])
# [6] улучшение по дыре: сначала тест на отказ, потом всё остальное
assert r2["answer"] == "не знаю" and r2["source"] is None
print("отказ проверен")
# ожидаем: re_kamera.md | Камера включается кнопкой POWER. Аккумулятор держит 90 минут.
# ожидаем: отказ проверен

Что здесь важно увидеть:

  • [1] и [4] неразделимы. Отказ «не знаю» без журнала ничего не доказывает: может быть, поиск вообще не запускался. Журнал шаг 1: re_kamera.md -> нет, шаг 2: tu_shtativ.md -> нет показывает, что отказ честный — оба файла посмотрели.
  • [3] контракт записан в docstring словами. Это первая форма контракта, ещё до type hints и Pydantic. Если в docstring нельзя написать, что функция делает при отсутствии данных, — контракта нет.
  • [5] потолок срабатывает даже в простом for. Сто файлов в папке — и без max_steps поиск честно пройдёт все сто, что для поиска по диску нормально, а для ста вызовов модели — счёт.
  • [6] тест пишется на отказ первым. Успешный путь «и так видно», а сломанный отказ молча превращается в выдумку.

Типичная ошибка новичка: вернуть в случае отказа другую форму данных, например просто строку "не знаю", а в случае успеха словарь. Вызывающий код тогда падает на r["source"] ровно в тот день, когда данных нет. Правило: успех и отказ возвращают одинаковую форму, отличаются только значения.

Аналогия из жизни документалиста. Монтажный лист заполняется и для удачных, и для бракованных дублей, в одних и тех же графах. Если брак записывать «на полях», через месяц никто не отличит «не снимали» от «сняли, но в брак».

Мини-упражнение. Допиши в ask защиту от пустого вопроса: если в query нет ни одного слова длиннее трёх букв, функция должна сразу вернуть отказ и записать в журнал причину, не просматривая файлы.

<details><summary>Решение</summary>

def ask(query: str, docs: dict[str, str], max_steps: int = 3) -> dict:
    log = []
    words = [w.lower() for w in query.split() if len(w) > 3]
    if not words:
        log.append("пустой вопрос: нечего искать")
        return {"answer": "не знаю", "source": None, "log": log}
    step = 0
    for name, text in docs.items():
        step += 1
        if step > max_steps:
            log.append(f"шаг {step}: потолок {max_steps}")
            break
        if any(w in text.lower() for w in words):
            log.append(f"шаг {step}: {name} -> есть")
            return {"answer": text, "source": name, "log": log}
        log.append(f"шаг {step}: {name} -> нет")
    return {"answer": "не знаю", "source": None, "log": log}

r = ask("и а", {"a.md": "и а и а"})
print(r["answer"], r["log"])
# ожидаем: не знаю ['пустой вопрос: нечего искать']

Обрати внимание: без этой проверки вопрос «и а» мог бы «найти» что угодно по коротким словам. Пустой вход — это тоже случай, который цель должна уметь провалить.
</details>

Правила работы с этой методичкой

  1. Читай последовательно. Не прыгай к вызову модели, пока не закрыты основы своими руками.
  2. Параллельно с курсами Stepik пиши свой контур: сначала скрипт «папка → сводка», потом «вопрос к файлам с отказом».
  3. Один репозиторий / одна папка через все ступени. Не пять учебных поделок.
  4. Нагрузка: 45–75 минут, пять вечеров в неделю. Пропуск двух дней не ломает. Пропуск двух недель ломает.
  5. Локальные модели и четыре агента — только после работающего контура с тормозом.

Доработка: как вести свой контур, чтобы правила не остались на бумаге

Правило 3 «одна папка через все ступени» проще соблюдать, если с первого дня у папки есть скелет и привычка. Предлагаемая раскладка (её можно завести уже на Ступени 1, пустые файлы — нормально):

kontur/
  data/            # .md-файлы, по которым ищем (копии, не оригиналы!)
  kontur/          # код: по одному модулю на шаг
    search.py
    answer.py
  tests/
    test_otkaz.py  # три обязательных случая из умения 4
  journal.md       # дневник: дата, что сделал, какая дыра найдена
  README.md        # одна страница: цель, вход, отказ, потолок

Журнал важнее кода. Каждый вечер — 3 строки в journal.md:

2026-10-12 | сделал: чтение одного файла | дыра: падает на пустом файле | завтра: проверка len(text) == 0

Третья графа — это и есть умение 6 «улучшение по дыре». Если неделю подряд в графе «дыра» пусто, значит, ты не проверяешь систему, а только добавляешь функции.

Типичные ошибки при работе по методичке:

  1. Читать без набора кода. Через неделю остаётся ощущение «понятно», но пустой редактор пугает. Любой пример из методички перепечатай руками и сломай одну строку — посмотри, какая будет ошибка.
  2. Прыгнуть к API модели «на минутку». Первый же ответ модели выглядит так убедительно, что желание писать отказ и тесты пропадает. Правило 1 защищает именно от этого.
  3. Переписывать с нуля вместо правки. Новый репозиторий на каждую ступень — это пять поделок без истории. Правка старого кода и есть тренировка оркестратора: понять, что уже работает, и не сломать.
  4. Компенсировать пропуск марафоном. Пять часов в выходной не заменяют пяти вечеров: навык держится повторением, а не объёмом.

Мини-упражнение. Напиши скрипт, который дописывает строку в journal.md в формате выше, подставляя сегодняшнюю дату, и не затирает старые записи.

<details><summary>Решение</summary>

from datetime import date
from pathlib import Path

def add_entry(path: Path, done: str, hole: str, tomorrow: str) -> str:
    line = f"{date.today().isoformat()} | сделал: {done} | дыра: {hole} | завтра: {tomorrow}\n"
    with path.open("a", encoding="utf-8") as f:   # "a" = дописать в конец, не "w"!
        f.write(line)
    return line

p = Path("journal.md")
add_entry(p, "чтение файла", "пустой файл", "проверка длины")
add_entry(p, "проверка длины", "файла нет", "try/except FileNotFoundError")
print(len(p.read_text(encoding="utf-8").splitlines()))
# ожидаем: 2

Главное — режим "a". С режимом "w" каждый вечер журнал начинался бы с чистого листа, а это та же ошибка «затёр прошлое», от которой методичка защищается правилом «дополняй, не затирай».
</details>

1.1. Переменные и типы данных

Что такое переменная

Переменная — это имя, под которым Python хранит значение в памяти.
Аналогия: ярлык на коробке. Коробка может содержать яблоко (число), записку (строку) или целую полку (список). Имя ярлыка — это имя переменной.

count = 0          # ярлык "count" указывает на число 0
name = "документ"  # ярлык "name" указывает на строку

Важно: в Python тип привязан к значению, а не к переменной. Одна и та же переменная может в разные моменты указывать на разные типы (но для оркестратора это почти всегда плохая идея — лучше держать ясность).

Доработка: «пустые» значения, is None и ловушка input()

В таблице типов есть None, пустая строка "", ноль 0 и пустой список []. Для if все четыре «ложные» — и именно поэтому их легко перепутать. Для оркестратора разница принципиальная: «инструмент ничего не нашёл» ([]), «инструмент не ответил» (None) и «нашёл ноль ошибок» (0) — это три разных события в следе.

for value in [None, "", 0, [], "0", " ", [None]]:
    print(repr(value).ljust(8), "-> if считает:", bool(value))

Вывод покажет, что "0", " " и [None] — истинные: строка из нуля или пробела не пустая, список с одним None тоже не пустой.

Ошибка 1. if not result вместо if result is None.

def count_errors(log: list[str]) -> int | None:
    if log is None:
        return None
    return sum(1 for line in log if "ERROR" in line)

errors = count_errors(["ok", "ok"])   # 0 ошибок — хорошая новость
if not errors:
    print("ПЛОХО: решили, что подсчёт не удался")
if errors is None:
    print("подсчёт не удался")
else:
    print(f"ХОРОШО: ошибок {errors}")
# ожидаем: ХОРОШО: ошибок 0

Правило: is None — когда спрашиваешь «был ли ответ»; if not x — когда спрашиваешь «есть ли в ответе содержимое».

Ошибка 2. input() всегда возвращает строку. На Stepik это первая ловушка: input() даёт "5", а не 5.

raw = "5"            # так выглядит то, что вернул бы input()
print(raw * 2)       # 55 — склейка строк, не умножение
n = int(raw)
print(n * 2)         # 10

Если в строке не число, int("пять") бросит ValueError — это ещё один «вход, который надо уметь провалить» (см. 1.7).

Ошибка 3. Одна переменная — два типа. Раздел выше уже говорит, что это «плохая идея». Вот как это выглядит в жизни:

result = "не знаю"          # иногда строка-отказ...
result = ["a.md", "b.md"]   # ...иногда список источников
# дальше в коде: len(result) — 7 для строки, 2 для списка. Оба «работают», один врёт.
print(len("не знаю"), len(["a.md", "b.md"]))

Лучше: sources: list[str] всегда список (пустой — значит, ничего нет), а отказ — отдельная переменная или явный None.

Аналогия из жизни техника. Индикатор «0 дБ» на пульте и погасший индикатор — разные вещи: первый говорит «сигнал есть, уровень номинальный», второй — «сигнала нет или прибор выключен». 0 и None — ровно эта разница.

Мини-упражнение. Напиши parse_count(raw: str) -> int | None: убирает пробелы, возвращает целое число, если строка — число (в том числе "0"), и None, если строка пустая или не число. Не используй try — только методы строк.

<details><summary>Решение</summary>

def parse_count(raw: str) -> int | None:
    s = raw.strip()
    if not s.isdigit():       # "" и "пять" -> False
        return None
    return int(s)

for raw in [" 12 ", "0", "", "пять"]:
    r = parse_count(raw)
    print(repr(raw), "->", "нет числа" if r is None else r)
# ожидаем: '0' -> 0
# ожидаем: '' -> нет числа

Обрати внимание: для "0" результат 0, и проверка r is None правильно говорит «число есть». С проверкой if not r ноль превратился бы в «нет числа». (isdigit не принимает минус — для отрицательных понадобится try/int, это тема 1.7.)
</details>

1.2. Управление потоком выполнения

Поток выполнения — это порядок, в котором выполняются строки кода.
По умолчанию сверху вниз. Оркестратор управляет ветками и остановками.

Условный оператор if / elif / else

Что это.
Проверка условия. Если условие истинно (True) — выполняется один блок, иначе — другой.

Аналогия: развилка на дороге. «Если дождь — взять зонт, иначе идти без него».

if not sources:                    # если список пуст
    answer = "не знаю"
elif len(sources) > 5:             # иначе если слишком много
    answer = "слишком много источников, уточни запрос"
else:                              # во всех остальных случаях
    answer = generate(sources)

Термины:

  • if — если.
  • elif (else if) — иначе если.
  • else — иначе (выполняется, только если все предыдущие условия ложны).
  • Условие — выражение, которое даёт True или False.

Частые ошибки:

  • Забыл двоеточие :.
  • Неправильный отступ (Python смотрит на пробелы).
  • Путает = (присваивание) и == (сравнение).

Цикл for

Что это.
Повторяет блок кода для каждого элемента коллекции.

Аналогия: раздать каждому гостю по конверту.

files = ["a.md", "b.md", "c.md"]
for file in files:
    print(f"Обрабатываю {file}")

Термины:

  • for — для.
  • in — в.
  • Переменная цикла (file) на каждой итерации получает следующий элемент.

Цикл while — здесь ты сейчас

Что это.
Повторяет блок, пока условие истинно.

Аналогия: «Пока не нашёл ключ — продолжай искать, но не больше 10 попыток».

attempts = 0
max_attempts = 5
success = False

while attempts < max_attempts and not success:
    result = call_tool()
    attempts += 1
    if result is not None:
        success = True
        break          # немедленный выход из цикла
    # если не нашли — продолжаем
else:
    # блок else у while выполняется, только если цикл закончился без break
    print("Потолок достигнут, отказ")

Ключевые термины и механизмы:

  • Условие выхода — то, что рано или поздно станет False. Без него — бесконечный цикл.
  • break — немедленный выход из цикла.
  • continue — перейти к следующей итерации, пропустив оставшийся код в текущей.
  • else у цикла — выполняется, если цикл завершился нормально (без break).

Типичные ошибки while (90% новичков):

  1. Забыл увеличить счётчик → бесконечный цикл.
  2. Условие всегда True.
  3. Поставил break слишком рано.
  4. Путает, когда выполняется else.

Зачем оркестратору.
while с max_attempts — это уже маленький тормоз (потолок попыток). Позже он превратится в граф с ограничением шагов.

Разбор типичных ошибок while — подробно

Короткий список выше — это «что». Здесь — «как это выглядит в коде, что произойдёт и как починить». Для каждой ошибки: плохой код → что случится → исправленный код.

Плохие примеры с бесконечным циклом не запускай просто так. Если очень хочется посмотреть — запускай в терминале и будь готов нажать Ctrl+C (это прерывает программу).

Ошибка 1. Бесконечный цикл: забыли изменить переменную условия.

# ПЛОХО — не запускать без Ctrl+C
attempts = 0
while attempts < 3:
    print("Попытка", attempts)
    # забыли attempts += 1

Что произойдёт: attempts навсегда остаётся 0, условие 0 < 3 всегда True. Экран заливает строками «Попытка 0», программа не заканчивается.

# ИСПРАВЛЕНО
attempts = 0
while attempts < 3:
    print("Попытка", attempts)
    attempts += 1      # условие сдвигается к False на каждой итерации
# Попытка 0
# Попытка 1
# Попытка 2

Правило: в теле while обязательно должна быть строка, которая меняет то, что проверяется в условии.

Ошибка 2. Ошибка на единицу (< вместо <=).

Задача: напечатать номера дублей с 1 по 5.

# ПЛОХО
i = 1
while i < 5:
    print(i)
    i += 1
# 1 2 3 4 — пятого дубля нет

Что произойдёт: цикл остановится на i == 5, потому что 5 < 5 — это False. Потерян последний элемент. Ошибки не будет — и именно поэтому её трудно заметить.

# ИСПРАВЛЕНО
i = 1
while i <= 5:      # «включая 5»
    print(i)
    i += 1
# 1 2 3 4 5

Как проверять себя: мысленно прогони первую и последнюю итерацию. «С какого значения начинаю? На каком значении условие впервые станет False? Сколько раз выполнится тело?» Для i = 1; while i < 5 — 4 раза, для while i <= 5 — 5 раз.

Ошибка 3. Счётчик меняется не в той ветке / continue перед инкрементом.

Вариант А: continue перепрыгивает через i += 1.

# ПЛОХО — не запускать без Ctrl+C
i = 0
while i < 10:
    if i % 2 == 0:
        continue       # уходим на новую итерацию, НЕ увеличив i
    print(i)
    i += 1

Что произойдёт: i = 0 — чётное, срабатывает continue, строка i += 1 не выполняется. На следующей итерации снова i = 0… Программа зависает молча, ничего не печатая (это хуже, чем бесконечный вывод: кажется, что «просто долго думает»).

Вариант Б: счётчик попыток растёт только в ветке «успех».

# ПЛОХО — не запускать без Ctrl+C
attempts = 0
while attempts < 3:
    result = None              # представим, что инструмент молчит
    if result is not None:
        attempts += 1          # счётчик растёт только при успехе...
        break
    # ...а при неудаче — не растёт, потолок никогда не наступит

Что произойдёт: при каждой неудаче attempts остаётся 0. Потолок попыток, ради которого всё затевалось, не работает.

# ИСПРАВЛЕНО (вариант А): сдвигаем счётчик ПЕРВОЙ строкой тела
i = 0
while i < 10:
    i += 1
    if i % 2 == 0:
        continue       # теперь пропуск безопасен: i уже изменился
    print(i)
# 1 3 5 7 9

# ИСПРАВЛЕНО (вариант Б): попытка считается всегда, независимо от исхода
attempts = 0
max_attempts = 3
result = None
while attempts < max_attempts:
    attempts += 1              # попытка потрачена в любом случае
    result = None              # инструмент снова молчит
    if result is not None:
        break
print("Попыток потрачено:", attempts)   # Попыток потрачено: 3

Правило: счётчик попыток — это «сколько раз я пробовал», а не «сколько раз получилось». Увеличивай его в начале тела, до любых continue и if.

Ошибка 4. while True без break или с недостижимым break.

# ПЛОХО — не запускать без Ctrl+C
attempts = 0
while True:
    attempts += 1
    if attempts == 0:      # после += 1 attempts никогда не будет 0
        break              # break есть, но до него невозможно дойти

Что произойдёт: break формально есть, но условие перед ним никогда не выполняется. Цикл бесконечный. Тот же результат, если break вообще забыли написать.

# ИСПРАВЛЕНО
attempts = 0
max_attempts = 3
while True:
    attempts += 1
    print("Дубль", attempts)
    if attempts >= max_attempts:   # >= надёжнее, чем ==: не «проскочит» мимо
        break
# Дубль 1
# Дубль 2
# Дубль 3

Правило: while True допустим, только если ты можешь показать пальцем строку с break и объяснить, почему условие перед ней обязательно когда-нибудь станет истинным. Если не можешь — пиши условие прямо в while.

Ошибка 5. Изменение списка во время обхода через while с индексом.

Задача: убрать пустые имена файлов из списка.

# ПЛОХО
files = ["a.md", "", "", "b.md"]
i = 0
while i < len(files):
    if files[i] == "":
        files.pop(i)       # элементы справа сдвинулись влево...
    i += 1                 # ...а мы всё равно шагнули вперёд
print(files)
# ['a.md', '', 'b.md'] — одна пустая строка выжила

Что произойдёт: после pop(1) второй "" переехал на место с индексом 1, но i уже стал 2 — элемент пропущен. Программа не падает, просто даёт неверный результат. Похожая ловушка с append внутри цикла может привести к бесконечному обходу: список растёт быстрее, чем i.

# ИСПРАВЛЕНО (вариант 1): двигаем индекс, только если ничего не удаляли
files = ["a.md", "", "", "b.md"]
i = 0
while i < len(files):
    if files[i] == "":
        files.pop(i)       # на место i приехал следующий элемент — проверим его
    else:
        i += 1
print(files)               # ['a.md', 'b.md']

# ИСПРАВЛЕНО (вариант 2, проще и надёжнее): не меняем исходный список, строим новый
files = ["a.md", "", "", "b.md"]
clean = [f for f in files if f != ""]
print(clean)               # ['a.md', 'b.md']

Ошибка 6. Неверное условие с and / or.

Задача: пробовать, пока не нашли источник, но не больше 5 попыток.

# ПЛОХО — не запускать без Ctrl+C
attempts = 0
found = False
while attempts < 5 or not found:     # or вместо and
    attempts += 1
    found = False                    # источник так и не нашёлся

Что произойдёт: or истинно, если истинна хотя бы одна часть. После 5 попыток attempts < 5 стало False, но not found всё ещё True → цикл продолжается. Потолок не работает, цикл бесконечный.

# ИСПРАВЛЕНО
attempts = 0
found = False
while attempts < 5 and not found:    # продолжаем, только если ОБА условия верны
    attempts += 1
    found = False
print("Попыток:", attempts, "найдено:", found)   # Попыток: 5 найдено: False

Как не путаться. Сначала сформулируй условие остановки: «стоп, если попытки кончились или нашли». Условие продолжения — его отрицание: «продолжаем, если попытки не кончились и не нашли». Отрицание меняет или на и (закон де Моргана): not (A or B) == (not A) and (not B).

Ошибка 7. Сравнение float на равенство.

# ПЛОХО — не запускать без Ctrl+C
x = 0.0
while x != 1.0:
    x += 0.1

Что произойдёт: дробные числа хранятся в памяти приближённо. После десяти сложений x равно 0.9999999999999999, а не 1.0. Условие x != 1.0 остаётся True, x «проскакивает» мимо 1.0 и растёт бесконечно.

print(0.1 + 0.1 + 0.1 == 0.3)   # False
print(0.1 + 0.1 + 0.1)          # 0.30000000000000004
# ИСПРАВЛЕНО (вариант 1, лучший): считаем шаги целым числом, float вычисляем
step = 0
while step < 10:
    step += 1
    x = step / 10
print(x)                        # 1.0

# ИСПРАВЛЕНО (вариант 2): сравнение с допуском + страховочный потолок
import math
x = 0.0
guard = 0
while not math.isclose(x, 1.0) and guard < 100:
    x += 0.1
    guard += 1
print(round(x, 2), guard)       # 1.0 10

Правило: в условии while используй целые счётчики. Если без float никак — < / > или math.isclose, и всегда страховочный потолок итераций.

  1. Что именно проверяет условие?
  2. Какая строка в теле меняет это — и выполняется ли она на каждой итерации (нет ли continue / if перед ней)?
  3. Есть ли потолок (max_attempts), который сработает, даже если «успех» не наступит никогда?

Упражнение 1. Обратный отсчёт перед записью.

Дано n = 5. С помощью while выведи числа от n до 1 (каждое на новой строке), а после цикла — слово Мотор!.

Подсказка: условие — «пока n больше нуля»; в теле не забудь уменьшать n.

<details><summary>Решение</summary>

n = 5
while n > 0:
    print(n)
    n -= 1          # без этого — бесконечный цикл (ошибка 1)
print("Мотор!")
# 5
# 4
# 3
# 2
# 1
# Мотор!

</details>

Упражнение 2. Сумма цифр числа.

Дано n = 2026. Найди сумму его цифр с помощью while (ответ: 10). Не превращай число в строку — работай арифметикой.

Подсказка: n % 10 — последняя цифра, n // 10 — число без последней цифры. Продолжай, пока n > 0.

<details><summary>Решение</summary>

n = 2026
total = 0
while n > 0:
    total += n % 10     # забрали последнюю цифру
    n //= 10            # отрезали её — условие движется к False
print(total)            # 10

</details>

Упражнение 3. Дубли с лимитом.

Результаты плейбэка лежат в списке takes = ["брак", "брак", "ок", "брак"]. Проходи по дублям с помощью while и индекса, пока не встретишь "ок", но просмотри не больше max_takes = 3 дублей. Если удачный дубль найден — выведи Удачный дубль №3 (номер считаем с 1). Если нет — Лимит исчерпан. Проверь решение ещё и на takes = ["брак", "брак", "брак", "ок"] — должно быть Лимит исчерпан.

Подсказка: в условии нужны сразу два ограничения: потолок max_takes и конец списка (len(takes)). Для итогового сообщения удобно использовать break и else у цикла.

<details><summary>Решение</summary>

def find_good_take(takes, max_takes=3):
    i = 0
    while i < max_takes and i < len(takes):
        if takes[i] == "ок":
            print(f"Удачный дубль №{i + 1}")
            break
        i += 1
    else:
        # сюда попадаем, только если цикл закончился без break
        print("Лимит исчерпан")

find_good_take(["брак", "брак", "ок", "брак"])   # Удачный дубль №3
find_good_take(["брак", "брак", "брак", "ок"])   # Лимит исчерпан

</details>

Аналогия из жизни техника/документалиста: дубли с лимитом

Ты снимаешь интервью-синхрон. Сцену переписывают, пока не получится чистый дубль, — но у героя есть 20 минут, а у тебя заряда на ограниченное число попыток. Режиссёр заранее говорит: «Максимум пять дублей, потом переносим».

Это и есть while:

  • Условие — то, что проверяют перед каждым новым дублем: «дубль ещё не удачный и лимит не исчерпан». Проверка идёт перед командой «Мотор!», а не после.
  • Тело — один полный цикл работы: «Мотор!» → запись → «Стоп!» → плейбэк → вердикт (шум ветра, сбился фокус, чисто).
  • Изменение состояния — номер дубля на хлопушке растёт каждый раз, даже если дубль бракованный. Если не менять номер на хлопушке, в монтаже не разберёшься, а в коде — цикл не закончится (ошибки 1 и 3).
  • Выход — два честных пути: «чисто, снято» (успех, break или флаг) или «лимит, переносим» (потолок). Оба нужно записать в монтажный лист — это и есть след для оркестратора.
  • Защита от бесконечного цикла — лимит дублей. Без него группа будет переснимать до ночи, «потому что ещё чуть-чуть, и получится». Ровно так ведёт себя агент без max_attempts.
playback = ["шум ветра", "сбился фокус", "чисто"]   # что покажет плейбэк

take = 0
max_takes = 5
good = False

while take < max_takes and not good:      # условие: проверяем ПЕРЕД дублем
    take += 1                             # хлопушка: номер растёт всегда
    if take <= len(playback):
        verdict = playback[take - 1]
    else:
        verdict = "брак"
    print(f"Дубль {take}: {verdict}")
    if verdict == "чисто":
        good = True                       # выход через успех

if good:
    print(f"Снято с {take}-го дубля, сворачиваемся")
else:
    print("Лимит дублей исчерпан — переносим сцену, пишем в монтажный лист")
# Дубль 1: шум ветра
# Дубль 2: сбился фокус
# Дубль 3: чисто
# Снято с 3-го дубля, сворачиваемся

Попробуй поменять playback на список из одних "брак" — цикл честно остановится на 5-м дубле и напишет про перенос. Это и есть «маленький тормоз» оркестратора: попытки идут, пока есть шанс, но не дольше, чем разрешил потолок.

Вложенные конструкции

Можно комбинировать: for внутри if, while внутри функции и т.д. Главное — ясность и правильные отступы.

Доработка: if и for — порядок веток, enumerate, zip и ранний выход

Про while выше уже есть большой разбор. Здесь — то, что не хватает про if и for.

1. Порядок elif — это логика, а не оформление. Python проверяет ветки сверху вниз и останавливается на первой истинной. Широкое условие наверху «съедает» узкие.

def classify(score: float) -> str:
    # ПЛОХО: score >= 0.5 сработает и для 0.95, ветка "уверенно" недостижима
    if score >= 0.5:
        return "сомнительно"
    elif score >= 0.9:
        return "уверенно"
    return "отказ"

def classify_ok(score: float) -> str:
    if score >= 0.9:          # от узкого к широкому
        return "уверенно"
    if score >= 0.5:
        return "сомнительно"
    return "отказ"

print(classify(0.95), classify_ok(0.95))
# ожидаем: сомнительно уверенно

2. Ранний выход (guard clause) вместо «лестницы». Сначала отсеиваем все случаи отказа, потом спокойно пишем основную работу без отступов на пять уровней. Это та же мысль «цель, которую можно провалить» из файла 00, записанная формой кода.

def answer(query: str, sources: list[str]) -> str:
    if not query.strip():
        return "отказ: пустой вопрос"
    if not sources:
        return "не знаю"
    if len(sources) > 5:
        return "слишком много источников, уточни запрос"
    return f"ответ по {sources[0]}"

print(answer("  ", ["a.md"]))
print(answer("потолок", []))
print(answer("потолок", ["a.md"]))
# ожидаем: ответ по a.md

3. enumerate — номер шага без ручного счётчика. Ручной i += 1 внутри for — частый источник «ошибки на единицу».

files = ["a.md", "b.md", "c.md"]
for step, name in enumerate(files, start=1):
    print(f"шаг {step}/{len(files)}: {name}")
# ожидаем: шаг 3/3: c.md

4. zip — идти по двум спискам параллельно. Например, вопросы и ответы модели. Важно: zip молча останавливается на коротком списке — потеря данных без ошибки. С Python 3.10 есть strict=True, который в этом случае бросает ValueError.

questions = ["q1", "q2", "q3"]
answers = ["a1", "a2"]                 # одного ответа не хватает
print(list(zip(questions, answers)))   # q3 молча пропал
try:
    list(zip(questions, answers, strict=True))
except ValueError as e:
    print("поймали:", e)

5. for ... else — «поиск без находки». Как у while, блок else выполняется, если цикл дошёл до конца без break. Это готовая форма отказа:

docs = {"a.md": "про штатив", "b.md": "про свет"}
for name, text in docs.items():
    if "аккумулятор" in text:
        print("нашли в", name)
        break
else:
    print("не знаю")
# ожидаем: не знаю

Аналогия из жизни документалиста. Порядок elif — как чек-лист перед выездом: сначала «есть ли разрешение на съёмку», и только потом «какой объектив брать». Если начать с объектива, можно идеально собраться на съёмку, которой не будет.

Мини-упражнение. Есть списки names = ["A-01", "A-02", "A-03"] и statuses = ["ок", "брак", "ок"]. Напечатай для каждого дубля строку 1. A-01 — ок, а в конце — номер первого бракованного дубля или «брака нет» (используй for ... else).

<details><summary>Решение</summary>

names = ["A-01", "A-02", "A-03"]
statuses = ["ок", "брак", "ок"]
for i, (name, st) in enumerate(zip(names, statuses, strict=True), start=1):
    print(f"{i}. {name} — {st}")
for i, st in enumerate(statuses, start=1):
    if st == "брак":
        print("первый брак: дубль", i)
        break
else:
    print("брака нет")
# ожидаем: первый брак: дубль 2

strict=True здесь — маленький контракт: если кто-то забыл записать статус одного дубля, программа скажет об этом сразу, а не напечатает неполный лист.
</details>

1.3. Функции

Что такое функция

Функция — именованный блок кода, который можно вызывать много раз.
Она принимает вход (аргументы), делает работу и возвращает результат (или ничего).

Аналогия: машина. Ты кладёшь сырьё (аргументы), нажимаешь кнопку (вызов), получаешь продукт (return) или сообщение об ошибке.

def summarize(text: str, max_len: int = 500) -> str | None:
    """
    Возвращает начало текста или None, если текст пустой.
    max_len — максимальная длина результата.
    """
    if not text or not text.strip():
        return None
    return text.strip()[:max_len]

Термины

  • Определение (def) — создание функции.
  • Вызов — использование функции: summarize("текст").
  • Аргументы (параметры) — то, что передаётся внутрь.
  • Возвращаемое значение (return) — то, что функция отдаёт наружу. Если return нет — возвращается None.
  • Значение по умолчанию (max_len: int = 500) — если аргумент не передали, используется это.
  • Docstring — строка в тройных кавычках сразу после def. Описывает контракт функции.

Почему функции — основа контракта оркестратора

Функция — это узел с контрактом:

  • что принимает;
  • что возвращает;
  • когда отказывает (None или исключение).

Молчание (возврат None без комментария в логе) — тоже ответ, который надо учитывать.

Область видимости

Переменные, созданные внутри функции, видны только внутри неё (локальные).
Переменные снаружи — глобальные. Для состояния агента лучше передавать словарь или объект, а не полагаться на глобальные переменные.

Глубже: return против print, изменяемые значения по умолчанию и забытый None

Три ошибки с функциями, которые чаще всего ломают цепочку оркестратора. Все три «молчаливые»: Python не падает сразу, а выдаёт неправильный результат где-то дальше.

Ошибка 1. print вместо return. print показывает значение человеку на экране, return отдаёт его следующему узлу. Следующий шаг цепочки экрана не видит.

# ПЛОХО
def clean_title(title):
    print(title.strip().lower())

result = clean_title("  Интервью_01 ")
print(result)   # None — функция ничего не вернула

# ИСПРАВЛЕНО
def clean_title(title: str) -> str:
    return title.strip().lower()

result = clean_title("  Интервью_01 ")
print(result)   # интервью_01

Ошибка 2. Изменяемое значение по умолчанию. Значение по умолчанию создаётся один раз, при определении функции, а не при каждом вызове. Если это список или словарь, он копит данные между вызовами.

# ПЛОХО
def add_tag(tag, tags=[]):
    tags.append(tag)
    return tags

print(add_tag("звук"))   # ['звук']
print(add_tag("свет"))   # ['звук', 'свет'] — «звук» протёк из прошлого вызова

# ИСПРАВЛЕНО: по умолчанию None, новый список внутри
def add_tag(tag: str, tags: list | None = None) -> list:
    if tags is None:
        tags = []
    tags.append(tag)
    return tags

print(add_tag("звук"))   # ['звук']
print(add_tag("свет"))   # ['свет']

Ошибка 3. Забытая ветка без return. Если хоть одна ветка if не доходит до return, функция в этом случае вернёт None, и упадёт уже следующий шаг.

# ПЛОХО
def duration_label(seconds):
    if seconds < 60:
        return "короткий"
    elif seconds < 600:
        return "средний"
    # для 600+ ничего не возвращается

label = duration_label(900)
print(label.upper())   # AttributeError: 'NoneType' object has no attribute 'upper'

# ИСПРАВЛЕНО: у каждой ветки есть явный ответ
def duration_label(seconds: int) -> str:
    if seconds < 60:
        return "короткий"
    if seconds < 600:
        return "средний"
    return "длинный"

Связь с оркестратором. Каждый шаг пайплайна (получил запрос, вызвал модель, разобрал ответ, сохранил) — это функция, и следующий шаг доверяет её return. Правило: функция либо возвращает значение обещанного типа, либо явно None (и вызывающий код это проверяет), либо бросает исключение. Третьего «как-нибудь» нет.

def parse_reply(raw: str) -> dict | None:
    if not raw.strip():
        return None
    return {"text": raw.strip(), "length": len(raw.strip())}

reply = parse_reply("")
if reply is None:
    print("Пустой ответ модели — повторяем запрос")
else:
    print(reply["length"])

Аналогия из жизни техника/документалиста. print — это показать кадр на мониторе в павильоне: режиссёр увидел, но на карту ничего не записалось, и монтажёр получит пустоту. return — это записать дубль на карту и передать её дальше. Изменяемое значение по умолчанию — одна и та же карта памяти, которую не форматируют между съёмками: в новом проекте вдруг всплывают дубли из прошлого. Забытая ветка — сцена, для которой забыли включить запись: всё выглядело нормально, а на монтаже материала нет.

Сделай сам.

  1. Напиши file_ext(name), которая возвращает расширение без точки ("clip.mp4" → "mp4"), а для имени без точки возвращает None. Проверь оба случая через is None.
  2. Напиши collect(item, bucket=None), которая без утечки между вызовами добавляет item в список и возвращает его. Вызови её дважды без bucket и убедись, что списки разные.
Закрепление: почини функцию монтажного листа

Вечернее упражнение на утреннюю тему. В одной короткой функции спрятаны сразу все три ошибки из разбора выше: print вместо return, изменяемое значение по умолчанию и ветка без явного ответа. Найди и исправь каждую.

Условие. Функция accept_take ведёт список принятых дублей одной сцены. Вот как её написали в спешке на площадке:

def accept_take(name, status, accepted=[]):
    if status == "ок":
        accepted.append(name)
        print(accepted)
    elif status == "брак":
        return accepted

Перепиши её так, чтобы выполнялся контракт:

  • для статуса "ок" дубль добавляется в список, и функция возвращает этот список;
  • для статуса "брак" список возвращается без изменений;
  • для любого другого статуса (например, "под вопросом") функция явно возвращает None, а вызывающий код проверяет это через is None;
  • новая сцена (вызов без accepted) всегда начинается с пустого списка, без дублей из прошлой сцены.

Проверь себя этим кодом. С исходной версией он упадёт на третьей строке с AttributeError, с исправленной выведет то, что написано в комментариях:

scene1 = accept_take("A-01", "ок")
scene1 = accept_take("A-02", "брак", scene1)
scene1 = accept_take("A-03", "ок", scene1)
print(scene1)        # ['A-01', 'A-03']

scene2 = accept_take("B-01", "ок")
print(scene2)        # ['B-01'] — дубли сцены A не протекли

if accept_take("B-02", "под вопросом", scene2) is None:
    print("Статус не распознан, спроси у режиссёра")

Подсказка: начни с подписи accepted: list | None = None и первой строкой тела создай пустой список, если его не передали. Потом пройди по веткам и убедись, что каждая заканчивается своим return, включая последнюю, «для всего остального».

<details><summary>Решение</summary>

def accept_take(name: str, status: str, accepted: list | None = None) -> list | None:
    if accepted is None:      # ошибка 2: новый список на каждую сцену
        accepted = []
    if status == "ок":
        accepted.append(name)
        return accepted       # ошибка 1: отдаём дальше, а не только показываем
    if status == "брак":
        return accepted
    return None               # ошибка 3: явный отказ для неизвестного статуса


scene1 = accept_take("A-01", "ок")
scene1 = accept_take("A-02", "брак", scene1)
scene1 = accept_take("A-03", "ок", scene1)
print(scene1)        # ['A-01', 'A-03']

scene2 = accept_take("B-01", "ок")
print(scene2)        # ['B-01']

if accept_take("B-02", "под вопросом", scene2) is None:
    print("Статус не распознан, спроси у режиссёра")

Почему исходная версия падает: первый вызов печатает список, но возвращает None, и scene1 становится None. Второй вызов с accepted=None попадает в ветку "брак" и снова возвращает None. Третий пытается сделать None.append(...), отсюда AttributeError. А если бы print заменили на return, но оставили accepted=[], сцена B получила бы ['A-01', 'A-03', 'B-01']: та самая неотформатированная карта памяти.

</details>

1.4. Коллекции — узлы системы

Список (list)

Упорядоченная изменяемая коллекция. Можно дубли.
Аналогия: очередь или полка с ящиками, где порядок важен.

log = []
log.append({"step": 1, "action": "search"})   # добавить в конец
log[0]                                          # первый элемент
len(log)                                        # длина

Основные операции:

  • append(x) — добавить в конец.
  • extend(other) — добавить все элементы другого списка.
  • insert(i, x) — вставить по индексу.
  • pop() — удалить и вернуть последний.
  • Срезы: log[:3], log[-1].

Словарь (dict)

Карточка «ключ → значение». Ключи уникальны.
Аналогия: картотека или паспорт агента на текущий момент.

state = {
    "step": 0,
    "max_steps": 7,
    "query": "что такое потолок",
    "sources": [],
    "log": []
}
state["step"] += 1
state["sources"].append("file.md")

Основные операции:

  • state["key"] — получить (ошибка, если ключа нет).
  • state.get("key", default) — безопасно получить.
  • state["new"] = value — добавить/изменить.
  • in — проверить наличие ключа: "step" in state.

Зачем оркестратору.
Состояние агента почти всегда словарь (или TypedDict / Pydantic-модель). Список — очередь шагов или лог. Множество — «уже посещённые узлы».

Множество (set)

Набор уникальных элементов. Порядок не гарантирован.
Аналогия: список гостей без повторов.

visited = set()
visited.add("file1.md")
if "file1.md" in visited:
    print("уже смотрели")

Кортеж (tuple)

Неизменяемый список. Часто используется для пар (имя, значение) или как ключ.

point = (10, 20)
name_and_score = ("документ", 0.87)

Comprehensions (включения)

Компактный способ создать список/словарь/множество.

md_files = [p for p in paths if p.endswith(".md")]
# читается: «создай список из p для каждого p в paths, если p заканчивается на .md»

Доработка: ссылки, копии и безопасный доступ к состоянию

Самая коварная особенность коллекций в Python: присваивание не копирует. b = a — это второй ярлык на ту же коробку (вспомни аналогию из 1.1). Для состояния агента это значит: «сохранил снимок состояния до шага» может оказаться не снимком, а тем же живым объектом.

Ошибка 1. «Снимок» без копии.

state = {"step": 0, "log": []}
before = state                    # НЕ копия
state["step"] = 1
print(before["step"])             # 1 — «снимок» изменился вместе с оригиналом
# ожидаем: 1

Ошибка 2. Поверхностная копия и вложенный список. dict.copy() копирует только верхний уровень. Списки внутри остаются общими.

import copy

state = {"step": 0, "log": []}
shallow = state.copy()
deep = copy.deepcopy(state)
state["step"] = 1
state["log"].append("поиск")
print(shallow["step"], shallow["log"])   # 0 ['поиск'] — число своё, список общий
print(deep["step"], deep["log"])         # 0 []        — полностью независим
# ожидаем: 0 ['поиск']
# ожидаем: 0 []

Правило оркестратора: снимок состояния для журнала или отката — только copy.deepcopy (или сериализация в JSON, см. 1.6).

Ошибка 3. [[]] * 3 — три ссылки на один список.

grid = [[]] * 3
grid[0].append("x")
print(grid)                       # [['x'], ['x'], ['x']]
grid_ok = [[] for _ in range(3)]
grid_ok[0].append("x")
print(grid_ok)                    # [['x'], [], []]

Безопасная работа со словарём-состоянием.

state = {"query": "потолок"}
# get с умолчанием — чтение без KeyError
print(state.get("sources", []))
# setdefault — создать ключ, если его нет, и сразу вернуть значение
state.setdefault("log", []).append("старт")
state.setdefault("log", []).append("поиск")   # второй раз ключ уже есть, список тот же
print(state["log"])
# ожидаем: ['старт', 'поиск']

Счётчики через dict. Частая задача — посчитать, сколько раз встретился каждый статус шага:

statuses = ["ok", "retry", "ok", "fail", "ok"]
counts: dict[str, int] = {}
for s in statuses:
    counts[s] = counts.get(s, 0) + 1
print(counts)
# ожидаем: {'ok': 3, 'retry': 1, 'fail': 1}

(Тот же результат даёт collections.Counter(statuses) — запомни имя, пригодится в логах.)

set для защиты от зацикливания. Агент, который ходит по ссылкам между документами, может вернуться в уже прочитанный файл и крутиться по кругу. visited из раздела выше — это и есть защита:

links = {"a.md": ["b.md"], "b.md": ["c.md", "a.md"], "c.md": ["a.md"]}
visited, queue = set(), ["a.md"]
while queue:
    cur = queue.pop(0)
    if cur in visited:
        continue
    visited.add(cur)
    queue.extend(links[cur])
print(sorted(visited))
# ожидаем: ['a.md', 'b.md', 'c.md']

Без строк if cur in visited: continue этот while никогда бы не закончился: a → b → a → b ….

Аналогия из жизни техника. b = a — это второй ярлык на тот же кофр, а не второй кофр. copy() — новый кофр, но кабели внутри — те же самые кабели (вытащишь из одного — пропадут в «обоих»). deepcopy — полный второй комплект.

Мини-упражнение. Напиши run_step(state, action), которая не меняет переданный словарь, а возвращает новый: со step на единицу больше и action, дописанным в конец log. Проверь, что исходный словарь не изменился.

<details><summary>Решение</summary>

import copy

def run_step(state: dict, action: str) -> dict:
    new = copy.deepcopy(state)
    new["step"] += 1
    new["log"].append(action)
    return new

s0 = {"step": 0, "log": []}
s1 = run_step(s0, "поиск")
s2 = run_step(s1, "ответ")
print(s0, s2)
# ожидаем: {'step': 0, 'log': []} {'step': 2, 'log': ['поиск', 'ответ']}

Так у тебя сохраняется вся история: s0, s1, s2 — три честных снимка. Это та же идея, что позже будет в графе состояний (файл 04): шаг получает состояние и возвращает обновление, а не портит общее.
</details>

1.5. Строки

Строка — неизменяемая последовательность символов.

Важные методы для работы с документами:

  • .strip() — убрать пробелы по краям.
  • .lower() / .upper() — регистр.
  • .split() — разбить на слова/строки.
  • .replace(old, new) — заменить.
  • in — проверить вхождение: "не знаю" in answer.
  • f-строки: f"Шаг {step}: {status}" — удобное форматирование.
query = "  Что такое потолок?  "
clean = query.strip().lower()
words = set(clean.split())

Доработка: нормализация текста, поиск слова и разбор ответа модели

В 1.5 перечислены методы, но не сказано главное: строки неизменяемы, поэтому каждый метод возвращает новую строку.

title = "  Интервью  "
title.strip()            # результат выброшен!
print(repr(title))       # '  Интервью  ' — не изменилось
title = title.strip()    # правильно: присвоить результат
print(repr(title))
# ожидаем: 'Интервью'

Ошибка 1. Подстрока вместо слова. "кот" in "который" — True. Для поиска по документам это ложные находки.

text = "который час на камере"
print("кот" in text)                 # True — ложная находка
words = set(text.lower().split())
print("кот" in words)                # False — проверяем слово целиком

Ошибка 2. Пунктуация прилипает к словам. "потолок?".split() даёт ["потолок?"], и слово «потолок» не найдётся. Простая нормализация без регулярных выражений:

import string

def normalize(text: str) -> list[str]:
    table = str.maketrans("", "", string.punctuation + "«»—…")
    return text.lower().translate(table).split()

print(normalize("Что такое Потолок? — «шаги», деньги…"))
# ожидаем: ['что', 'такое', 'потолок', 'шаги', 'деньги']

Ошибка 3. Склейка в цикле через +. Для журнала из тысячи строк лучше собрать список и один раз вызвать "\n".join(...) — это и быстрее, и сразу даёт правильные переводы строк без лишнего в конце.

lines = [f"шаг {i}: ok" for i in range(1, 4)]
report = "\n".join(lines)
print(report)
print(report.count("\n"))   # 2 перевода строки на 3 строки
# ожидаем: шаг 3: ok

Практика оркестратора: разбор ответа модели по префиксу. Модели часто просят отвечать в форме ОТВЕТ: ... или НЕ ЗНАЮ. Ответ может прийти с пробелами, в другом регистре или с лишним текстом до/после. Разбирать надо строго и с отказом:

def parse_reply(raw: str) -> tuple[str, str]:
    """Возвращает (статус, текст). Статус: 'ok', 'unknown' или 'broken'."""
    s = raw.strip()
    head = s.upper()
    if head.startswith("НЕ ЗНАЮ"):
        return ("unknown", "")
    if head.startswith("ОТВЕТ:"):
        body = s[len("ОТВЕТ:"):].strip()
        return ("ok", body) if body else ("broken", s)
    return ("broken", s)

for raw in ["  ответ: 90 минут ", "Не знаю.", "Конечно! Вот ответ: 90", "ОТВЕТ:   "]:
    print(parse_reply(raw))
# ожидаем: ('ok', '90 минут')
# ожидаем: ('broken', 'ОТВЕТ:')

Обрати внимание на третий случай: «Конечно! Вот ответ: 90» — это broken, хотя число в нём есть. Оркестратор не «вытаскивает что-нибудь похожее», а честно фиксирует нарушение формата (в файле 02 это превратится в Pydantic-валидацию).

Аналогия из жизни документалиста. Нормализация — как приведение имён файлов с разных камер к одному шаблону сцена_дубль. Пока у одной камеры A001.MOV, а у другой a_1.mov, поиск «все дубли сцены А» будет терять половину.

Мини-упражнение. Напиши count_word(text, word), которая считает, сколько раз слово встречается в тексте как слово, без учёта регистра и пунктуации. count_word("Кот, кот! Который кот?", "кот") → 3.

<details><summary>Решение</summary>

import string

def count_word(text: str, word: str) -> int:
    table = str.maketrans("", "", string.punctuation + "«»—…")
    words = text.lower().translate(table).split()
    return words.count(word.lower())

print(count_word("Кот, кот! Который кот?", "кот"))
# ожидаем: 3

</details>

1.6. Файлы и JSON

Чтение и запись файлов

Предпочтительно использовать pathlib (современный и удобный).

from pathlib import Path

path = Path("docs") / "example.md"
text = path.read_text(encoding="utf-8")
path.write_text("новый текст", encoding="utf-8")

Термины:

  • Path — объект пути.
  • encoding="utf-8" — обязательно для русского текста.
  • with open(...) as f: — старый способ, тоже работает, но Path чище.

JSON

Формат обмена данными. Словари и списки Python легко превращаются в JSON и обратно.

import json

data = {"files": ["a.md"], "errors": []}
json_text = json.dumps(data, ensure_ascii=False, indent=2)
Path("summary.json").write_text(json_text, encoding="utf-8")

loaded = json.loads(Path("summary.json").read_text(encoding="utf-8"))

Зачем.
Сводка по папке, состояние агента, лог шагов — всё удобно хранить в JSON.

Доработка: файл, которого нет, пустой файл и битый JSON

Контрольная точка ступени требует скрипт, который «на пустом/битом файле не падает». Вот три случая, которые надо различать, и как их отличить.

СитуацияЧто делает PythonЧто пишем в след
Файла нетFileNotFoundError«файл не найден: путь»
Файл пустой / из пробеловчитается "" или " \n"«пустой файл»
JSON битыйjson.JSONDecodeError«битый JSON: строка N»

import json
from pathlib import Path

def load_json(path: Path) -> tuple[dict | None, str]:
    """Возвращает (данные, сообщение). Данные None — значит отказ, причина в сообщении."""
    if not path.exists():
        return None, f"файл не найден: {path}"
    try:
        text = path.read_text(encoding="utf-8")
    except UnicodeDecodeError:
        return None, f"не UTF-8: {path}"
    if not text.strip():
        return None, f"пустой файл: {path}"
    try:
        data = json.loads(text)
    except json.JSONDecodeError as e:
        return None, f"битый JSON: строка {e.lineno}, позиция {e.colno}"
    if not isinstance(data, dict):
        return None, f"ожидали объект {{...}}, пришёл {type(data).__name__}"
    return data, "ok"

Path("good.json").write_text('{"files": ["a.md"]}', encoding="utf-8")
Path("empty.json").write_text("  \n", encoding="utf-8")
Path("broken.json").write_text('{"files": ["a.md",]}', encoding="utf-8")
Path("list.json").write_text('[1, 2]', encoding="utf-8")
Path("cp1251.json").write_bytes('{"имя": 1}'.encode("cp1251"))

for name in ["good.json", "nope.json", "empty.json", "broken.json", "list.json", "cp1251.json"]:
    data, msg = load_json(Path(name))
    print(name.ljust(12), msg)
# ожидаем: good.json    ok
# ожидаем: empty.json   пустой файл: empty.json
# ожидаем: list.json    ожидали объект {...}, пришёл list

Важные детали:

  • ensure_ascii=False в json.dumps (в разделе выше) — иначе кириллица запишется как \u043f\u0443...: файл рабочий, но читать глазами невозможно.
  • Запятая после последнего элемента (["a.md",]) — нормальна в Python, но запрещена в JSON. Это самая частая причина «битого JSON», когда его пишет человек или модель.
  • Проверка формы после парсинга. JSON [1, 2] или "строка" — валидный JSON, но не тот, что ждали. isinstance(data, dict) — первый, ручной вариант контракта (в 02 его заменит Pydantic).

Безопасная запись: не потерять старый файл. Если программа упадёт посреди write_text, файл окажется обрезанным. Приём «записать во временный, потом заменить» делает подмену атомарной:

import json
from pathlib import Path

def save_json(path: Path, data: dict) -> None:
    tmp = path.with_suffix(path.suffix + ".tmp")
    tmp.write_text(json.dumps(data, ensure_ascii=False, indent=2), encoding="utf-8")
    tmp.replace(path)          # замена одним действием

p = Path("state.json")
save_json(p, {"step": 1, "log": ["поиск"]})
print(p.read_text(encoding="utf-8"))
print(Path("state.json.tmp").exists())
# ожидаем: False

Аналогия из жизни техника. Сначала копируешь материал с карты на диск и проверяешь копию — и только потом форматируешь карту. tmp.replace(path) — тот же порядок: старое уходит только тогда, когда новое уже целиком на месте.

Мини-упражнение (это и есть «следующий шаг» ступени). Напиши md_stats(path), которая возвращает строку: "файл не найден", "пустой файл" или "строк: N, символов: M".

<details><summary>Решение</summary>

from pathlib import Path

def md_stats(path: Path) -> str:
    try:
        text = path.read_text(encoding="utf-8")
    except FileNotFoundError:
        return "файл не найден"
    if not text.strip():
        return "пустой файл"
    return f"строк: {len(text.splitlines())}, символов: {len(text)}"

Path("note.md").write_text("# Заголовок\nТекст\n", encoding="utf-8")
Path("blank.md").write_text("", encoding="utf-8")
for n in ["note.md", "blank.md", "missing.md"]:
    print(n, "->", md_stats(Path(n)))
# ожидаем: note.md -> строк: 2, символов: 18

splitlines() не считает «пустую строку» после последнего \n, поэтому строк 2, а не 3. Символов 18: 11 в первой строке («#», пробел и 9 букв), 5 во второй и два \n.
</details>

1.7. Исключения — маленький тормоз

Исключение — сигнал, что что-то пошло не так.
Аналогия: красная лампочка. Можно проигнорировать (плохо) или обработать.

try:
    data = json.loads(raw_text)
except json.JSONDecodeError as e:
    log.append(f"битый JSON: {e}")
    return "отказ: битый ответ"
except FileNotFoundError:
    return None
except Exception as e:
    log.append(f"неожиданная ошибка: {e}")
    raise   # пробросить дальше, если не знаем, как лечить

Термины:

  • try — попробовать выполнить.
  • except — если возникло исключение указанного типа.
  • as e — сохранить объект исключения в переменную.
  • raise — вызвать исключение (или пробросить дальше).
  • finally — выполнится в любом случае (редко нужен на старте).

Правило оркестратора: не глотать исключения молча. Либо обработать и зафиксировать в следе, либо пробросить.

Доработка: что ловить, где ловить и как не потерять ошибку

Пример в разделе выше показывает синтаксис. Здесь — три решения, которые оркестратор принимает каждый раз, когда пишет try.

1. Ловить узко. except Exception (а тем более голый except:) ловит в том числе твои собственные опечатки:

def risky(data: dict) -> str:
    try:
        return data["anwser"]        # опечатка в ключе
    except Exception:
        return "не знаю"             # опечатка спрятана: выглядит как честный отказ

print(risky({"answer": "90 минут"}))
# ожидаем: не знаю

Функция «честно» отказала, хотя ответ в данных был. Это худший вид ошибки: след говорит «источника нет», а на деле сломан код. Правило: ловим только то исключение, которое умеем лечить, и с наименьшим try-блоком.

2. try — минимального размера, else — для успешного продолжения.

import json

def parse(raw: str) -> dict | None:
    try:
        data = json.loads(raw)          # в try — только то, что может бросить JSONDecodeError
    except json.JSONDecodeError:
        return None
    else:
        return {"text": data["text"].strip()}   # KeyError здесь НЕ будет пойман как «битый JSON»

print(parse('{"text": " ок "}'), parse("не json"))
try:
    parse('{"txt": 1}')
except KeyError as e:
    print("ошибка формы, а не синтаксиса:", e)
# ожидаем: {'text': 'ок'} None

3. raise ... from e — новая ошибка с сохранённой причиной. Когда низкоуровневую ошибку надо превратить в понятную для своего контура:

class SourceError(Exception):
    """Источник недоступен или испорчен."""

def read_source(name: str) -> str:
    try:
        return open(name, encoding="utf-8").read()
    except FileNotFoundError as e:
        raise SourceError(f"источник {name} не найден") from e

try:
    read_source("нет_такого.md")
except SourceError as e:
    print(e, "| причина:", type(e.__cause__).__name__)
# ожидаем: источник нет_такого.md не найден | причина: FileNotFoundError

Свой класс исключения (SourceError) — это часть контракта: вызывающий код может отличить «источника нет» (отказ, нормальная ветка) от «упал код» (баг, надо чинить).

finally — когда нужно. Он выполняется и при успехе, и при ошибке, и даже при return внутри try. Типичное применение у оркестратора — записать в журнал «шаг закончен», что бы ни случилось:

log = []

def step(x: int) -> float:
    log.append(f"старт {x}")
    try:
        return 10 / x
    finally:
        log.append(f"конец {x}")

step(2)
try:
    step(0)
except ZeroDivisionError:
    pass
print(log)
# ожидаем: ['старт 2', 'конец 2', 'старт 0', 'конец 0']

Аналогия из жизни техника. Предохранитель на линию камеры, а не общий рубильник на всю площадку: сгорело одно — отключилось одно, и видно, что именно. except Exception — это общий рубильник: свет погас, а почему — непонятно.

Мини-упражнение. Напиши safe_int(raw: str) -> int | None, которая возвращает число или None при нечисловой строке (включая отрицательные, " -7 " → -7). Ловить нужно только ValueError.

<details><summary>Решение</summary>

def safe_int(raw: str) -> int | None:
    try:
        return int(raw.strip())
    except ValueError:
        return None

print([safe_int(x) for x in [" -7 ", "12", "", "пять", "3.5"]])
# ожидаем: [-7, 12, None, None, None]

Если передать не строку, а None, функция упадёт с AttributeError — и это правильно: это ошибка вызывающего кода, а не «нечисловой ввод», и прятать её не нужно.
</details>

1.8. Основы объектно-ориентированного программирования (ООП)

Класс — чертёж объекта. Объект — конкретный экземпляр с состоянием и поведением.

class SimpleAgent:
    def __init__(self, max_steps: int = 5):
        self.max_steps = max_steps
        self.steps = 0
        self.log = []

    def can_continue(self) -> bool:
        return self.steps < self.max_steps

    def record(self, action: str):
        self.steps += 1
        self.log.append({"step": self.steps, "action": action})

Термины:

  • class — определение класса.
  • __init__ — конструктор (вызывается при создании объекта).
  • self — ссылка на текущий объект.
  • Метод — функция внутри класса.
  • Атрибут — переменная объекта (self.steps).

На Ступени 1 достаточно понимать, что класс может хранить состояние агента (шаги, лог, потолок).

Доработка: класс, который сам держит свой потолок

SimpleAgent выше хранит потолок, но ничем его не защищает: record можно вызывать сколько угодно, и steps уйдёт за max_steps. Класс полезен тогда, когда правила живут внутри него, а не в памяти программиста.

class StepLimitError(Exception):
    pass

class SimpleAgent:
    def __init__(self, max_steps: int = 5):
        if max_steps < 1:
            raise ValueError("max_steps должен быть >= 1")
        self.max_steps = max_steps
        self.steps = 0
        self.log: list[dict] = []          # своё поле у каждого объекта

    def can_continue(self) -> bool:
        return self.steps < self.max_steps

    def record(self, action: str) -> None:
        if not self.can_continue():
            raise StepLimitError(f"потолок {self.max_steps} шагов достигнут")
        self.steps += 1
        self.log.append({"step": self.steps, "action": action})

    def __repr__(self) -> str:
        return f"SimpleAgent(steps={self.steps}/{self.max_steps})"

agent = SimpleAgent(max_steps=2)
agent.record("поиск")
agent.record("ответ")
try:
    agent.record("ещё поиск")
except StepLimitError as e:
    print("стоп:", e)
print(agent)
# ожидаем: стоп: потолок 2 шагов достигнут
# ожидаем: SimpleAgent(steps=2/2)

Что изменилось:

  • Инвариант в одном месте. «Шагов не больше потолка» проверяется внутри record. Сколько бы мест в коде ни вызывали record, правило не обойти.
  • Проверка в __init__. Агент с max_steps=0 не создастся — ошибка всплывает сразу, а не через десять шагов.
  • __repr__ — как объект выглядит в print и в журнале. Без него будет <__main__.SimpleAgent object at 0x7f…>, и в следе ничего не понятно.

Ошибка новичка: изменяемый атрибут класса. Это родственник «изменяемого значения по умолчанию» из 1.3.

class BadAgent:
    log = []                    # атрибут КЛАССА — один на все объекты

    def record(self, action):
        self.log.append(action)

a, b = BadAgent(), BadAgent()
a.record("поиск")
print(b.log)                    # ['поиск'] — чужой журнал протёк
# ожидаем: ['поиск']

Правило: всё, что меняется (списки, словари, счётчики), создаётся в __init__ через self..

Ошибка 2: забыть self. def record(action): внутри класса — при вызове agent.record("x") Python передаст два аргумента (agent и "x"), и будет TypeError: ... takes 1 positional argument but 2 were given. Если видишь такое сообщение про метод, первым делом проверь self.

Когда класс не нужен. Если у тебя нет состояния, которое живёт между вызовами, обычная функция проще. Класс оправдан, когда есть «объект с памятью»: агент с журналом, бюджет с остатком (файл 05), кэш.

Аналогия из жизни техника. Класс с проверкой внутри — как камера, которая сама не даёт начать запись, если на карте нет места. Класс без проверки — камера с наклейкой «не снимать на полную карту»: правило есть, но держится только на внимательности оператора.

Мини-упражнение. Напиши класс TakeCounter для одной сцены: add(status) принимает только "ок" или "брак" (иначе ValueError), свойство-метод summary() возвращает строку "дублей: 3, ок: 2, брак: 1". Не больше limit дублей (по умолчанию 5) — при превышении StepLimitError из примера выше.

<details><summary>Решение</summary>

class StepLimitError(Exception):
    pass

class TakeCounter:
    ALLOWED = ("ок", "брак")          # неизменяемый кортеж на уровне класса — можно

    def __init__(self, limit: int = 5):
        self.limit = limit
        self.takes: list[str] = []

    def add(self, status: str) -> None:
        if status not in self.ALLOWED:
            raise ValueError(f"неизвестный статус: {status!r}")
        if len(self.takes) >= self.limit:
            raise StepLimitError(f"лимит {self.limit} дублей")
        self.takes.append(status)

    def summary(self) -> str:
        return (f"дублей: {len(self.takes)}, ок: {self.takes.count('ок')}, "
                f"брак: {self.takes.count('брак')}")

c = TakeCounter(limit=3)
for s in ["брак", "ок", "ок"]:
    c.add(s)
try:
    c.add("ок")
except StepLimitError as e:
    print(e)
print(c.summary())
# ожидаем: дублей: 3, ок: 2, брак: 1

Атрибут класса ALLOWED — кортеж, его нельзя изменить, поэтому он безопасно общий для всех объектов. А вот takes — список, и он создаётся в __init__.
</details>

Доработка: эталонный скрипт контрольной точки и самопроверка

Ниже один из вариантов скрипта из «следующего шага» — уже в версии «для папки». Не копируй его сразу: сначала напиши свой, потом сравни. Здесь собраны почти все темы ступени: функция с контрактом, for и while, словарь, строки, файлы, исключения.

from pathlib import Path

def file_report(path: Path) -> dict:
    """Всегда возвращает dict одной формы: name, status, lines, chars."""
    rep = {"name": path.name, "status": "ok", "lines": 0, "chars": 0}
    try:
        text = path.read_text(encoding="utf-8")
    except FileNotFoundError:
        rep["status"] = "нет файла"
        return rep
    except UnicodeDecodeError:
        rep["status"] = "не UTF-8"
        return rep
    if not text.strip():
        rep["status"] = "пустой"
        return rep
    rep["lines"] = len(text.splitlines())
    rep["chars"] = len(text)
    return rep

def folder_report(folder: Path, max_files: int = 50) -> list[dict]:
    reports = []
    for path in sorted(folder.glob("*.md")):
        if len(reports) >= max_files:        # потолок даже здесь
            reports.append({"name": "...", "status": f"потолок {max_files}", "lines": 0, "chars": 0})
            break
        reports.append(file_report(path))
    return reports

# подготовим тестовую папку
d = Path("docs"); d.mkdir(exist_ok=True)
(d / "a.md").write_text("# A\nтекст\n", encoding="utf-8")
(d / "b.md").write_text("   ", encoding="utf-8")
(d / "c.md").write_bytes("Привет".encode("cp1251"))

for r in folder_report(d):
    print(f"{r['name']:6} {r['status']:9} строк={r['lines']} символов={r['chars']}")
print(file_report(d / "zzz.md")["status"])
# ожидаем: a.md   ok        строк=2 символов=10
# ожидаем: b.md   пустой    строк=0 символов=0
# ожидаем: c.md   не UTF-8  строк=0 символов=0
# ожидаем: нет файла

Самопроверка «три вопроса по любому коду» (это и есть цель ступени — ясно говорить про вход, ветку и конец). Пройди их по скрипту выше вслух:

  1. Что было на входе? Путь к папке и max_files. Что будет, если папки нет? (glob вернёт пусто, отчёт — пустой список. Это честно или надо отдельное сообщение? Реши сам.)
  2. Какая ветка выбрана? Для каждого файла — одна из четырёх: ok, нет файла, не UTF-8, пустой. Других нет, и форма словаря одинаковая во всех.
  3. Где ход кончается? for кончается, когда файлы закончились, или на потолке max_files. Бесконечного пути нет.

Типичные пробелы, которые видны на контрольной точке:

  • скрипт падает на первом же «плохом» файле и не обрабатывает остальные — значит, try стоит снаружи цикла, а не внутри функции на один файл;
  • в отчёте для пустого файла другая форма (строка вместо словаря) — вызывающий код ломается;
  • результат только печатается (print), а не возвращается — его нельзя ни проверить assert, ни сохранить в JSON.

Мини-упражнение. Допиши сохранение отчёта в report.json (с ensure_ascii=False) и проверку: прочитай файл обратно и убедись через assert, что количество записей совпадает.

import json
from pathlib import Path

reports = [{"name": "a.md", "status": "ok", "lines": 2, "chars": 10},
           {"name": "b.md", "status": "пустой", "lines": 0, "chars": 0}]

2.1. Аннотации типов (type hints)

Что это

Подсказки типов — способ явно указать, какого типа ожидается аргумент и что возвращает функция.
Python их не проверяет во время выполнения сам по себе (это делают отдельные инструменты: mypy, Pydantic, IDE), но они делают контракт видимым.

Аналогия: табличка на двери «только для сотрудников» или «вход по пропуску».

def search(query: str, top_k: int = 3) -> list[str]:
    ...

Термины:

  • str, int, bool, list[str], dict[str, int] — встроенные.
  • str | None (Python 3.10+) — строка или None.
  • Optional[str] — то же самое (из модуля typing).
  • TypedDict — словарь с фиксированными ключами и типами.
from typing import TypedDict

class StepLog(TypedDict):
    step: int
    action: str
    success: bool
    tokens: int

Зачем оркестратору.
Контракт связи становится явным. Легче увидеть, где функция может вернуть None или неожиданный тип.

Доработка: подсказки не проверяются сами — и как сделать их полезными

Главное, что надо почувствовать руками: Python не останавливает неверный тип. Аннотация — обещание, а не проверка.

def top_k(items: list[str], k: int) -> list[str]:
    return items[:k]

print(top_k(["a.md", "b.md", "c.md"], 2))
print(top_k("abcdef", 2))        # передали строку, а не список — Python молчит
# ожидаем: ab

Второй вызов вернул "ab" вместо списка, и никто не возразил. Поймать это могут три вещи: IDE (подчеркнёт), mypy (проверка перед запуском: pip install mypy, затем mypy файл.py) и Pydantic (проверка во время работы, раздел 2.2). Для оркестратора правило такое: аннотации пишем везде на границах шагов, а там, где данные приходят снаружи (модель, API, файл), — ещё и проверяем во время работы.

Literal — закрытый список значений. Статусы шага — классический случай: строка, но не любая.

from typing import Literal, TypedDict

Status = Literal["ok", "unknown", "broken"]

class StepLog(TypedDict):
    step: int
    action: str
    status: Status

def make_log(step: int, action: str, status: Status) -> StepLog:
    return {"step": step, "action": action, "status": status}

print(make_log(1, "поиск", "ok"))
# make_log(1, "поиск", "окей")  # mypy: Argument 3 has incompatible type

TypedDict — это всё ещё обычный словарь. Он описывает форму для инструментов проверки, но во время работы ничего не запрещает:

from typing import TypedDict

class StepLog(TypedDict):
    step: int
    action: str

entry: StepLog = {"step": "один", "action": "поиск"}   # mypy заругается, Python — нет
print(type(entry).__name__, entry["step"])
# ожидаем: dict один

Типичные ошибки:

  1. list вместо list[str]. Подсказка «какой-то список» почти ничего не сообщает о контракте.
  2. Забытый | None. Если функция может вернуть None, а в подписи -> str, вызывающий код будет уверен, что строка есть всегда. Подпись должна честно говорить об отказе: -> str | None.
  3. Any везде. Any выключает проверку. Иногда нужен (данные «как пришли» от модели), но тогда сразу на следующем шаге — валидация.

Аналогия из жизни техника. Маркировка на разъёме «12 В» — это аннотация. Она не мешает воткнуть туда 220, но любой внимательный монтажник (mypy) увидит нарушение до включения. Предохранитель внутри (Pydantic) сработает уже под напряжением.

Мини-упражнение. Напиши подпись (только подпись и docstring, тело — ...) для функции search, которая принимает вопрос, список путей к файлам и необязательный потолок числа результатов (по умолчанию 3), а возвращает список пар «путь, оценка» или None, если поиск не удалось выполнить.

<details><summary>Решение</summary>

from pathlib import Path

def search(query: str, files: list[Path], top_k: int = 3) -> list[tuple[Path, float]] | None:
    """Ищет query в files.
    Возвращает до top_k пар (путь, оценка от 0 до 1), лучшие первыми.
    Пустой список — поиск прошёл, но ничего не нашёл.
    None — поиск выполнить не удалось (например, ни один файл не прочитался)."""
    ...

print(search.__annotations__["return"])

Обрати внимание на docstring: он различает [] («ничего не нашли») и None («не смогли искать»). Подсказка типа это различие разрешает, а docstring объясняет — вместе это и есть контракт.
</details>

2.2. Pydantic — валидация контракта

Pydantic — библиотека, которая превращает словарь (часто приходящий от модели или API) в строго типизированный объект и сразу говорит, если данные битые.

from pydantic import BaseModel, ValidationError

class ModelAnswer(BaseModel):
    text: str
    sources: list[str]
    confident: bool

raw = {"text": "ответ", "sources": ["a.md"], "confident": True}
try:
    answer = ModelAnswer.model_validate(raw)
except ValidationError as e:
    # битый ответ — фиксируем в следе и отказываем
    log.append(str(e))
    return "отказ: битый формат ответа"

Термины:

  • BaseModel — базовый класс модели.
  • model_validate — проверить и создать объект.
  • ValidationError — исключение при несоответствии.

Зачем.
Ответ модели часто приходит как словарь. Pydantic — автоматическая проверка контракта «ответ должен содержать текст, список источников и флаг уверенности».

Доработка: из JSON-строки модели в объект — строгость, ограничения и разбор ошибки

Модель почти никогда не отдаёт готовый словарь — она отдаёт строку, в которой, возможно, JSON. Поэтому реальная цепочка такая: строка → model_validate_json → объект или отказ.

1. Pydantic по умолчанию «подгоняет» типы. Строка "true" станет True, "5" станет 5. Для ответа модели это может спрятать проблему. strict=True выключает подгонку:

from pydantic import BaseModel, ConfigDict, ValidationError

class Loose(BaseModel):
    confident: bool

class Strict(BaseModel):
    model_config = ConfigDict(strict=True)
    confident: bool

print(Loose.model_validate({"confident": "yes"}))   # молча стало True
try:
    Strict.model_validate({"confident": "yes"})
except ValidationError:
    print("strict: отказ")
# ожидаем: confident=True
# ожидаем: strict: отказ

Строгий режим — не всегда правильный: для чисел из формы или конфига подгонка удобна. Но для флагов, которые меняют ветку (confident, found), лучше строго.

2. Ограничения значений и запрет лишних полей.

from pydantic import BaseModel, ConfigDict, Field, ValidationError, field_validator

class ModelAnswer(BaseModel):
    model_config = ConfigDict(extra="forbid")      # лишние ключи — ошибка
    text: str = Field(min_length=1)
    sources: list[str]
    confidence: float = Field(ge=0, le=1)

    @field_validator("sources")
    @classmethod
    def sources_are_md(cls, v: list[str]) -> list[str]:
        bad = [s for s in v if not s.endswith(".md")]
        if bad:
            raise ValueError(f"источники не из базы: {bad}")
        return v

raw = '{"text": "90 минут", "sources": ["re_kamera.md", "интернет"], "confidence": 1.4, "mood": "ok"}'
try:
    ModelAnswer.model_validate_json(raw)
except ValidationError as e:
    for err in e.errors():
        print(err["loc"], "->", err["msg"])
    print("ошибок:", e.error_count())
# ожидаем: ошибок: 3

Вывод — три понятные причины сразу: лишний mood, выдуманный источник интернет и confidence больше 1. Это и есть след: не «битый ответ», а «что именно битое». Последнее в журнал оркестратора стоит писать именно списком e.errors(), а не всей длинной строкой str(e).

3. Полный шаг «ответ модели → объект или отказ» с поддельной моделью.

from pydantic import BaseModel, Field, ValidationError

class ModelAnswer(BaseModel):
    text: str = Field(min_length=1)
    sources: list[str]
    confident: bool

def fake_llm(question: str) -> str:
    """Заглушка вместо настоящей модели: возвращает разные варианты ответа."""
    return {
        "good": '{"text": "90 минут", "sources": ["re_kamera.md"], "confident": true}',
        "prose": 'Конечно! Аккумулятор держит 90 минут.',
        "nosrc": '{"text": "90 минут", "confident": true}',
    }[question]

def answer_step(question: str, log: list[str]) -> ModelAnswer | None:
    raw = fake_llm(question)
    try:
        ans = ModelAnswer.model_validate_json(raw)
    except ValidationError as e:
        log.append(f"{question}: отказ, {e.error_count()} ошибк(и): {e.errors()[0]['type']}")
        return None
    if not ans.sources:
        log.append(f"{question}: отказ, нет источников")
        return None
    log.append(f"{question}: ok")
    return ans

log: list[str] = []
for q in ["good", "prose", "nosrc"]:
    answer_step(q, log)
print("\n".join(log))
# ожидаем: good: ok
# ожидаем: prose: отказ, 1 ошибк(и): json_invalid
# ожидаем: nosrc: отказ, 1 ошибк(и): missing

Обрати внимание на проверку if not ans.sources после Pydantic. Схема говорит «список строк», и пустой список ей подходит. А контракт оркестратора — «ответ без источника — отказ». Это можно перенести в схему (Field(min_length=1) для списка), главное — не забыть ни там, ни там.

Аналогия из жизни документалиста. Pydantic — это приёмка материала на монтаже: формат кадра, частота, звук, тайм-код. Не «вроде похоже», а по списку. Брак возвращают с актом, где написано, что не так, а не со словом «плохо».

from typing import Literal

    status: Literal["ok", "unknown", "broken"]

for raw in [{"step": 0, "status": "ok"}, {"step": 1, "status": "fine"}, {"step": 2, "status": "unknown"}]:

        print("ok:", StepReport.model_validate(raw))
    except ValidationError as e:

# ожидаем: отказ: ('status',)
# ожидаем: ok: step=2 status='unknown' note=''

2.3. Генераторы и итераторы

Что это

Генератор — функция, которая выдаёт значения по одному (через yield), не создавая весь список сразу в памяти.

Аналогия: конвейер. Вместо того чтобы принести всю пачку документов сразу, работник приносит по одному.

def iter_files(folder: Path):
    for p in folder.glob("*.md"):
        yield p          # отдаём по одному

def iter_chunks(text: str, size: int = 1000):
    for i in range(0, len(text), size):
        yield text[i:i + size]

Термины:

  • yield — «отдать значение и приостановиться».
  • Генератор — объект, который можно итерировать один раз.
  • Ленивость — значение создаётся только когда его просят.

Зачем оркестратору.
Папка с сотнями документов или большой текст. Не нужно держать всё в памяти. Удобно для нарезки на чанки перед поиском.

Доработка: одноразовость, нарезка с перекрытием и потолок на бесконечном потоке

Ошибка 1. Генератор кончается после первого прохода. Это самая частая неожиданность:

def iter_names():
    yield "a.md"
    yield "b.md"

gen = iter_names()
print(list(gen))   # ['a.md', 'b.md']
print(list(gen))   # [] — генератор уже пуст, ошибки нет!
# ожидаем: []

Если нужно пройти два раза (например, сначала посчитать, потом обработать), либо создай генератор заново (iter_names() ещё раз), либо сохрани результат в список. Опасность для оркестратора: второй проход «ничего не нашёл», и это легко принять за честное «не знаю».

Ошибка 2. Чанк, разрезавший мысль пополам. Нарезка из раздела выше режет ровно по size символов — граница может пройти посередине слова или предложения, и поиск не найдёт фразу, попавшую на стык. Обычный приём — перекрытие: каждый следующий кусок начинается чуть раньше конца предыдущего.

def iter_chunks(text: str, size: int = 20, overlap: int = 5):
    if not 0 <= overlap < size:
        raise ValueError("нужно 0 <= overlap < size")
    step = size - overlap
    for start in range(0, len(text), step):
        yield start, text[start:start + size]
        if start + size >= len(text):
            break

text = "Аккумулятор держит 90 минут при 20 градусах."
for start, chunk in iter_chunks(text):
    print(start, repr(chunk))
print(any("90 минут" in c for _, c in iter_chunks(text, overlap=0)))
print(any("90 минут" in c for _, c in iter_chunks(text, overlap=8)))
# ожидаем: False
# ожидаем: True

Без перекрытия «90 минут» разрезалось границей чанков; с перекрытием в 8 символов фраза целиком попала в один кусок. Возвращать start вместе с куском полезно для следа: видно, откуда в документе взят фрагмент.

Проверка 0 <= overlap < size — не формальность: при overlap == size шаг станет нулём, и range упадёт с ошибкой, а при неправильной реализации на while цикл стал бы бесконечным.

3. Потолок для генератора — itertools.islice. Генератор может быть бесконечным (поток событий, повторные попытки). islice берёт не больше N элементов:

import itertools

def attempts():
    n = 0
    while True:            # бесконечный источник
        n += 1
        yield f"попытка {n}"

for a in itertools.islice(attempts(), 3):
    print(a)
# ожидаем: попытка 3

4. Генераторное выражение в sum/any. Круглые скобки вместо квадратных — и список не строится. any к тому же останавливается на первой находке:

checked = []
def has_word(name: str) -> bool:
    checked.append(name)
    return name.startswith("b")

print(any(has_word(n) for n in ["a.md", "b.md", "c.md", "d.md"]), checked)
# ожидаем: True ['a.md', 'b.md']

c.md и d.md даже не проверялись — ленивость экономит работу (а с моделью — и деньги).

Аналогия из жизни документалиста. Генератор — это перемотка плёнки: проиграл до конца — чтобы посмотреть ещё раз, надо перемотать (создать заново). Перекрытие чанков — это «нахлёст» при склейке: пара секунд общего материала, чтобы фраза не оборвалась на стыке.

Мини-упражнение. Напиши генератор iter_lines_with_word(lines, word), который отдаёт пары (номер_строки, строка) для строк, содержащих слово, и общий потолок max_hits (после него генератор останавливается).

<details><summary>Решение</summary>

def iter_lines_with_word(lines: list[str], word: str, max_hits: int = 2):
    hits = 0
    for i, line in enumerate(lines, start=1):
        if word in line.lower().split():
            yield i, line
            hits += 1
            if hits >= max_hits:
                return          # return в генераторе = конец потока

lines = ["потолок шагов", "просто текст", "потолок денег", "потолок повторов"]
print(list(iter_lines_with_word(lines, "потолок")))
# ожидаем: [(1, 'потолок шагов'), (3, 'потолок денег')]

</details>

2.4. Декораторы (на уровне чтения и простого использования)

Что это

Декоратор — функция, которая оборачивает другую функцию и добавляет поведение до/после вызова, не меняя исходный код.

Аналогия: чехол на телефон. Телефон тот же, но теперь он защищён или логирует каждое включение.

import functools
import time

def log_call(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Вызов {func.__name__} с {args}")
        result = func(*args, **kwargs)
        print(f"Результат: {result}")
        return result
    return wrapper

@log_call
def search(query: str) -> list[str]:
    ...

Простой декоратор повтора (полезно для API):

def retry(times: int = 3, delay: float = 1.0):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_error = None
            for attempt in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    last_error = e
                    time.sleep(delay)
            raise last_error
        return wrapper
    return decorator

Термины:

  • @decorator — синтаксический сахар.
  • *args, **kwargs — принять любые аргументы и передать дальше.
  • functools.wraps — сохраняет имя и документацию исходной функции.

Правило: не учить декораторы ради красоты. Брать то, что ловит сбой (логирование шага, повтор при временной ошибке сети).

Доработка: что не так с retry выше и как сделать его безопасным

Декоратор retry из раздела работает, но у него три дыры, которые в контуре с моделью обходятся дорого.

  1. Повторяет любую ошибку. except Exception повторит и KeyError из-за опечатки, и ошибку «неверный ключ API». Такие ошибки не проходят от повтора — мы просто трижды тратим время (а иногда и деньги).
  2. Спит после последней попытки. Цикл засыпает и после третьей неудачи, хотя повторять уже не будет.
  3. Ничего не пишет в след. Снаружи не видно, что было две неудачи перед успехом.

Исправленная версия: повторяет только перечисленные «временные» исключения, с растущей паузой и журналом. Время сна вынесено в параметр sleep, чтобы в примере и в тестах не ждать по-настоящему.

import functools
import time

class TemporaryError(Exception):
    """Сеть, таймаут, перегрузка: повтор может помочь."""

def retry(times: int = 3, delay: float = 1.0, on=(TemporaryError,), sleep=time.sleep, log=None):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except on as e:
                    if log is not None:
                        log.append(f"{func.__name__}: попытка {attempt}/{times} — {e}")
                    if attempt == times:
                        raise                     # исходная ошибка с исходным traceback
                    sleep(delay * 2 ** (attempt - 1))   # 1, 2, 4 ... секунды
        return wrapper
    return decorator

# --- проверка с заглушкой вместо сети ---
journal, pauses = [], []
answers = iter([TemporaryError("таймаут"), TemporaryError("503"), "ответ"])

@retry(times=3, delay=1.0, sleep=pauses.append, log=journal)
def call_model(q: str) -> str:
    """Заглушка вызова модели."""
    r = next(answers)
    if isinstance(r, Exception):
        raise r
    return r

print(call_model("вопрос"), pauses, journal, call_model.__name__, sep="\n")
# ожидаем: ответ
# ожидаем: [1.0, 2.0]

@retry(times=3, sleep=pauses.append, log=journal)
def broken(q: str) -> str:
    return {"a": 1}["b"]          # постоянная ошибка — повторять бессмысленно

try:
    broken("x")
except KeyError:
    print("KeyError не повторялся, записей в журнале:", len(journal))
# ожидаем: KeyError не повторялся, записей в журнале: 2

Что стоит отметить:

  • on=(TemporaryError,) — белый список. В реальном коде туда попадут, например, таймаут и ошибки «сервер перегружен» вашей HTTP-библиотеки (подробности — в файле 03).
  • raise без аргумента внутри except пробрасывает ту же ошибку с исходным местом падения — так проще найти причину, чем с raise last_error после цикла.
  • functools.wraps — видно по call_model.__name__: без него там было бы wrapper, и в логах все функции звались бы одинаково.
  • Параметр sleep — приём «внедрение зависимости»: в бою time.sleep, в тесте — list.append, который просто запоминает паузы. Тест идёт мгновенно и при этом проверяет, какие паузы были бы.

Порядок декораторов. @a над @b означает a(b(func)): снаружи a. Если над функцией и @log_call, и @retry, то при @log_call сверху лог покажет один вызов (вместе со всеми повторами внутри), а при @retry сверху — каждую попытку отдельно. Решай, что тебе нужно видеть в следе.

Аналогия из жизни техника. Перезапуск зависшего рекордера помогает. Перезапуск рекордера без карты памяти — нет, сколько ни нажимай. Хороший retry сначала смотрит, какая это поломка.

Мини-упражнение. Напиши декоратор timed(log), который после каждого вызова дописывает в log строку "имя_функции: N.NN мс" и возвращает результат функции без изменений — даже если функция бросила исключение (тогда строку тоже записать, а исключение пробросить).

<details><summary>Решение</summary>

import functools
import time

def timed(log: list[str]):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            t0 = time.perf_counter()
            try:
                return func(*args, **kwargs)
            finally:
                log.append(f"{func.__name__}: {(time.perf_counter() - t0) * 1000:.2f} мс")
        return wrapper
    return decorator

log: list[str] = []

@timed(log)
def add(a, b):
    return a + b

@timed(log)
def fail():
    raise ValueError("сбой")

print(add(2, 3))
try:
    fail()
except ValueError:
    pass
print(len(log), log[1].startswith("fail:"))
# ожидаем: 5
# ожидаем: 2 True

finally из файла 01 (раздел 1.7) делает здесь всю работу: строка в журнал попадает и при успехе, и при ошибке.
</details>

2.5. Логирование — след системы

Что это

Логирование — запись событий в процессе работы программы. Не print для отладки, а структурированный след, который можно сохранить и проанализировать.

import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    handlers=[
        logging.FileHandler("agent.log", encoding="utf-8"),
        logging.StreamHandler()
    ]
)
log = logging.getLogger("orchestrator")

log.info("Шаг %s: поиск по запросу '%s'", step, query)
log.warning("Источник не найден")
log.error("API вернул 500, попытка %s", attempt)

Уровни:

  • DEBUG — подробности для разработчика.
  • INFO — нормальные события (шаг сделан).
  • WARNING — что-то не так, но работа продолжается.
  • ERROR — ошибка, шаг не удался.
  • CRITICAL — система не может продолжать.

Зачем оркестратору.
Проверка следа. В логе должно быть видно: какой шаг, какой аргумент, какой результат, сколько токенов потрачено. Итог красивый, а в логе пустой поиск — слабое место найдено.

Доработка: след, который можно разобрать программой (JSON Lines)

Лог из раздела выше удобно читать глазами. Но проверка следа (умение 4 из файла 00) — это вопросы вроде «на каком шаге поиск был пустым?» или «сколько вызовов модели ушло на вопрос?». Отвечать на них по тексту вида 2026-10-12 ... [INFO] Шаг 3: поиск приходится регулярками. Проще сразу писать одну JSON-строку на событие (формат JSON Lines, .jsonl).

import json
import logging

class JsonFormatter(logging.Formatter):
    def format(self, record: logging.LogRecord) -> str:
        data = {"level": record.levelname, "msg": record.getMessage()}
        data.update(getattr(record, "fields", {}))      # поля шага
        return json.dumps(data, ensure_ascii=False)

handler = logging.FileHandler("trace.jsonl", mode="w", encoding="utf-8")
handler.setFormatter(JsonFormatter())
log = logging.getLogger("trace_demo")
log.setLevel(logging.INFO)
log.addHandler(handler)
log.propagate = False

def step(n: int, action: str, **fields):
    log.info(action, extra={"fields": {"step": n, "action": action, **fields}})

step(1, "search", query="аккумулятор", hits=0)
step(2, "refuse", reason="нет источника")
handler.close()

events = [json.loads(line) for line in open("trace.jsonl", encoding="utf-8")]
empty = [e["step"] for e in events if e.get("action") == "search" and e.get("hits") == 0]
print("пустой поиск на шагах:", empty)
print(events[1])
# ожидаем: пустой поиск на шагах: [1]

Теперь след — это данные: его можно отфильтровать, посчитать и проверить тестом (см. 2.6).

Типичные ошибки с logging:

  1. basicConfig вызван второй раз — и ничего не изменилось. basicConfig срабатывает, только если у корневого логгера ещё нет обработчиков. Второй вызов молча игнорируется (с Python 3.8 есть force=True). Конфигурируй логирование один раз, в точке входа программы, а не в каждом модуле.
  2. Дубли строк. Если в функции, которая вызывается много раз, делать log.addHandler(...), обработчики копятся, и каждая строка печатается 2, 3, 10 раз. Обработчики добавляются один раз при настройке.
  3. f-строка вместо %s. log.debug(f"данные: {big}") строит строку даже когда DEBUG выключен. log.debug("данные: %s", big) — только если сообщение действительно пишется.
  4. Ключи и личные данные в логе. В след не пишем API-ключ, полный текст личных документов и т. п. Лог часто живёт дольше, чем кажется, и его читают другие люди.
  5. log.error в except без трейсбэка. Используй log.exception("...") внутри except — он добавит полный traceback.
import logging, io
buf = io.StringIO()
lg = logging.getLogger("exc_demo"); lg.addHandler(logging.StreamHandler(buf)); lg.propagate = False
try:
    1 / 0
except ZeroDivisionError:
    lg.exception("шаг 3 упал")
print("Traceback" in buf.getvalue())
# ожидаем: True

Аналогия из жизни документалиста. Обычный лог — это голосовые заметки режиссёра на площадке: всё есть, но чтобы найти «где был брак по звуку», надо всё переслушать. JSON-лог — монтажный лист с графами: отфильтровал по графе «звук = брак» — получил список.

Мини-упражнение. По списку событий ниже (это то, что ты прочитал бы из trace.jsonl) посчитай, сколько было вызовов модели и сколько токенов они стоили в сумме, и найди шаги со статусом broken.

    {"step": 1, "action": "search", "hits": 2},
    {"step": 2, "action": "llm", "tokens": 350, "status": "broken"},
    {"step": 3, "action": "llm", "tokens": 410, "status": "ok"},
]

2.6. Pytest — автоматическая проверка трёх случаев

Что это

Pytest — инструмент для написания и запуска тестов. Тест — маленькая функция, которая проверяет, что код ведёт себя ожидаемо.

Цель на этой ступени не покрытие 80%, а три конкретных случая, которые не должны проходить молча:

  1. Пустой поиск → «не знаю».
  2. Битый ответ модели → отказ.
  3. «Не знаю» действительно возвращается (не подменяется красивым текстом).
# test_agent.py
def test_empty_search(monkeypatch):
    # подменяем функцию поиска, чтобы она всегда возвращала пустой список
    monkeypatch.setattr("my_agent.search", lambda q: [])
    result = my_agent.answer("любой вопрос")
    assert result == "не знаю"

def test_broken_model_response(monkeypatch):
    monkeypatch.setattr("my_agent.call_llm", lambda *a, **k: {"broken": True})
    result = my_agent.answer("вопрос")
    assert "отказ" in result.lower() or result == "не знаю"

Термины:

  • assert — утверждение. Если ложно — тест падает.
  • monkeypatch — способ временно подменить функцию (чтобы не звать реальный API и не тратить деньги).
  • Фикстура — подготовка данных перед тестом (на старте можно обойтись без сложных).

Как запускать:

pip install pytest
pytest -v

Готово, когда: три проверки запускаются одной командой и падают, если отказ сломался.

Доработка: рабочий набор из трёх тестов и главная ловушка monkeypatch

Пример выше показывает идею, но в нём не видно модуля my_agent. Ниже — полностью запускаемый вариант: блок кода сам создаёт my_agent.py и test_agent.py во временной папке и запускает pytest. У себя ты просто положишь эти два файла рядом и выполнишь pytest -v.

import pathlib, subprocess, sys, tempfile, textwrap

AGENT = textwrap.dedent("""
    import json

    def search(query):
        raise RuntimeError("в тестах настоящий поиск не нужен")

    def call_llm(prompt):
        raise RuntimeError("в тестах настоящую модель не зовём")

    def answer(query):
        sources = search(query)
        if not sources:
            return "не знаю"
        raw = call_llm(f"Вопрос: {query}\\nИсточники: {sources}")
        try:
            data = json.loads(raw)
        except (TypeError, json.JSONDecodeError):
            return "отказ: битый ответ"
        text = data.get("text") if isinstance(data, dict) else None
        if not text or not data.get("sources"):
            return "отказ: битый ответ"
        return text
""")

TESTS = textwrap.dedent("""
    import pytest
    import my_agent

    def test_empty_search(monkeypatch):
        monkeypatch.setattr(my_agent, "search", lambda q: [])
        assert my_agent.answer("любой вопрос") == "не знаю"

    @pytest.mark.parametrize("raw", [
        "Конечно! Вот ответ",                    # не JSON
        '{"broken": true}',                      # JSON без нужных полей
        '{"text": "90 минут", "sources": []}',   # нет источников
        '[1, 2]',                                # не объект
    ])
    def test_broken_model_response(monkeypatch, raw):
        monkeypatch.setattr(my_agent, "search", lambda q: ["a.md"])
        monkeypatch.setattr(my_agent, "call_llm", lambda p: raw)
        assert my_agent.answer("вопрос").startswith("отказ")

    def test_unknown_is_not_replaced(monkeypatch):
        # модель зовут не должны: при пустом поиске сразу «не знаю»
        monkeypatch.setattr(my_agent, "search", lambda q: [])
        def boom(p):
            raise AssertionError("модель вызвана без источников!")
        monkeypatch.setattr(my_agent, "call_llm", boom)
        assert my_agent.answer("вопрос") == "не знаю"
""")

with tempfile.TemporaryDirectory() as d:
    pathlib.Path(d, "my_agent.py").write_text(AGENT, encoding="utf-8")
    pathlib.Path(d, "test_agent.py").write_text(TESTS, encoding="utf-8")
    r = subprocess.run([sys.executable, "-m", "pytest", "-q", "-p", "no:cacheprovider"],
                       cwd=d, capture_output=True, text=True, timeout=60)
    print(r.stdout.strip().splitlines()[-1])
# ожидаем: 6 passed

Что здесь важно:

  • parametrize превращает один тест в четыре — по одному на каждый вид «битого ответа». Модель ломается по-разному, и каждый способ должен давать отказ.
  • Третий тест проверяет не только результат, но и дорогу: если при пустом поиске код всё равно позовёт модель (и потратит деньги), boom уронит тест. Это проверка следа, а не вкуса.
  • Настоящие search и call_llm бросают ошибку. Если какой-то тест забудет их подменить, он упадёт громко, а не пойдёт в сеть.

Главная ловушка monkeypatch: подменять там, где используют. Если в my_agent.py написано from tools import search, то внутри my_agent есть своё имя search. Подмена monkeypatch.setattr(tools, "search", ...) его не затронет — тест будет звать настоящий поиск. Подменять надо my_agent.search. Именно поэтому в примере выше подмена идёт по модулю my_agent.

Как убедиться, что тест вообще что-то ловит. Временно сломай код: например, замени return "не знаю" на return "Вот ответ по базе". Тест должен покраснеть. Если не покраснел — он ничего не проверяет. Это быстрая и честная проверка самих тестов.

Аналогия из жизни техника. Тестовый сигнал (полосы и тон 1 кГц) перед записью: мы подаём заранее известный вход и смотрим, что на выходе ровно ожидаемое. monkeypatch — это генератор тестового сигнала вместо живой камеры.

Мини-упражнение. Добавь четвёртый тест: если search бросает исключение TimeoutError, answer должен вернуть "отказ: поиск недоступен". Сначала напиши тест (он упадёт), потом исправь answer.

2.7. Работа с датами и регулярными выражениями (кратко)

Даты (datetime):

from datetime import datetime
now = datetime.now()
log_entry = {"time": now.isoformat(), "step": 1}

Регулярные выражения (re) — поиск по шаблону. На старте достаточно простых случаев (найти все ссылки, очистить текст). Не углубляться, пока не понадобится для конкретного контракта.

Доработка: часовой пояс в следе и три регулярки, которые реально нужны

Даты: datetime.now() без пояса — ловушка для следа. Такое время «наивное»: в нём нет информации о часовом поясе. Если контур работает на сервере в UTC, а ты читаешь лог по Москве, события «сдвинутся» на три часа, и сопоставить их с реальностью будет трудно. Для журнала пиши время с поясом:

from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo

naive = datetime(2026, 10, 12, 7, 30)
utc = datetime(2026, 10, 12, 4, 30, tzinfo=timezone.utc)
msk = utc.astimezone(ZoneInfo("Europe/Moscow"))
print(naive.isoformat())      # без пояса — непонятно, чьи это 07:30
print(utc.isoformat())
print(msk.isoformat())
# ожидаем: 2026-10-12T07:30:00+03:00

В реальном коде: datetime.now(timezone.utc).isoformat() для записи, перевод в местное время — только при показе человеку.

Длительность шага — через time.perf_counter(), а не разностью datetime.now(): системные часы могут подвести (синхронизация, перевод времени), а perf_counter для измерения интервалов именно и предназначен.

Разница дат и «устаревший источник»:

from datetime import date

def is_stale(updated: date, today: date, max_age_days: int = 365) -> bool:
    return (today - updated).days > max_age_days

print(is_stale(date(2025, 1, 10), date(2026, 10, 12)))
print(is_stale(date(2026, 9, 1), date(2026, 10, 12)))
# ожидаем: True
# ожидаем: False

Для оркестратора это готовый кусок контракта: «если документ старше года — отвечать с пометкой или отказывать».

Регулярные выражения: три шаблона на каждый день.

import re

FENCE = "`" * 3          # три обратные кавычки: так модель часто оборачивает JSON
reply = (
    "Вот ответ.\n"
    + FENCE + "json\n"
    + '{"text": "90 минут", "sources": ["re_kamera.md"]}\n'
    + FENCE + "\n"
    + "Источник: [РЭ камеры](docs/re_kamera.md), см. также docs/tu_shtativ.md. Дата: 2026-10-12."
)

# 1. Вытащить JSON из ответа модели, обёрнутого в тройные кавычки с пометкой json
m = re.search(r"`{3}(?:json)?\s*(\{.*?\})\s*`{3}", reply, re.DOTALL)
print(m.group(1) if m else "JSON не найден")

# 2. Найти все упоминания .md-файлов
print(re.findall(r"[\w/.-]+\.md\b", reply))   # первое имя — из самого JSON

# 3. Найти даты ГГГГ-ММ-ДД
print(re.findall(r"\b\d{4}-\d{2}-\d{2}\b", reply))
# ожидаем: ['re_kamera.md', 'docs/re_kamera.md', 'docs/tu_shtativ.md']
# ожидаем: ['2026-10-12']

Пояснения к шаблонам:

  • r"..." — «сырая» строка: \d и \b не превращаются в спецсимволы Python. Всегда пиши регулярки в r"...".
  • ` {3} `` — ровно три обратные кавычки подряд (так в шаблоне не нужно писать их буквально).
  • .*? — «как можно меньше» (ленивый квантор). С жадным .* при двух JSON-блоках в ответе захватился бы текст от первой { до последней }.
  • re.DOTALL — точка совпадает и с переводом строки, иначе многострочный JSON не найдётся.
  • \b — граница слова: \d{4}-\d{2}-\d{2} без \b найдёт «дату» внутри 12026-10-123.

Правило оркестратора для регулярок: они достают кандидата, но не проверяют его. Найденный JSON всё равно идёт в Pydantic (2.2), найденная дата — в date.fromisoformat, которая отвергнет 2026-13-45.

Аналогия из жизни техника. Регулярка — как поиск по тайм-коду: быстро находит нужное место, но не говорит, хорош ли там кадр. Смотреть кадр — отдельная проверка.

Мини-упражнение. Из строки "дубли: A-01 ок, A-02 брак, B-11 ок, X1 ?" достань все номера дублей формата «буква-две цифры» вместе со статусом в виде списка пар.

<details><summary>Решение</summary>

import re

pairs = re.findall(r"\b([A-Z]-\d{2})\s+(ок|брак)\b", s)

# ожидаем: [('A-01', 'ок'), ('A-02', 'брак'), ('B-11', 'ок')]

Контрольная точка Ступени 3

Готово, когда:

  • Курс закрыт задачами.
  • Тот же скрипт по папке не падает на битом файле и пишет, какой именно файл сломался.

Не делать: учить декораторы ради красоты. Брать только то, что ловит сбой.

Доработка: скрипт по папке «не падает и говорит, какой файл сломался» — с логом и тестом

Контрольная точка требует сразу три вещи: устойчивость к битому файлу, лог в файл и тест. Вот как они сходятся в одном небольшом модуле. Это продолжение эталонного скрипта Ступени 1 (файл 01, контрольная точка), но теперь с логированием и Pydantic-контрактом на отчёт.

import json
import logging
from pathlib import Path
from typing import Literal
from pydantic import BaseModel

log = logging.getLogger("folder")

class FileReport(BaseModel):
    name: str
    status: Literal["ok", "empty", "bad_encoding", "bad_json"]
    lines: int = 0

def check_file(path: Path) -> FileReport:
    try:
        text = path.read_text(encoding="utf-8")
    except UnicodeDecodeError:
        log.warning("не UTF-8: %s", path.name)
        return FileReport(name=path.name, status="bad_encoding")
    if not text.strip():
        log.warning("пустой: %s", path.name)
        return FileReport(name=path.name, status="empty")
    if path.suffix == ".json":
        try:
            json.loads(text)
        except json.JSONDecodeError as e:
            log.error("битый JSON: %s, строка %s", path.name, e.lineno)
            return FileReport(name=path.name, status="bad_json")
    log.info("ok: %s", path.name)
    return FileReport(name=path.name, status="ok", lines=len(text.splitlines()))

def check_folder(folder: Path) -> list[FileReport]:
    return [check_file(p) for p in sorted(folder.iterdir()) if p.is_file()]

# --- демонстрация ---
logging.basicConfig(level=logging.INFO, filename="folder.log", filemode="w",
                    encoding="utf-8", format="%(levelname)s %(message)s")
d = Path("box"); d.mkdir(exist_ok=True)
(d / "a.md").write_text("текст\nещё\n", encoding="utf-8")
(d / "b.md").write_text("", encoding="utf-8")
(d / "c.json").write_text("{oops}", encoding="utf-8")
(d / "d.md").write_bytes("кириллица".encode("cp1251"))

reports = check_folder(d)
broken = [r.name for r in reports if r.status != "ok"]
print("сломаны:", broken)
print(Path("folder.log").read_text(encoding="utf-8").strip().splitlines()[1])
# ожидаем: сломаны: ['b.md', 'c.json', 'd.md']
# ожидаем: WARNING пустой: b.md

3.1. Переменные окружения и ключ вне кода

Что такое переменная окружения

Переменная окружения — значение, которое живёт вне программы (в системе или в файле .env) и передаётся программе при запуске.
Аналогия: ключ от квартиры лежит не внутри квартиры, а в сейфе у входа. Программа знает, где взять ключ, но сам ключ в коде не хранится.

import os
from dotenv import load_dotenv

load_dotenv()                          # читает файл .env
API_KEY = os.getenv("OPENAI_API_KEY")  # или GROK_API_KEY и т.д.

if not API_KEY:
    raise RuntimeError("Ключ не найден в окружении")

Файл .env (не коммитить!):

OPENAI_API_KEY=sk-...

.gitignore обязательно содержит:

.env

Термины:

  • os.getenv — получить переменную окружения.
  • python-dotenv — библиотека для чтения .env.
  • Секрет — то, что нельзя класть в репозиторий.

Зачем оркестратору.
Ключ в коде = ключ в git = ключ у всех, кто скачает репозиторий. Это нарушение контракта безопасности.

Доработка: проверка ключа при старте, а не на сотом шаге, и что делать, если ключ утёк

1. Проверять всё окружение в одной функции при запуске. Если ключ проверяется только внутри call_llm, программа может полчаса резать документы на чанки и упасть на первом вызове модели. Лучше собрать все настройки в одном месте и упасть сразу, с понятным списком того, чего не хватает:

import os
from dataclasses import dataclass

@dataclass(frozen=True)
class Settings:
    api_key: str
    model: str
    timeout: int

    def __repr__(self) -> str:                 # ключ не попадёт в лог даже через print(settings)
        return f"Settings(api_key='***{self.api_key[-4:]}', model={self.model!r}, timeout={self.timeout})"

def load_settings(env: dict[str, str] | None = None) -> Settings:
    env = dict(os.environ) if env is None else env
    missing = [k for k in ("LLM_API_KEY", "LLM_MODEL") if not env.get(k, "").strip()]
    if missing:
        raise RuntimeError(f"не заданы переменные окружения: {', '.join(missing)}")
    try:
        timeout = int(env.get("LLM_TIMEOUT", "30"))
    except ValueError:
        raise RuntimeError("LLM_TIMEOUT должен быть целым числом секунд") from None
    return Settings(env["LLM_API_KEY"].strip(), env["LLM_MODEL"].strip(), timeout)

try:
    load_settings({"LLM_MODEL": "some-model"})
except RuntimeError as e:
    print(e)
s = load_settings({"LLM_API_KEY": "  sk-test-1234abcd\n", "LLM_MODEL": "some-model"})
print(s)
# ожидаем: не заданы переменные окружения: LLM_API_KEY
# ожидаем: Settings(api_key='***abcd', model='some-model', timeout=30)

Что здесь закрыто:

  • Пробелы и перевод строки в ключе. При копировании ключа из браузера в .env часто цепляется пробел или \n. Сервер ответит 401, и будет казаться, что ключ неверный. .strip() снимает эту проблему.
  • Пустая строка. os.getenv("X") вернёт "", если в .env написано X=. Проверка if not API_KEY из раздела выше это ловит, а if API_KEY is None — нет.
  • Ключ в логах. __repr__ показывает только последние 4 символа. Это важно: лог (файл 02, раздел 2.5) часто читают и пересылают, и ключ, напечатанный «для отладки», утекает именно так.
  • Имя модели тоже в окружении. Модели меняются и выводятся из обращения; имя в настройках меняется без правки кода. (Имена конкретных моделей в примерах этой методички — условные, актуальный список смотри в документации своего провайдера.)

2. load_dotenv() не перезаписывает уже заданные переменные. По умолчанию, если переменная уже есть в окружении системы, значение из .env будет проигнорировано (для перезаписи есть load_dotenv(override=True)). Если «поменял ключ в .env, а работает старый» — проверь, не задан ли он в системе.

3. Если ключ попал в git. Удалить файл новым коммитом недостаточно: ключ остаётся в истории, а публичные репозитории сканируются ботами очень быстро. Порядок действий:

  1. Сразу отозвать (revoke) ключ в кабинете провайдера и выпустить новый. Это главное и единственное надёжное действие.
  2. Положить новый ключ в .env, проверить, что .env есть в .gitignore (git check-ignore -v .env покажет, каким правилом он исключён).
  3. Только потом чистить историю — и помнить, что очистка истории не отменяет того, что ключ уже могли скопировать.

Аналогия из жизни техника. Перед выездом проверяют весь кейс по списку на складе, а не обнаруживают на площадке, что нет аккумуляторов. load_settings — это проверка кейса на складе.

Мини-упражнение. Добавь в load_settings проверку: таймаут должен быть от 1 до 300 секунд, иначе RuntimeError с понятным текстом.

<details><summary>Решение</summary>

def check_timeout(raw: str) -> int:
    try:
        timeout = int(raw)
    except ValueError:
        raise RuntimeError("LLM_TIMEOUT должен быть целым числом секунд") from None
    if not 1 <= timeout <= 300:
        raise RuntimeError(f"LLM_TIMEOUT={timeout} вне диапазона 1..300 секунд")
    return timeout

for raw in ["30", "0", "abc"]:
    try:
        print("ok", check_timeout(raw))
    except RuntimeError as e:
        print(e)

Таймаут 0 — это не «без ожидания», а гарантированная ошибка на каждом запросе; а 100000 — запрос, который может висеть больше суток. Оба значения — нарушение потолка.

3.2. HTTP-запрос к API модели

Что такое API в этом контексте

API (Application Programming Interface) — способ одной программы попросить другую сделать работу по заранее оговорённому контракту.
Здесь: твой скрипт отправляет HTTP-запрос (обычно POST) с текстом и получает JSON с ответом модели.

import requests

def call_llm(messages: list[dict], model: str = "gpt-4o-mini", timeout: int = 30) -> dict | None:
    """
    Возвращает словарь ответа или None при ошибке.
    messages — список вида [{"role": "system", "content": "..."}, {"role": "user", "content": "..."}]
    """
    try:
        response = requests.post(
            "https://api.openai.com/v1/chat/completions",
            headers={
                "Authorization": f"Bearer {API_KEY}",
                "Content-Type": "application/json"
            },
            json={
                "model": model,
                "messages": messages,
                "temperature": 0.2,
                "max_tokens": 1000
            },
            timeout=timeout
        )
        response.raise_for_status()          # вызовет исключение при 4xx/5xx
        return response.json()
    except requests.Timeout:
        log.error("Таймаут запроса к модели")
        return None
    except requests.HTTPError as e:
        status = e.response.status_code if e.response else "unknown"
        log.error("HTTP ошибка %s", status)
        if status == 429:
            log.warning("Слишком много запросов, нужен повтор с паузой")
        return None
    except Exception as e:
        log.error("Неожиданная ошибка вызова: %s", e)
        return None

Термины:

  • requests.post — отправить POST-запрос.
  • timeout — максимальное время ожидания (секунды). Без него запрос может висеть вечно.
  • raise_for_status() — превратить плохой HTTP-код в исключение.
  • 429 — Too Many Requests (слишком часто).
  • 500 — ошибка на стороне сервера.
  • temperature — параметр «случайности» ответа (0 — почти детерминированный, 1 — более творческий). Для оркестратора обычно низкая.
  • max_tokens — потолок длины ответа.
  • Системное сообщение (role: system) — инструкция модели, которая задаёт контракт поведения.

Системная фраза — часть контракта:

Доработка: скрытая ошибка в call_llm, классы ошибок и проверка без сети

1. Ошибка в примере выше: if e.response. В библиотеке requests объект ответа «ложный», если код ответа — ошибка (4xx/5xx): bool(response) равно response.ok. Поэтому в строке

Чтобы пример запускался без сети и без ключа, функция отправки (post) передаётся параметром — в бою это requests.post, здесь заглушка.

import requests

RETRYABLE = {429, 500, 502, 503, 504}

def call_llm(messages: list[dict], post=requests.post, timeout: int = 30) -> tuple[dict | None, str]:
    """Возвращает (json_ответа, 'ok') или (None, причина). Причина начинается
    с 'retry:' если повтор имеет смысл, и с 'fatal:' если нет."""
    try:
        r = post("https://example.invalid/v1/chat", json={"messages": messages}, timeout=timeout)
        r.raise_for_status()
    except requests.Timeout:
        return None, "retry: таймаут"
    except requests.ConnectionError:
        return None, "retry: нет соединения"
    except requests.HTTPError as e:
        code = e.response.status_code if e.response is not None else None
        kind = "retry" if code in RETRYABLE else "fatal"
        return None, f"{kind}: HTTP {code}"
    try:
        return r.json(), "ok"
    except ValueError:                      # сервер ответил не JSON
        return None, "fatal: ответ не JSON"

def fake_response(code: int, body: str = '{"choices": []}') -> requests.Response:
    resp = requests.Response()
    resp.status_code = code
    resp._content = body.encode("utf-8")
    return resp

def post_timeout(*a, **k):
    raise requests.Timeout()

4. Системная фраза не гарантирует поведения. Промпт «не выдумывай источник» снижает вероятность выдумки, но не исключает её. Поэтому контракт держится не на промпте, а на коде: отказ до вызова при пустом поиске (3.4) и проверка, что названные моделью источники действительно были в контексте (доработка к 3.4 ниже).

Аналогия из жизни техника. Разные лампочки на рекордере: «нет сигнала» (подождать, переподключить) и «карта защищена от записи» (ждать бесполезно, надо идти менять карту). Код, который на обе лампочки делает одно и то же, либо ждёт вечно, либо сдаётся, когда мог бы подождать.

Мини-упражнение. Допиши в call_llm чтение заголовка Retry-After для кода 429: если он есть и это целое число секунд, причина должна быть "retry: HTTP 429, ждать N с".

import requests

def reason_for(resp: requests.Response) -> str:
    code = resp.status_code
    if code == 429:
        ra = resp.headers.get("Retry-After", "")
        if ra.isdigit():
            return f"retry: HTTP 429, ждать {int(ra)} с"
        return "retry: HTTP 429"
    return f"{'retry' if code >= 500 else 'fatal'}: HTTP {code}"

r = requests.Response(); r.status_code = 429; r.headers["Retry-After"] = "7"
print(reason_for(r))
# ожидаем: retry: HTTP 429, ждать 7 с

Retry-After может прийти и в виде даты — тогда isdigit() вернёт False, и мы честно используем свою паузу, не падая.
</details>

3.3. Простой поиск по своим файлам (зародыш RAG)

RAG (Retrieval-Augmented Generation) — ответ модели дополняется найденными фрагментами из твоих документов.
На этой ступени достаточно простого поиска по словам, без векторных баз.

from pathlib import Path

def load_chunks(folder: Path, chunk_size: int = 800) -> list[str]:
    chunks = []
    for p in folder.glob("*.md"):
        text = p.read_text(encoding="utf-8")
        # простая нарезка
        for i in range(0, len(text), chunk_size):
            chunk = text[i:i + chunk_size].strip()
            if chunk:
                chunks.append(f"[{p.name}]\n{chunk}")
    return chunks

def simple_retrieve(query: str, chunks: list[str], top_k: int = 3) -> list[str]:
    query_words = set(query.lower().split())
    scored = []
    for chunk in chunks:
        chunk_words = set(chunk.lower().split())
        score = len(query_words & chunk_words)   # пересечение слов
        if score > 0:
            scored.append((score, chunk))
    scored.sort(key=lambda x: x[0], reverse=True)
    return [chunk for _, chunk in scored[:top_k]]

Термины:

  • Чанк (chunk) — кусок текста фиксированного размера.
  • Пересечение множеств (&) — общие слова.
  • top_k — сколько лучших фрагментов взять.

Доработка: почему поиск по словам «не находит очевидное» и как это поправить, не усложняя

simple_retrieve из раздела выше хорош как зародыш, но у него три слепых пятна. Проверим их на маленькой базе.

Улучшенная версия: нормализация + стоп-слова + грубая обрезка окончаний + порог. Никаких библиотек, всё на материале файла 01.

import string

STOP = {"и", "в", "на", "до", "не", "что", "как", "сколько", "ли", "а", "по", "с", "к", "о"}
PUNCT = str.maketrans("", "", string.punctuation + "«»—…")

def terms(text: str) -> set[str]:
    words = text.lower().translate(PUNCT).split()
    # грубый «стемминг»: первые 6 букв длинного слова — аккумулятор/аккумулятора -> «аккуму»
    return {w[:6] if len(w) > 6 else w for w in words if w not in STOP and len(w) > 1}

def retrieve(query: str, chunks: list[str], top_k: int = 3, min_share: float = 0.5) -> list[tuple[float, str]]:
    q = terms(query)
    if not q:
        return []                                   # вопрос из одних стоп-слов: искать нечего
    res = []
    for c in chunks:
        share = len(q & terms(c)) / len(q)          # доля слов вопроса, найденных в куске
        if share >= min_share:
            res.append((round(share, 2), c))
    res.sort(key=lambda x: x[0], reverse=True)
    return res[:top_k]

  • Порог min_share — это часть контракта отказа. Ниже порога — «не нашли», даже если одно слово совпало. Подбирается на своих вопросах; начни с 0.5.
  • Вопрос «аккумулятора хватит надолго» найдёт камеру с долей 0.33 и не пройдёт порог 0.5: из трёх значимых слов совпало одно. Это честный результат: слова «хватит» и «надолго» в базе нет. Если такой отказ кажется неправильным — это сигнал о пределах поиска по словам, а не повод снижать порог до нуля.
  • Обрезка до 6 букв — очень грубый приём: «камера» и «камеры» совпадут, но могут совпасть и разные слова с общим началом. Это компромисс зародыша; на следующих ступенях его заменяют поиском по смыслу (векторный поиск, эмбеддинги).

Нарезка в load_chunks режет по 800 символов и может разрезать фразу пополам — см. перекрытие чанков в доработке к разделу 2.3 файла 02.

Аналогия из жизни документалиста. Поиск по словам — это поиск по названиям файлов на диске с материалом. Если оператор назвал клип akkum_test.mov, а ты ищешь «аккумулятор», не найдёшь. def split_chunk(chunk: str) -> tuple[str, str]:
    head, _, body = chunk.partition("\n")
    if not (head.startswith("[") and head.endswith("]")):
        return "?", chunk
    return head[1:-1], body

def as_records(hits: list[tuple[float, str]]) -> list[dict]:
    out = []
    for score, chunk in hits:
        name, body = split_chunk(chunk)
        out.append({"file": name, "score": score, "text": body})
    return out

Доработка: отказ после ответа модели — проверка, что источник настоящий

Раздел выше закрывает отказ до вызова: пусто — модель не зовём. Но остаётся вторая дыра: поиск что-то нашёл, модель ответила, и в ответе ссылается на файл, которого в контексте не было (или говорит «не знаю» другими словами, а мы принимаем это за ответ). Контракт главы «имя файла не выдумывается» проверяется только кодом.

Приём: просим модель отвечать в фиксированном JSON и проверяем источники по списку того, что сами передали. Модель здесь — заглушка, чтобы пример запускался без сети; разные «вопросы» заставляют её вести себя по-разному.

import json

def fake_model(context_files: list[str], question: str) -> str:
    """Заглушка модели. Возвращает строку, как настоящий API."""
    if "гарантия" in question:
        return '{"answer": "Гарантия 2 года", "sources": ["garantiya.md"]}'   # выдуманный файл
    if "вес" in question:
        return '{"answer": "не знаю", "sources": []}'
    if "цвет" in question:
        return 'К сожалению, в документах этого нет, но обычно камеры чёрные.'
    return json.dumps({"answer": "90 минут", "sources": [context_files[0]]}, ensure_ascii=False)

def answer(question: str, found: list[dict], model=fake_model) -> dict:
    """found — записи вида {"file": ..., "text": ...} из поиска (см. доработку 3.3)."""
    if not found:
        return {"answer": "не знаю", "sources": [], "reason": "поиск пуст, модель не вызывалась"}
    allowed = {f["file"] for f in found}
    raw = model(sorted(allowed), question)
    try:
        data = json.loads(raw)
        text, sources = data["answer"].strip(), list(data["sources"])
    except (json.JSONDecodeError, KeyError, TypeError, AttributeError):
        return {"answer": "не знаю", "sources": [], "reason": "ответ модели не по формату"}
    if text.lower().rstrip(".!") == "не знаю":
        return {"answer": "не знаю", "sources": [], "reason": "модель не нашла ответа в контексте"}
    invented = [s for s in sources if s not in allowed]
    if not sources or invented:
        return {"answer": "не знаю", "sources": [],
                "reason": f"источники не из контекста: {invented or 'не указаны'}"}
    return {"answer": text, "sources": sources, "reason": "ok"}

Что здесь важно:

  • Все отказы имеют одну форму (answer, sources, reason), различается только reason. Это след: по нему видно, какой из четырёх отказов сработал.
  • «Гарантия 2 года» с выдуманным garantiya.md — самый опасный случай: ответ выглядит уверенно и даже со ссылкой. Без проверки invented он прошёл бы к пользователю.
  • Вежливая проза вместо JSON («К сожалению… но обычно камеры чёрные») — это и есть «красиво ответил без источника». Отказ по формату здесь правильный.
  • Проверка источника по имени файла не проверяет, что ответ действительно следует из текста. Это следующий уровень (например, проверка, что ключевые числа ответа встречаются в процитированном куске). Начни с имени файла — это дешёво и ловит самые грубые выдумки.

Аналогия из жизни документалиста. В титрах нельзя указать архив, из которого кадр не брали. Монтажёр сверяет: каждый архивный кадр в фильме — с листом заказанных фрагментов. Нет в листе — кадр вырезается, как бы хорош он ни был.

Мини-упражнение. Добавь проверку: если в ответе модели есть число, оно должно встречаться в тексте хотя бы одного из процитированных кусков, иначе отказ с причиной "число не подтверждено источником".

<details><summary>Решение</summary>

import re

def numbers_confirmed(answer_text: str, cited: list[dict]) -> bool:
    nums = re.findall(r"\d+(?:[.,]\d+)?", answer_text)
    corpus = " ".join(c["text"] for c in cited)
    return all(n in corpus for n in nums)

cited = [{"file": "re_kamera.md", "text": "Аккумулятор держит 90 минут."}]
print(numbers_confirmed("90 минут", cited), numbers_confirmed("120 минут", cited))
# ожидаем: True False

В функции answer эту проверку ставят последней, перед return ... "ok": cited = [f for f in found if f["file"] in sources], и если not numbers_confirmed(text, cited) — отказ. Числа — самое частое место, где модель «округляет» или придумывает.

3.5. Повтор при временных ошибках

Простой цикл повтора (или декоратор из предыдущего файла):

import time

def call_with_retry(messages, max_tries=3):
    for attempt in range(max_tries):
        result = call_llm(messages)
        if result is not None:
            return result
        time.sleep(2 ** attempt)   # экспоненциальная пауза: 1, 2, 4 сек
    return None

Доработка: повторять только то, что может пройти, со случайной паузой и общим лимитом времени

call_with_retry из раздела выше повторяет любой None. С исходным call_llm это значит: неверный ключ (401) будет повторён трижды с паузами 1 + 2 + 4 = 7 секунд — и всё равно не пройдёт. Используя версию call_llm из доработки к 3.2, которая возвращает причину, можно решать осмысленно.

Ещё две вещи, которые добавляют в повтор:

  • Случайная добавка к паузе (jitter). Если десять копий контура упали одновременно (у провайдера был сбой), то с одинаковыми паузами они и повторят одновременно — и снова перегрузят сервер. Небольшая случайная добавка разносит повторы по времени.
  • Общий лимит времени. Три попытки по 30 секунд таймаута плюс паузы — это больше полутора минут на один вопрос. Потолок «не дольше N секунд на всё» защищает пользователя от ожидания.
import random
import time

def call_with_retry(call, messages, max_tries=3, base=1.0, max_total=60.0,
                    sleep=time.sleep, clock=time.monotonic, rng=random.random, log=None):
    """call(messages) -> (data | None, reason). Повторяет только reason, начинающийся с 'retry:'."""
    log = [] if log is None else log
    start = clock()
    for attempt in range(1, max_tries + 1):
        data, reason = call(messages)
        log.append(f"попытка {attempt}: {reason}")
        if data is not None:
            return data, log
        if not reason.startswith("retry:"):
            log.append("постоянная ошибка — не повторяем")
            return None, log
        if attempt == max_tries:
            break
        pause = base * 2 ** (attempt - 1) * (1 + rng() * 0.5)   # 1–1.5, 2–3, 4–6 ...
        if clock() - start + pause > max_total:
            log.append("общий лимит времени — останавливаемся")
            return None, log
        sleep(pause)
    log.append("попытки кончились")
    return None, log

# --- заглушки: последовательность ответов «сервера» ---
def scripted(*replies):
    it = iter(replies)
    return lambda messages: next(it)

pauses = []
fake = dict(sleep=pauses.append, rng=lambda: 0.0, clock=lambda: 0.0)

data, log = call_with_retry(scripted((None, "retry: HTTP 503"), (None, "retry: таймаут"), ({"ok": 1}, "ok")), [], **fake)
print(data, pauses, log[-1])
data, log = call_with_retry(scripted((None, "fatal: HTTP 401")), [], **fake)
print(data, log)
# ожидаем: {'ok': 1} [1.0, 2.0] попытка 3: ok
# ожидаем: None ['попытка 1: fatal: HTTP 401', 'постоянная ошибка — не повторяем']

В заглушке rng всегда 0, поэтому паузы предсказуемы (1 и 2 секунды) и тест не спит по-настоящему — тот же приём, что в декораторе retry из доработки 2.4 файла 02.

Типичные ошибки с повторами:

  1. Повтор неидемпотентного действия. Повторять «спросить модель» безопасно. Повторять «отправить письмо» или «записать строку в базу» — нет: при таймауте действие могло уже выполниться, и повтор сделает его дважды. Прежде чем обернуть шаг в повтор, ответь: «что будет, если он выполнится два раза?»
  2. Вложенные повторы. retry на HTTP-клиенте + retry на call_llm + retry на шаге графа = 3 × 3 × 3 = 27 попыток. Повторы ставят на одном уровне.
  3. Повтор вместо исправления. Если «временная» ошибка случается в каждом втором запросе, это не временная ошибка. Повтор её скрывает — смотри на долю повторов в следе.

Аналогия из жизни документалиста. Не попали в фокус — снимаем ещё дубль. Объект съёмки ушёл — новые дубли бессмысленны. А «переснять интервью» нельзя повторять без вопроса: человек второй раз ту же историю расскажет иначе.

Мини-упражнение. Посчитай без запуска: при max_tries=4, base=1.0 и rng, всегда равном 1.0, сколько секунд суммарно уйдёт на паузы, если все попытки неудачные и временные? Проверь, вызвав функцию.

<details><summary>Решение</summary>

Паузы бывают только между попытками, то есть три раза: 1·1.5 + 2·1.5 + 4·1.5 = 10.5 секунды.

import random, time

def call_with_retry(call, messages, max_tries=3, base=1.0, max_total=60.0,
                    sleep=time.sleep, clock=time.monotonic, rng=random.random):
    start = clock()
    for attempt in range(1, max_tries + 1):
        data, reason = call(messages)
        if data is not None or not reason.startswith("retry:") or attempt == max_tries:
            return data
        pause = base * 2 ** (attempt - 1) * (1 + rng() * 0.5)
        if clock() - start + pause > max_total:
            return None
        sleep(pause)

pauses = []
call_with_retry(lambda m: (None, "retry: 503"), [], max_tries=4,
                sleep=pauses.append, clock=lambda: 0.0, rng=lambda: 1.0)

# ожидаем: [1.5, 3.0, 6.0] 10.5

Доработка: полный контур Ступени 4 на заглушке и пять проверок перед «готово»

Ниже весь путь ступени одним куском: настройки → поиск → отказ до модели → вызов (заглушка) → проверка формата и источника → след. Каждая часть — уменьшенная версия доработок выше. Чтобы подключить настоящую модель, заменяешь только fake_model на функцию, которая делает HTTP-запрос (3.2) и возвращает текст ответа.

import json
import string

STOP = {"и", "в", "на", "до", "не", "что", "как", "сколько", "какая", "какой"}
PUNCT = str.maketrans("", "", string.punctuation + "«»—…")

def terms(t: str) -> set[str]:
    return {w[:6] for w in t.lower().translate(PUNCT).split() if w not in STOP and len(w) > 1}

def retrieve(q: str, docs: dict[str, str], min_share=0.5) -> list[dict]:
    qt = terms(q)
    if not qt:
        return []
    hits = [{"file": n, "text": t, "score": len(qt & terms(t)) / len(qt)} for n, t in docs.items()]
    return sorted([h for h in hits if h["score"] >= min_share], key=lambda h: -h["score"])[:3]

def fake_model(prompt: str) -> str:
    return '{"answer": "90 минут", "sources": ["re_kamera.md"]}'

def ask(q: str, docs: dict[str, str], model=fake_model) -> dict:
    trace = [f"вопрос: {q}"]
    found = retrieve(q, docs)
    trace.append(f"поиск: {[(h['file'], round(h['score'], 2)) for h in found]}")
    if not found:
        trace.append("отказ до модели")
        return {"answer": "не знаю", "sources": [], "trace": trace}
    context = "\n\n".join(f"[{h['file']}]\n{h['text']}" for h in found)
    raw = model(f"Отвечай JSON {{answer, sources}} только по контексту.\n{context}\nВопрос: {q}")
    trace.append("модель вызвана")
    try:
        data = json.loads(raw)
        ans, src = data["answer"], data["sources"]
    except (json.JSONDecodeError, KeyError, TypeError):
        trace.append("отказ: формат")
        return {"answer": "не знаю", "sources": [], "trace": trace}
    allowed = {h["file"] for h in found}
    if not src or any(s not in allowed for s in src):
        trace.append(f"отказ: источники {src} не из {sorted(allowed)}")
        return {"answer": "не знаю", "sources": [], "trace": trace}
    trace.append("ok")
    return {"answer": ans, "sources": src, "trace": trace}

DOCS = {"re_kamera.md": "Аккумулятор камеры держит 90 минут.",
        "tu_shtativ.md": "Штатив выдерживает до 5 кг."}

r1 = ask("Сколько держит аккумулятор камеры?", DOCS)
r2 = ask("Какая гарантия на объектив?", DOCS)
r3 = ask("Сколько выдерживает штатив?", DOCS)        # модель-заглушка сошлётся на чужой файл
for r in (r1, r2, r3):
    print(r["answer"], r["sources"], "|", r["trace"][-1])
# ожидаем: 90 минут ['re_kamera.md'] | ok
# ожидаем: не знаю [] | отказ до модели
# ожидаем: не знаю [] | отказ: источники ['re_kamera.md'] не из ['tu_shtativ.md']

Третий случай показывает, зачем проверка источника: заглушка нарочно «отвечает не про то», ссылаясь на файл, которого в контексте этого вопроса не было, — и контур это ловит.

Пять проверок перед тем, как отметить ступень «готово» (каждую — руками, а лучше тестом из файла 02):

  1. В репозитории нет ключа: git log -p | grep -i "sk-" (или префикс твоего провайдера) ничего не находит, .env в .gitignore.
  2. Вопрос, ответа на который нет в файлах, даёт «не знаю», и в следе видно, что модель не вызывалась.
  3. Заглушка модели, возвращающая прозу вместо JSON, даёт отказ, а не падение.
  4. Заглушка, ссылающаяся на несуществующий файл, даёт отказ.
  5. Заглушка, бросающая таймаут, даёт понятное сообщение, и программа не висит дольше заданного потолка.

Если все пять проходят на заглушках — подключай настоящую модель. Если что-то не проходит на заглушке, с настоящей моделью оно не пройдёт тем более, только будет стоить денег.

4.1. Состояние агента

Что такое состояние

Состояние — вся информация, которая нужна, чтобы продолжить работу с того места, где остановились.
Аналогия: паспорт + журнал + текущая задача. Без состояния каждый шаг начинается с нуля.

from dataclasses import dataclass, field

@dataclass
class AgentState:
    query: str
    step: int = 0
    max_steps: int = 5
    sources: list[str] = field(default_factory=list)
    log: list[dict] = field(default_factory=list)
    answer: str | None = None
    done: bool = False
    tokens_used: int = 0

Термины:

  • @dataclass — удобный способ создать класс для хранения данных.
  • field(default_factory=list) — правильный способ задать пустой список по умолчанию (иначе все объекты будут делить один список).

В LangGraph состояние обычно описывается через TypedDict.

Доработка: что класть в состояние, а что нет, и как сохранить его между запусками

Определение выше — «всё, что нужно, чтобы продолжить с того места». Из него следуют три практических правила.

1. В состоянии — данные, а не объекты с «живыми» ресурсами. Открытый файл, HTTP-сессия, клиент модели в состояние не кладутся: их нельзя сохранить на диск и восстановить. Состояние должно легко превращаться в JSON — тогда его можно положить в журнал, сохранить при сбое и продолжить.

2. Состояние хранит факты, а не выводы, которые можно пересчитать. step и max_steps — факты. can_continue — вывод: его лучше считать функцией, чем хранить флагом, который можно забыть обновить.

3. В состоянии есть причина остановки. Поле done: bool говорит, что агент закончил, но не говорит почему. Для следа нужно отличать «ответил», «не нашёл», «упёрся в потолок» и «сломался».

import json
from dataclasses import asdict, dataclass, field
from typing import Literal

StopReason = Literal["", "answered", "not_found", "ceiling", "error"]

@dataclass
class AgentState:
    query: str
    step: int = 0
    max_steps: int = 5
    sources: list[str] = field(default_factory=list)
    log: list[dict] = field(default_factory=list)
    answer: str | None = None
    stop_reason: StopReason = ""
    tokens_used: int = 0

    @property
    def done(self) -> bool:                    # вывод, а не отдельный флаг
        return self.stop_reason != ""

    def can_continue(self) -> bool:
        return not self.done and self.step < self.max_steps

    def to_json(self) -> str:
        return json.dumps(asdict(self), ensure_ascii=False)

    @classmethod
    def from_json(cls, text: str) -> "AgentState":
        return cls(**json.loads(text))

s = AgentState(query="сколько держит аккумулятор", max_steps=3)
s.step = 2
s.sources.append("re_kamera.md")
saved = s.to_json()                           # например, записали в файл перед вызовом модели
restored = AgentState.from_json(saved)        # программа упала и перезапустилась
print(restored.step, restored.sources, restored.can_continue())
restored.stop_reason = "answered"
print(restored.done, restored.can_continue())
# ожидаем: 2 ['re_kamera.md'] True
# ожидаем: True False

Типичные ошибки:

  • sources: list[str] = [] в @dataclass. Python здесь сам защищает: dataclass бросит ValueError: mutable default <class 'list'> for field sources is not allowed: use default_factory. Это та же ловушка, что изменяемое значение по умолчанию в функциях (файл 01, раздел 1.3), — но тут её ловят на этапе определения класса.
  • Части состояния в глобальных переменных. «Счётчик токенов я держу в глобальной TOTAL» — и при двух вопросах подряд второй начнёт с чужого счёта. Всё, что относится к одному прогону, живёт в одном объекте состояния.
  • Огромное состояние. Класть в sources полные тексты документов — значит раздувать и журнал, и сохранения. Храни имена файлов и короткие фрагменты, а полный текст при нужде читай снова.

Аналогия из жизни документалиста. Состояние — это съёмочный план с отметками: какие сцены сняты, сколько дублей, что осталось, почему сцену перенесли. Если завтра на площадку приходит другой оператор, по плану он продолжит с того же места. Камера и штатив в план не входят — их просто берут со склада заново.

Мини-упражнение. Добавь в AgentState метод snapshot(), который возвращает словарь только с полями step, stop_reason, sources и количеством записей журнала (не самим журналом) — для краткой строки в лог.

from dataclasses import dataclass, field

@dataclass
class AgentState:

    step: int = 0
    sources: list[str] = field(default_factory=list)
    log: list[dict] = field(default_factory=list)
    stop_reason: str = ""

        return {"step": self.step, "stop_reason": self.stop_reason,

list(self.sources) — копия: если кто-то изменит снимок, состояние не пострадает (вспомни ссылки и копии из доработки 1.4 файла 01).

Доработка: каждый шаг должен что-то менять — иначе потолок просто считает одинаковые круги

Посмотри внимательно на цикл выше: на каждой итерации делается тот же самый поиск по тому же запросу. Если первый поиск ничего не нашёл — цикл честно останавливается. Но если нашёл, а генерация пока не написана, следующие четыре шага повторят идентичный поиск и упрутся в потолок. Потолок сработал, но шаги были пустые: повторение без изменения — это не попытка, а ожидание чуда.

Правило для любого цикла агента: на каждом шаге что-то должно измениться — запрос, набор источников, инструмент, — иначе шаг бессмыслен. Ниже рабочий ручной цикл с двумя узлами и переформулировкой запроса после неудачи. Модель — заглушка.

from dataclasses import dataclass, field

DOCS = {"re_kamera.md": "аккумулятор камеры держит 90 минут при плюс 20",
        "tu_shtativ.md": "штатив выдерживает до 5 кг"}

@dataclass
class State:
    query: str
    step: int = 0
    max_steps: int = 4
    tried: list[str] = field(default_factory=list)
    sources: list[str] = field(default_factory=list)
    answer: str | None = None
    stop_reason: str = ""
    log: list[dict] = field(default_factory=list)

def search(q: str) -> list[str]:
    words = set(q.lower().split())
    return [n for n, t in DOCS.items() if words & set(t.split())]

def rewrite(q: str, tried: list[str]) -> str | None:
    """Заглушка «переформулировки»: подставляет синонимы. None — идей больше нет."""
    variants = [q.replace("батарея", "аккумулятор"), q.replace("работает", "держит")]
    for v in variants:
        if v not in tried:
            return v
    return None

def fake_generate(q: str, sources: list[str]) -> str:
    return f"90 минут (по {sources[0]})"

def run(query: str) -> State:
    st = State(query=query)
    q = query
    while st.step < st.max_steps:
        st.step += 1
        st.tried.append(q)
        found = search(q)
        st.log.append({"step": st.step, "node": "search", "query": q, "found": found})
        if found:
            st.sources = found
            st.answer = fake_generate(q, found)
            st.log.append({"step": st.step, "node": "generate"})
            st.stop_reason = "answered"
            return st
        q = rewrite(q, st.tried)                 # шаг меняет запрос
        if q is None:
            st.answer, st.stop_reason = "не знаю", "not_found"
            return st
    st.answer, st.stop_reason = "не знаю", "ceiling"
    return st

r1 = run("сколько работает батарея")
print(r1.answer, "|", r1.stop_reason, "|", r1.tried)
r2 = run("гарантия объектива")
print(r2.answer, "|", r2.stop_reason, "|", r2.step, "шаг(а)")
# ожидаем: 90 минут (по re_kamera.md) | answered | ['сколько работает батарея', 'сколько работает аккумулятор']
# ожидаем: не знаю | not_found | 1 шаг(а)

Что видно в этом цикле:

  • Три разных выхода (answered, not_found, ceiling) — и каждый записан. Сравни с исходным циклом, где «не нашли» и «потолок» в журнале различаются только отсутствием записи ceiling.
  • tried — защита от круга. Переформулировка может вернуть уже испробованный запрос; без списка tried цикл гонял бы два варианта по кругу до потолка (та же идея, что visited в доработке 1.4 файла 01).
  • Вопрос про гарантию остановился на первом шаге, а не потратил все четыре: идей переформулировки нет — значит, честно «не знаю». Потолок — страховка, а не нормальный способ закончить.

Типичная ошибка: continue после done = True. В исходном цикле continue возвращает к проверке условия while, и цикл выходит — это работает. Но если когда-нибудь в условие перестанут включать not state.done, continue начнёт новую итерацию поверх уже готового ответа. return (или break) сразу после решения надёжнее: намерение «здесь конец» видно в самой строке.

Аналогия из жизни документалиста. Если дубль не удался из-за шума, следующий дубль снимают, что-то изменив: закрыв окно, переставив микрофон. Снять тот же дубль в тех же условиях пять раз — значит получить пять одинаково шумных дублей и исчерпанный лимит.

Мини-упражнение. Добавь в цикл проверку «повторный запрос»: если rewrite вернула запрос, который уже есть в tried, остановиться с причиной "loop". Проверь на функции rewrite, которая всегда возвращает один и тот же текст.

<details><summary>Решение</summary>

def run_guarded(query: str, rewrite, search, max_steps: int = 5) -> tuple[str, list[str]]:
    tried, q = [], query
    for _ in range(max_steps):
        tried.append(q)
        if search(q):
            return "answered", tried
        q = rewrite(q)
        if q is None:
            return "not_found", tried
        if q in tried:
            return "loop", tried
    return "ceiling", tried

print(run_guarded("x", rewrite=lambda q: "y", search=lambda q: []))
# ожидаем: ('loop', ['x', 'y'])

Без проверки q in tried этот агент сделал бы пять шагов: x, y, y, y, y. Причина loop в следе сразу говорит, что чинить надо переформулировку, а не поднимать потолок.
</details>

4.3. LangGraph — граф состояний

Основные понятия

  • State — общий словарь (или TypedDict), который передаётся между узлами.
  • Node (узел) — обычная функция Python, которая принимает состояние и возвращает обновление состояния.
  • Edge (ребро) — переход от узла к узлу.
  • Conditional edge — переход, который зависит от содержимого состояния.
  • Потолок — либо встроенный recursion_limit, либо явный счётчик в состоянии + условие выхода.

Пример структуры (упрощённо):

from typing import TypedDict
from langgraph.graph import StateGraph, END

class State(TypedDict):
    query: str
    step: int
    sources: list[str]
    answer: str
    log: list[dict]

def search_node(state: State) -> dict:
    found = simple_retrieve(state["query"], load_chunks(...))
    return {
        "sources": found,
        "step": state["step"] + 1,
        "log": state["log"] + [{"node": "search", "found": len(found)}]
    }

def generate_node(state: State) -> dict:
    if not state["sources"]:
        return {"answer": "не знаю"}
    # вызов модели
    return {"answer": "..."}

def should_continue(state: State) -> str:
    if state["step"] >= 5:
        return "end"
    if not state["sources"]:
        return "end"
    return "generate"

# Сборка графа

graph.add_node("search", search_node)
graph.add_node("generate", generate_node)

graph.add_edge("generate", END)

Термины LangGraph:

  • StateGraph — конструктор графа.
  • add_node — добавить узел.
  • add_conditional_edges — условный переход.
  • END — специальный маркер завершения.
  • compile() — собрать исполняемый граф.
  • Human-in-the-loop — возможность остановить граф и спросить человека перед необратимым действием.

Правило: не строить четыре агента, пока один граф не врёт предсказуемо. Мультиагентный модуль курса смотреть после того, как один граф стабилен.

Доработка: запускаемый граф с циклом, редьюсером журнала и recursion_limit

Пример выше — «упрощённо»: в нём нет цикла (граф идёт search → generate → END), а журнал собирается вручную через state["log"] + [...]. Ниже — полностью запускаемый граф с теми же тремя выходами, что в ручном цикле из 4.2. Проверено на langgraph 1.2 (API LangGraph меняется между версиями; если у тебя в курсе другая версия и что-то не совпадает — сверяйся с её документацией).

import operator
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.errors import GraphRecursionError

DOCS = {"re_kamera.md": "аккумулятор камеры держит 90 минут"}
SYNONYMS = {"батарея": "аккумулятор", "работает": "держит"}

class State(TypedDict):
    query: str
    step: int
    max_steps: int
    sources: list[str]
    answer: str
    log: Annotated[list[str], operator.add]     # редьюсер: обновления ДОПИСЫВАЮТСЯ

def search_node(state: State) -> dict:
    words = set(state["query"].split())
    found = [n for n, t in DOCS.items() if words & set(t.split())]
    return {"sources": found, "step": state["step"] + 1,
            "log": [f"search#{state['step'] + 1}: {state['query']!r} -> {found}"]}

def rewrite_node(state: State) -> dict:
    q = state["query"]
    for a, b in SYNONYMS.items():
        if a in q:
            return {"query": q.replace(a, b, 1), "log": [f"rewrite: {a} -> {b}"]}
    return {"answer": "не знаю", "log": ["rewrite: идей нет"]}

def generate_node(state: State) -> dict:
    return {"answer": f"90 минут (по {state['sources'][0]})", "log": ["generate"]}   # заглушка модели

def after_search(state: State) -> str:
    if state["sources"]:
        return "generate"
    if state["step"] >= state["max_steps"]:
        return "ceiling"
    return "rewrite"

def ceiling_node(state: State) -> dict:
    return {"answer": "не знаю", "log": [f"ceiling: {state['max_steps']} шагов"]}

def after_rewrite(state: State) -> str:
    return "end" if state.get("answer") else "search"

g = StateGraph(State)
g.add_node("search", search_node)
g.add_node("rewrite", rewrite_node)
g.add_node("generate", generate_node)
g.add_node("ceiling", ceiling_node)
g.add_edge(START, "search")
g.add_conditional_edges("search", after_search, {"generate": "generate", "rewrite": "rewrite", "ceiling": "ceiling"})
g.add_conditional_edges("rewrite", after_rewrite, {"search": "search", "end": END})
g.add_edge("generate", END)
g.add_edge("ceiling", END)
app = g.compile()

def ask(q: str, max_steps: int = 5, **cfg) -> State:
    return app.invoke({"query": q, "step": 0, "max_steps": max_steps,
                       "sources": [], "answer": "", "log": []}, config=cfg or None)

r = ask("сколько работает батарея")
print(r["answer"]); print(*r["log"], sep="\n")
print(ask("гарантия объектива")["log"][-1])
print(ask("батарея работает", max_steps=1)["log"][-1])
# ожидаем: 90 минут (по re_kamera.md)
# ожидаем: rewrite: идей нет
# ожидаем: ceiling: 1 шагов

try:
    ask("сколько работает батарея", recursion_limit=2)
except GraphRecursionError:
    print("recursion_limit сработал")
# ожидаем: recursion_limit сработал

Разберём то, чего не было в упрощённом примере:

  • Annotated[list[str], operator.add] — редьюсер. По умолчанию значение, которое вернул узел, заменяет поле состояния. С редьюсером operator.add возвращённый список дописывается к старому. Поэтому узлы возвращают только свою новую запись ("log": ["generate"]), а не весь журнал. Типичная ошибка — объявить редьюсер и при этом вернуть state["log"] + [...], как в примере выше: тогда каждая старая запись удвоится.
  • Узел возвращает только изменения. rewrite_node возвращает query и log — остальные поля граф оставляет как были.
  • Цикл search → rewrite → search — именно ради таких циклов граф и нужен. В нём два потолка: свой (step >= max_steps → узел ceiling, с записью в журнал) и встроенный recursion_limit (сколько переходов разрешено всему прогону, по умолчанию — в документации твоей версии). При превышении встроенного граф бросает GraphRecursionError.
  • Свой потолок важнее встроенного. recursion_limit — аварийный тормоз: он обрывает прогон исключением, без ответа «не знаю» и без записи в журнал. Свой потолок заканчивает работу штатно, с причиной. Ставь свой меньше встроенного, чтобы аварийный не срабатывал в нормальной работе.
  • Узел-функция тестируется отдельно. search_node({"query": "...", "step": 0, ...}) — обычный вызов функции, без графа. Это удобно для тестов из файла 02.

Аналогия из жизни техника. Граф — это коммутационная схема студии: какие выходы можно соединить с какими входами. Редьюсер — правило микшера: сигналы на шине складываются, а не заменяют друг друга. recursion_limit — автомат в щитке: спасает от пожара, но выключает всё сразу.

Мини-упражнение. Нарисуй (на бумаге или текстом) схему графа выше: узлы, рёбра, подписи условных переходов. Потом ответь: может ли граф попасть в generate, не пройдя через search? Сколько максимум раз выполнится search при max_steps=3?

<details><summary>Решение</summary>

START -> search
search --sources есть--> generate -> END
search --step >= max_steps--> ceiling -> END
search --иначе--> rewrite
rewrite --answer задан ("идей нет")--> END
rewrite --иначе--> search

В generate можно попасть только из search — и только когда sources не пусты. Это и есть контракт «ответ только при найденном источнике», записанный схемой, а не надеждой на промпт. search выполнится максимум 3 раза: после третьего step == 3 >= max_steps, и переход идёт в ceiling.
</details>

4.4. Журнал шага

В каждом узле добавляй запись:

{
    "step": 2,
    "node": "search",
    "query": "...",
    "found_files": ["a.md"],
    "tokens": 0,
    "timestamp": "..."
}

Журнал — это след. Без него нельзя проверить, «итог сошёлся, а дорога врёт».

Доработка: журнал, который пишется сам и проверяется программой

Формат записи выше хорош, но если каждый узел собирает словарь руками, рано или поздно кто-то забудет timestamp или напишет found вместо found_files. Решение — одна функция (или декоратор) для записи и одна функция для проверки журнала.

import functools
import time
from datetime import datetime, timezone

def journaled(node_name: str):
    """Декоратор узла: пишет запись журнала до/после, с временем и исходом."""
    def deco(func):
        @functools.wraps(func)
        def wrapper(state: dict) -> dict:
            t0 = time.perf_counter()
            entry = {"step": state["step"] + 1, "node": node_name,
                     "ts": datetime.now(timezone.utc).isoformat(timespec="seconds")}
            try:
                update = func(state)
                entry["outcome"] = "ok"
                entry.update(update.pop("_journal", {}))   # узел может добавить свои поля
                return {**update, "step": entry["step"]}
            except Exception as e:
                entry["outcome"] = f"error: {type(e).__name__}"
                raise
            finally:
                entry["ms"] = round((time.perf_counter() - t0) * 1000, 1)
                state["log"].append(entry)
        return wrapper
    return deco

@journaled("search")
def search(state: dict) -> dict:
    found = ["re_kamera.md"] if "аккумулятор" in state["query"] else []
    return {"sources": found, "_journal": {"found_files": found, "tokens": 0}}

@journaled("generate")
def generate(state: dict) -> dict:
    if not state["sources"]:
        raise ValueError("generate без источников")
    return {"answer": "90 минут", "_journal": {"tokens": 120}}   # заглушка модели

def check_journal(log: list[dict]) -> list[str]:
    """Проверка следа: возвращает список нарушений (пустой — всё честно)."""
    problems = []
    steps = [e["step"] for e in log]
    if steps != sorted(steps):
        problems.append("шаги идут не по порядку")
    for i, e in enumerate(log):
        if e["node"] == "generate":
            prev = [p for p in log[:i] if p["node"] == "search"]
            if not prev or not prev[-1].get("found_files"):
                problems.append(f"шаг {e['step']}: generate без найденного источника")
    return problems

state = {"query": "сколько держит аккумулятор", "step": 0, "log": []}
state.update(search(state)); state.update(generate(state))
print([(e["node"], e["outcome"], e.get("tokens")) for e in state["log"]], check_journal(state["log"]))

bad = {"query": "гарантия", "step": 0, "log": []}
bad.update(search(bad))
try:
    generate(bad)
except ValueError:
    pass
print(bad["log"][-1]["outcome"], check_journal(bad["log"]))
# ожидаем: [('search', 'ok', 0), ('generate', 'ok', 120)] []
# ожидаем: error: ValueError ['шаг 2: generate без найденного источника']

Что даёт такая конструкция:

  • Запись появляется даже при ошибке — благодаря finally (тема 1.7 файла 01). Журнал, в котором упавший шаг не оставил следа, врёт как раз в самом интересном месте.
  • check_journal — проверка дороги, а не итога. Её можно запускать в тестах (файл 02, 2.6): «после любого прогона журнал без нарушений». Правила (например, «генерация только после успешного поиска») записываются кодом и проверяются на каждом прогоне.
  • Время в UTC с поясом — см. доработку 2.7 в файле 02.
  • ms — длительность шага. По ней потом видно, где контур тратит время (обычно — на вызове модели).

Что не писать в журнал: ключи API, полные тексты личных документов, весь промпт целиком на каждом шаге (он раздует журнал; хватит его длины или хэша и версии шаблона).

Аналогия из жизни документалиста. Монтажный лист заполняет не «кто вспомнит», а ассистент по каждому дублю, по одной форме, даже для брака. А проверка листа — это когда редактор перед монтажом смотрит: нет ли сцены, у которой в листе есть «смонтировано», но нет «снято».

Мини-упражнение. Добавь в check_journal правило: сумма tokens по журналу не должна превышать заданный бюджет max_tokens; при превышении — нарушение "бюджет токенов превышен: N > M".

<details><summary>Решение</summary>

def check_budget(log: list[dict], max_tokens: int) -> list[str]:
    total = sum(e.get("tokens", 0) for e in log)
    return [f"бюджет токенов превышен: {total} > {max_tokens}"] if total > max_tokens else []

log = [{"node": "search", "tokens": 0}, {"node": "generate", "tokens": 700}, {"node": "generate", "tokens": 600}]
print(check_budget(log, 1000))
# ожидаем: ['бюджет токенов превышен: 1300 > 1000']

e.get("tokens", 0) — у некоторых узлов (поиск по диску) токенов нет вовсе, и это не должно ронять проверку. Как не допустить такого превышения заранее, а не только заметить его после, — тема файла 05.
</details>

4.5. MCP (кратко)

MCP (Model Context Protocol) — способ подключить инструмент (поиск по файлам, вызов API, чтение базы) так, чтобы модель могла его вызывать по контракту.
На этой ступени достаточно одного своего простого инструмента. Не обязательно сразу строить полноценный MCP-сервер, если курс показывает другой способ.

Доработка: контракт инструмента — что именно видит модель и что проверяет твой код

Суть MCP для оркестратора: инструмент описывается именем, описанием и схемой входных данных (JSON Schema). Модель видит это описание и решает, вызвать ли инструмент и с какими аргументами. Сервер MCP выполняет вызов и возвращает результат. То есть MCP — это стандартный способ записать контракт связи (умение 3 из файла 00) так, чтобы его понимали и модель, и разные программы-клиенты.

Важное следствие: модель может прислать аргументы, не соответствующие схеме, или вызвать инструмент не к месту. Схема — это просьба к модели, а проверка — работа твоего кода. Ниже — контракт инструмента на чистом Python, без SDK, чтобы увидеть механику:

import json

TOOL = {
    "name": "search_docs",
    "description": ("Ищет фрагменты в локальной базе документации по оборудованию. "
                    "Только чтение. Возвращает до top_k фрагментов с именем файла. "
                    "Пустой список означает: в базе ответа нет."),
    "inputSchema": {
        "type": "object",
        "properties": {
            "query": {"type": "string", "minLength": 2},
            "top_k": {"type": "integer", "minimum": 1, "maximum": 5, "default": 3},

        "required": ["query"],
        "additionalProperties": False,
    },
}

DOCS = {"re_kamera.md": "Аккумулятор камеры держит 90 минут."}

def validate_args(args: dict) -> str | None:
    """Ручная проверка по схеме выше. Возвращает текст ошибки или None."""
    props = TOOL["inputSchema"]["properties"]
    extra = set(args) - set(props)
    if extra:
        return f"лишние аргументы: {sorted(extra)}"
    q = args.get("query")
    if not isinstance(q, str) or len(q.strip()) < 2:
        return "query: нужна строка от 2 символов"
    k = args.get("top_k", 3)
    if not isinstance(k, int) or isinstance(k, bool) or not 1 <= k <= 5:
        return "top_k: целое от 1 до 5"
    return None

def call_tool(args_json: str) -> dict:
    try:
        args = json.loads(args_json)
    except json.JSONDecodeError:
        return {"isError": True, "content": "аргументы не JSON"}
    if not isinstance(args, dict) or (err := validate_args(args)):
        return {"isError": True, "content": err if isinstance(args, dict) else "ожидали объект"}
    words = set(args["query"].lower().split())
    hits = [{"file": n, "text": t} for n, t in DOCS.items() if words & set(t.lower().strip(".").split())]
    return {"isError": False, "content": hits[: args.get("top_k", 3)]}

Что стоит из этого вынести:

  • Описание инструмента — тоже промпт. Фразы «только чтение» и «пустой список означает: ответа нет» влияют на то, как модель использует результат. Плохое описание («ищет всякое») — частая причина того, что модель зовёт инструмент не к месту.
  • Ошибка инструмента — это результат, а не падение. Ответ isError: True с понятным текстом даёт модели (и журналу) шанс исправить вызов. Упавший сервер не даёт ничего.
  • Пустой результат — честный ответ. content: [] для «гарантии» — это то самое «молчание инструмента — тоже ответ» из файла 00.
  • Права — в коде, а не в описании. «Только чтение» в описании не мешает модели попросить delete: true. Мешает additionalProperties: False и проверка в validate_args — и, главное, то, что в коде инструмента просто нет операции удаления.

def run(query: str, search, generate, max_steps: int = 3) -> dict:
    log, q = [], query
    for step in range(1, max_steps + 1):
        found = search(q)
        log.append({"step": step, "node": "search", "found": len(found)})
        if found:
            try:
                ans = generate(q, found)
            except ValueError:
                log.append({"step": step, "node": "generate", "outcome": "broken"})
                q = q + " ?"                      # заглушка «переформулировки»
                continue
            log.append({"step": step, "node": "generate", "outcome": "ok"})
            return {"answer": ans, "reason": "answered", "log": log}
        log.append({"step": step, "node": "refuse"})
        return {"answer": "не знаю", "reason": "not_found", "log": log}
    log.append({"step": max_steps, "node": "ceiling"})
    return {"answer": "не знаю", "reason": "ceiling", "log": log}

5.1. Класс бюджета (потолок)

Что такое бюджет в системе агентов

Бюджет — жёсткие числовые ограничения на одну задачу: максимум шагов, максимум токенов, максимум денег.
Без бюджета система может крутиться или сжечь деньги за один «интересный» вопрос.

from dataclasses import dataclass

@dataclass
class Budget:
    max_steps: int = 7
    max_tokens: int = 4000
    max_cost_usd: float = 0.10
    
    steps: int = 0
    tokens: int = 0
    cost: float = 0.0
    
    def allow(self, est_tokens: int = 500, est_cost: float = 0.01) -> bool:
        if self.steps >= self.max_steps:
            return False
        if self.tokens + est_tokens > self.max_tokens:
            return False
        if self.cost + est_cost > self.max_cost_usd:
            return False
        return True
    
    def consume(self, tokens: int, cost: float):
        self.steps += 1
        self.tokens += tokens
        self.cost += cost
    
    def status(self) -> str:
        return f"шаги {self.steps}/{self.max_steps}, токены {self.tokens}/{self.max_tokens}, ${self.cost:.4f}"

Как использовать:

# вызов модели
result = call_llm(...)

Термины:

  • Оценка (est_tokens) — примерное количество до вызова.
  • Фактическое потребление — после ответа API (многие API возвращают usage).

Доработка: три дыры в Budget — перерасход после разрешения, копейки во float и бюджет без резерва

Класс выше проверяет потолок до вызова по оценке, а списывает после — по факту. Между этими моментами и прячутся дыры.

Дыра 1. Факт больше оценки — потолок пробит. allow(est_tokens=500) разрешил вызов, модель ответила длинно и потратила 1500 токенов. consume честно списал — и tokens ушёл за max_tokens. Класс этого даже не заметил. Исправление в два шага:

  • оценивать сверху: не «примерно 500», а «промпт + максимум ответа», где максимум ответа — тот самый max_tokens в запросе к модели (файл 03, 3.2). Тогда факт не может превысить оценку по длине ответа;
  • после consume проверять, не пробит ли потолок, и фиксировать это в следе — пробитый потолок означает, что оценка врёт и её надо чинить.

Дыра 2. Деньги во float. 0.1 + 0.2 == 0.30000000000000004. На одном вопросе не страшно, но сравнение cost + est > max_cost на границе может дать неожиданный результат, а сумма за тысячу вызовов накопит ошибку. Деньги удобнее считать в целых мелких единицах (например, в миллионных долях доллара) или через decimal.Decimal.

Дыра 3. Нет причины отказа. allow() возвращает False, но не говорит, какой потолок сработал. В след нужно писать причину.

from dataclasses import dataclass

MICRO = 1_000_000          # 1 доллар = 1 000 000 микродолларов

@dataclass
class Budget:
    max_steps: int = 7
    max_tokens: int = 4000
    max_cost_micro: int = 100_000       # $0.10
    steps: int = 0
    tokens: int = 0
    cost_micro: int = 0
    overruns: int = 0

    def check(self, est_tokens: int, est_cost_micro: int) -> str | None:
        """None — можно; иначе строка с причиной отказа."""
        if self.steps >= self.max_steps:
            return f"потолок шагов {self.max_steps}"
        if self.tokens + est_tokens > self.max_tokens:
            return f"потолок токенов: {self.tokens}+{est_tokens} > {self.max_tokens}"
        if self.cost_micro + est_cost_micro > self.max_cost_micro:
            return f"потолок денег: ${(self.cost_micro + est_cost_micro) / MICRO:.4f} > ${self.max_cost_micro / MICRO:.4f}"
        return None

    def consume(self, tokens: int, cost_micro: int, est_tokens: int) -> None:
        self.steps += 1
        self.tokens += tokens
        self.cost_micro += cost_micro
        if tokens > est_tokens:
            self.overruns += 1              # оценка оказалась ниже факта — сигнал в след

    def status(self) -> str:
        return (f"шаги {self.steps}/{self.max_steps}, токены {self.tokens}/{self.max_tokens}, "
                f"${self.cost_micro / MICRO:.4f}/${self.max_cost_micro / MICRO:.2f}, перерасходов оценки: {self.overruns}")

print(0.1 + 0.2 == 0.3, 100_000 + 200_000 == 300_000)

Цифры в примере (токены и центы) условные — для расчёта по своим ценам смотри следующий раздел.

Где проверять бюджет. Не только перед вызовом модели. Если граф (файл 04) делает поиск, переформулировку и генерацию, то бюджет проверяется на каждом дорогом узле, а max_steps — на каждом узле вообще. И бюджет — один объект на одну задачу: создаётся при приходе вопроса и не переиспользуется для следующего (иначе второй вопрос получит остаток первого — та же ошибка, что с общим списком по умолчанию в файле 01).

Аналогия из жизни документалиста. Бюджет съёмочного дня: смету проверяют до выезда (оценка), а чеки собирают после (факт). Если чеки систематически больше сметы — плохая смета, и это видно, только если сравнивать. Деньги в смете считают в рублях и копейках, а не «примерно».

Мини-упражнение. Добавь в Budget метод remaining_tokens() и используй его, чтобы урезать max_tokens ответа следующего вызова: если промпт 400 токенов, а осталось 500, ответ модели можно ограничить 100 токенами вместо отказа. Отказ — только если остаток меньше 50.

<details><summary>Решение</summary>

def answer_limit(remaining: int, prompt_tokens: int, wanted: int = 200, min_useful: int = 50) -> int | None:
    """Сколько токенов разрешить ответу. None — вызывать не стоит."""
    room = remaining - prompt_tokens
    if room < min_useful:
        return None
    return min(wanted, room)

print(answer_limit(remaining=500, prompt_tokens=400))
print(answer_limit(remaining=430, prompt_tokens=400))
print(answer_limit(remaining=2000, prompt_tokens=400))

# ожидаем: None
# ожидаем: 200

5.2. Подсчёт токенов и стоимости

Многие API возвращают в ответе поле usage:

usage = raw.get("usage", {})
prompt_tokens = usage.get("prompt_tokens", 0)
completion_tokens = usage.get("completion_tokens", 0)
total = prompt_tokens + completion_tokens

Стоимость можно считать по прайсу модели (хранить в конфиге).
Для оценки до вызова можно использовать библиотеку tiktoken (для моделей OpenAI) или грубую оценку «1 токен ≈ 4 символа».

Доработка: цена из конфига, раздельные тарифы и что делать, если usage не пришёл

1. Вход и выход обычно стоят по-разному. У большинства провайдеров цена токенов запроса (prompt/input) и ответа (completion/output) отличается, и часто ответ дороже. Цены указывают за миллион (иногда за тысячу) токенов и регулярно меняют. Поэтому:

  • цены не пишутся в коде, а лежат в конфиге с датой, когда их сверили с прайсом;
  • в конфиге — единица (per_million), чтобы не ошибиться в 1000 раз;
  • если модели в конфиге нет — это ошибка, а не «бесплатно».

Цифры ниже — условные, для примера, не цены какой-либо реальной модели. Реальные смотри на странице цен своего провайдера.

import json

PRICES_JSON = """
{
  "checked": "2026-10-12",
  "unit": "usd_per_million_tokens",
  "models": {
    "model-small": {"input": 0.20, "output": 0.80},
    "model-large": {"input": 3.00, "output": 12.00}
  }
}
"""
PRICES = json.loads(PRICES_JSON)

def cost_micro(model: str, usage: dict | None, prices: dict = PRICES) -> tuple[int, str]:
    """Стоимость в микродолларах и пометка, насколько ей можно верить."""
    try:
        p = prices["models"][model]
    except KeyError:
        raise ValueError(f"нет цены для модели {model!r} — добавь в конфиг") from None
    usage = usage or {}
    pin, pout = usage.get("prompt_tokens"), usage.get("completion_tokens")
    if pin is None or pout is None:
        return 0, "usage нет — стоимость неизвестна"
    # usd_per_million * tokens / 1e6 * 1e6 микродолларов = usd_per_million * tokens
    return round(p["input"] * pin + p["output"] * pout), "по usage"

raw = {"usage": {"prompt_tokens": 1200, "completion_tokens": 300}}
c, note = cost_micro("model-small", raw.get("usage"))
print(c, f"${c / 1e6:.6f}", note)
print(cost_micro("model-large", raw["usage"])[0] / cost_micro("model-small", raw["usage"])[0])
print(cost_micro("model-small", None))
try:
    cost_micro("model-new", raw["usage"])
except ValueError as e:
    print(e)
# ожидаем: 480 $0.000480 по usage
# ожидаем: 15.0
# ожидаем: (0, 'usage нет — стоимость неизвестна')

Обрати внимание на строку с 15.0: при условных ценах выше «большая» модель на том же вопросе дороже в 15 раз. Соотношение у реальных моделей своё, но порядок различий между «маленькими» и «большими» бывает именно таким — поэтому выбор модели для шага сильнее влияет на счёт, чем любая оптимизация промпта.

2. usage может не прийти. При обрыве соединения, при потоковой передаче ответа (у некоторых API usage в потоке надо запрашивать отдельно) или у другого провайдера с иными именами полей. Нельзя молча записать 0 — это занизит расходы. Варианты: записать «стоимость неизвестна» и считать по оценке сверху (её можно взять из Budget.check), и отметить это в следе.

3. Оценка до вызова. Грубое правило «1 токен ≈ 4 символа» выведено в основном для английского текста. Для русского текста токенов на тот же объём символов обычно больше (насколько — зависит от токенизатора модели), так что правило занижает оценку. Надёжный путь — посчитать на своих данных: отправь несколько типичных промптов, возьми usage.prompt_tokens из ответа и подели на длину текста. Получишь свой коэффициент «символов на токен» для своего языка и своей модели.

def calibrate(samples: list[tuple[str, int]]) -> float:
    """samples: (текст промпта, prompt_tokens из usage). Возвращает символов на токен."""
    chars = sum(len(t) for t, _ in samples)
    toks = sum(n for _, n in samples)
    return chars / toks

def estimate_tokens(text: str, chars_per_token: float, safety: float = 1.2) -> int:
    return int(len(text) / chars_per_token * safety) + 1     # с запасом сверху

# ожидаем: 2.59 233

Доработка: что входит в ключ кэша, когда кэш врёт и что в него не класть

Кэш выше сохраняет ответ по ключу «вопрос в нижнем регистре». Это экономит деньги, но создаёт новый способ соврать: ответить старым ответом на новую ситуацию.

Ошибка 1. Ключ — только вопрос. Ответ зависит не только от вопроса, но и от:

  • корпуса документов — добавил новый файл, а кэш продолжает отвечать «не знаю», сохранённое вчера;
  • модели — сменил модель на другую, а ответы остались от старой;
  • версии промпта — исправил системную фразу (файл 03, 3.2), а в кэше ответы по старой.

Всё, от чего зависит ответ, должно входить в ключ.

Ошибка 2. Кэшировать ошибки. Таймаут или «отказ: модель недоступна» нельзя класть в кэш — иначе временный сбой станет постоянным ответом. Кэшируем только настоящие исходы: ответ с источником или честное «не знаю» по найденному (не найденному) материалу.

Ошибка 3. Кэш без срока. Даже с версией корпуса полезен срок жизни записи (TTL), особенно для «не знаю».

Пояснения:

  • md5 против sha256. Для ключа кэша md5 из раздела выше работает (это не защита паролей), но sha256 не медленнее заметно и не вызывает вопросов у проверяющих инструментов безопасности. Главное — не функция хэша, а что в него входит.

class CountingCache:
    def __init__(self):
        self.data, self.hits, self.misses = {}, 0, 0

    def get(self, key):
        if key in self.data:
            self.hits += 1
            return self.data[key]
        self.misses += 1
        return None

    def hit_rate(self) -> float:
        total = self.hits + self.misses
        return self.hits / total if total else 0.0

5.4. Circuit breaker (предохранитель)

Если внешний сервис падает подряд N раз — останавливаемся, а не долбим его дальше.

class CircuitBreaker:
    def __init__(self, max_failures: int = 3):
        self.max_failures = max_failures
        self.failures = 0
        self.open = False
    
    def record_success(self):
        self.failures = 0
        self.open = False
    
    def record_failure(self):
        self.failures += 1
        if self.failures >= self.max_failures:
            self.open = True
            log.error("Circuit breaker открыт")
    
    def allow(self) -> bool:
        return not self.open

Доработка: предохранитель, который умеет включаться обратно

У CircuitBreaker выше есть скрытая ловушка: после открытия он никогда не закроется сам. allow() возвращает False, вызовов больше нет, значит, не будет и record_success() — единственного способа сбросить open. Сервис провайдера давно ожил, а твой контур до перезапуска отвечает «модель недоступна».

Классическая схема предохранителя — три состояния:

  • closed (замкнут) — вызовы идут, неудачи считаются;
  • open (разомкнут) — вызовы не идут, ждём cooldown секунд;
  • half-open (пробный) — после паузы пропускаем один пробный вызов: успех → closed, неудача → снова open на следующую паузу.
import time

class CircuitBreaker:
    def __init__(self, max_failures: int = 3, cooldown_s: float = 30.0, clock=time.monotonic):
        self.max_failures, self.cooldown_s, self.clock = max_failures, cooldown_s, clock
        self.failures = 0
        self.state = "closed"
        self.opened_at = 0.0
        self.events: list[str] = []          # след переключений

    def allow(self) -> bool:
        if self.state == "open" and self.clock() - self.opened_at >= self.cooldown_s:
            self._set("half-open")
        if self.state == "half-open":
            return True                      # пробный вызов
        return self.state == "closed"

    def record_success(self) -> None:
        self.failures = 0
        if self.state != "closed":
            self._set("closed")

    def record_failure(self) -> None:
        self.failures += 1
        if self.state == "half-open" or self.failures >= self.max_failures:
            self.opened_at = self.clock()
            self._set("open")

    def _set(self, new: str) -> None:
        self.events.append(f"{self.state} -> {new}")
        self.state = new

now = [0.0]
br = CircuitBreaker(max_failures=2, cooldown_s=30, clock=lambda: now[0])
service_ok = False

def call() -> str:
    if not br.allow():
        return "пропуск: предохранитель открыт"
    if service_ok:
        br.record_success(); return "ok"
    br.record_failure(); return "сбой"

print([call() for _ in range(3)])        # 2 сбоя -> открыт, третий даже не звонит
now[0] = 31; print(call())               # пробный вызов — снова сбой -> open
now[0] = 62; service_ok = True
print(call(), br.state)                  # пробный успешен -> closed
print(br.events)
# ожидаем: ['сбой', 'сбой', 'пропуск: предохранитель открыт']
# ожидаем: ok closed
# ожидаем: ['closed -> open', 'open -> half-open', 'half-open -> open', 'open -> half-open', 'half-open -> closed']

Как предохранитель сочетается с повтором (файл 03, 3.5): повтор работает внутри одного вопроса и лечит короткие сбои. Предохранитель работает между вопросами: если провайдер лежит, нет смысла каждому следующему вопросу заново проходить три попытки с паузами. Порядок: сначала breaker.allow(), потом call_with_retry, и одна запись в предохранитель по итогу всех попыток (а не по каждой попытке, иначе он откроется от одного вопроса).

Что считать неудачей. Только сбои сервиса: таймауты, 5xx, 429. Ошибка 400 из-за твоего битого запроса или 401 из-за ключа — не повод отключать сервис для всех; это ошибка твоего кода или настроек, и она должна быть видна как таковая.

Аналогия из жизни техника. Автомат в щитке после срабатывания не включают сразу обратно — ждут, остывает ли линия, и включают один раз «на пробу». Выбило снова — значит, неисправность не ушла. А автомат, который после срабатывания можно включить только заменой щитка, — это CircuitBreaker из раздела выше.

5.5. Запасной путь

Если поиск пуст — не звать дорогую модель «на всякий случай».
Если модель недоступна — вернуть честный отказ, а не пытаться бесконечно.

Это уже заложено в предыдущих ступенях, здесь просто закрепляется как правило.

Доработка: цепочка запасных путей, у которой тоже есть потолок

«Запасной путь» — это не «попробовать что-нибудь ещё», а заранее записанная лестница: в каком порядке и при каких условиях пробуем варианты, и где лестница кончается честным отказом. Каждая ступенька помечается в ответе, чтобы пользователь и след видели, откуда пришёл ответ.

Типичная лестница для вопроса к документам:

  1. кэш (5.3) — если есть свежий ответ, модель не нужна;
  2. основная модель — если предохранитель (5.4) замкнут и бюджет (5.1) позволяет;
  3. запасная, обычно более дешёвая модель — если основная недоступна, с теми же источниками и той же проверкой (файл 03, 3.4);
  4. выдача найденного фрагмента без генерации — «вот что есть в документе X», без пересказа;
  5. честный отказ с причиной.
def answer_with_fallback(q: str, found: list[dict], cache: dict, primary, backup) -> dict:
    trail = []
    if q in cache:
        return {**cache[q], "via": "cache", "trail": ["cache: hit"]}
    trail.append("cache: miss")
    if not found:
        return {"answer": "не знаю", "via": "refuse", "trail": trail + ["поиск пуст: модели не зовём"]}
    for name, model in (("primary", primary), ("backup", backup)):
        try:
            text = model(q, found)
        except TimeoutError as e:
            trail.append(f"{name}: {e}")
            continue
        trail.append(f"{name}: ok")
        return {"answer": text, "via": name, "trail": trail}
    top = found[0]
    return {"answer": f"Модель недоступна. Фрагмент из {top['file']}: «{top['text']}»",
            "via": "fragment", "trail": trail + ["показан фрагмент без генерации"]}

# ожидаем: ['cache: miss', 'поиск пуст: модели не зовём']

Правила запасного пути:

  • Запасной путь не ослабляет контракт. Запасная модель получает те же источники и проходит ту же проверку «источник не выдуман». Самая частая ошибка — при недоступности основной модели позвать другую без контекста «чтобы хоть что-то ответить». Это нарушение главного правила методички, просто спрятанное в обработчике ошибок.
  • Пустой поиск — не повод для запасного пути. «Не нашли» — это нормальный исход, а не сбой. Запасной путь нужен, когда сломан инструмент, а не когда нет данных.
  • У лестницы конечное число ступенек. Цикл for по фиксированному списку — уже потолок. Не делай «пробовать модели, пока какая-нибудь не ответит» по списку, который пополняется сам.
  • via в ответе — пользователь должен видеть, что ответ дала запасная модель или что показан сырой фрагмент. Это часть честности, а не техническая деталь.

Аналогия из жизни документалиста. Если не приехал основной звукорежиссёр, пишут звук на накамерный микрофон — но в монтажном листе отмечают «звук: накамерный», чтобы на сведении не удивлялись. И никто не «дописывает» реплики, которых никто не записал.

Пример выше показывает минимальный сервис. Для контура оркестратора к нему не хватает четырёх вещей: ограничения входа, схемы ответа, понятных HTTP-кодов для отказов и проверки «жив ли сервис». И всё это можно проверить тестом без запуска сервера — через TestClient (нужен пакет httpx).

from fastapi import FastAPI, HTTPException
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field

class Query(BaseModel):
    text: str = Field(min_length=2, max_length=500)       # длинный вход = дорогой промпт

class Answer(BaseModel):
    answer: str
    sources: list[str]
    via: str
    cost_usd: float

def run_agent(text: str) -> dict:
    """Заглушка контура. В бою — граф из файла 04 с бюджетом из 5.1."""
    if "сломай" in text:
        raise TimeoutError("модель не ответила")
    if "аккумулятор" in text:
        return {"answer": "90 минут", "sources": ["re_kamera.md"], "via": "primary", "cost_usd": 0.0005}
    return {"answer": "не знаю", "sources": [], "via": "refuse", "cost_usd": 0.0}

app = FastAPI()

@app.get("/health")
def health() -> dict:
    return {"status": "ok"}

@app.post("/answer", response_model=Answer)
def answer(q: Query) -> Answer:
    try:
        return Answer(**run_agent(q.text))
    except TimeoutError:
        raise HTTPException(status_code=503, detail="модель недоступна, попробуйте позже")

client = TestClient(app)
print(client.get("/health").json())
r = client.post("/answer", json={"text": "сколько держит аккумулятор"})
print(r.status_code, r.json()["answer"], r.json()["sources"])

# ожидаем: 200 90 минут ['re_kamera.md']
# ожидаем: не знаю
# ожидаем: 422
# ожидаем: 503

Разбор:

  • «Не знаю» — это 200, а не ошибка. Сервис отработал правильно: честный отказ — нормальный результат. Ошибкой (503) мы называем только то, что сломалось: модель недоступна. Если вернуть «не знаю» с кодом 404 или 500, мониторинг начнёт считать честные отказы сбоями.
  • 422 FastAPI возвращает сам, когда тело запроса не проходит Pydantic-схему (Query). Это тот же контракт из файла 02, только на входе сервиса.
  • max_length=500 — потолок на входе. Без него один запрос с мегабайтом текста превратится в огромный промпт и счёт.
  • response_model=Answer — схема на выходе. Если контур вернёт лишнее поле (например, полный журнал с текстами документов), оно не уйдёт клиенту. В примере из раздела выше в ответ отдаётся весь log — проверь, нет ли там того, чего пользователю видеть не нужно.
  • /health — короткий ответ «жив», без вызова модели. Им пользуются Docker и облака, чтобы понять, что контейнер поднялся.

.dockerignore — обязательно рядом с Dockerfile. Строка COPY . . копирует в образ всё из папки, включая .env с ключом, если его не исключить. Образ потом могут выложить в реестр — и ключ уедет вместе с ним.

# Этап B: поиск + модель (здесь заглушка)
def run_b(query: str, docs: dict[str, str]) -> dict:
    words = set(query.lower().split())
    found = [n for n, t in docs.items() if words & set(t.lower().split())]
    if not found:
        return {"answer": "не знаю", "sources": [], "reason": "not_found", "log": ["search: 0"]}
    return {"answer": f"ответ по {found[0]}", "sources": found[:1], "reason": "answered",
            "log": [f"search: {len(found)}", "llm"]}

# Этап C: тот же контракт, внутри цикл с потолком и переформулировкой
def run_c(query: str, docs: dict[str, str], max_steps: int = 3) -> dict:
    log, q = [], query
    for step in range(1, max_steps + 1):
        r = run_b(q, docs)
        log += [f"#{step} {x}" for x in r["log"]]
        if r["reason"] == "answered":
            return {**r, "log": log}
        nq = q.replace("батарея", "аккумулятор")
        if nq == q:
            return {**r, "log": log}
        q = nq
    return {"answer": "не знаю", "sources": [], "reason": "ceiling", "log": log}

def contract_tests(run) -> list[str]:
    """Тесты, которые не меняются между этапами."""
    docs = {"re_kamera.md": "аккумулятор держит 90 минут"}

Чтобы подключить настоящую модель, заменяешь одну функцию на HTTP-вызов из файла 03 (раздел 3.2, вариант с причиной ошибки).

import json
import string
from dataclasses import dataclass
from pathlib import Path

# ---------- бюджет (05, 5.1) ----------
@dataclass
class Budget:
    max_steps: int = 7
    max_tokens: int = 4000
    steps: int = 0
    tokens: int = 0

    def check(self, est: int) -> str | None:
        if self.steps >= self.max_steps:
            return "потолок шагов"
        if self.tokens + est > self.max_tokens:
            return "потолок токенов"
        return None

    def consume(self, tokens: int) -> None:
        self.steps += 1
        self.tokens += tokens

# ---------- чтение и поиск (01, 1.6; 03, 3.3) ----------
STOP = {"и", "в", "на", "до", "не", "что", "как", "сколько", "какая", "какой"}
PUNCT = str.maketrans("", "", string.punctuation + "«»—…")

def terms(t: str) -> set[str]:
    return {w[:6] for w in t.lower().translate(PUNCT).split() if w not in STOP and len(w) > 1}

def load_docs(folder: Path, log: list) -> dict[str, str]:
    docs = {}
    for p in sorted(folder.glob("*.md")):
        try:
            text = p.read_text(encoding="utf-8")
        except UnicodeDecodeError:
            log.append({"node": "load", "file": p.name, "error": "не UTF-8"})
            continue
        if text.strip():
            docs[p.name] = text
    return docs

def retrieve(q: str, docs: dict[str, str], min_share: float = 0.5) -> list[dict]:
    qt = terms(q)
    if not qt:
        return []
    hits = [{"file": n, "text": t, "score": len(qt & terms(t)) / len(qt)} for n, t in docs.items()]
    return sorted([h for h in hits if h["score"] >= min_share], key=lambda h: -h["score"])[:3]

Как пользоваться чеклистами по-честному:

  • Отмечай дату и доказательство, а не только галочку: - [x] Тесты падают, если отказ сломался — 2026-10-20, проверил подменой return.
  • Возвращайся к чеклистам прошлых ступеней после каждого большого изменения: подключение FastAPI (Ступень 7) легко ломает обработку пустого поиска (Ступень 4), если run вызывается по-новому.
  • Пункт «Четыре агента ещё не построены» — не шутка. Это единственная галочка, которую ставят за то, чего не сделал, и она защищает все остальные.

Скрипт выше проверяет один захардкоженный файл test.md. Следующее маленькое, но важное движение — сделать из него инструмент, который:

  • возвращает код выхода: 0 — всё хорошо, 1 — файл пустой, 2 — файла нет или неправильный вызов;
  • печатает результат в стандартный вывод, а ошибки — в поток ошибок.

Зачем оркестратору код выхода: так твой скрипт смогут вызывать другие программы — тесты, CI на этапе E, другой скрипт, а позже и агент как инструмент. Они не читают текст «пустой файл», они смотрят на код выхода. Это тот же контракт, что у функции, только на уровне программы.

import subprocess

STATS = r"""
import sys
from pathlib import Path

def main(argv: list[str]) -> int:
    if len(argv) != 2:
        print("использование: python stats.py ПУТЬ_К_ФАЙЛУ", file=sys.stderr)
        return 2
    p = Path(argv[1])
    try:
        text = p.read_text(encoding="utf-8")
    except FileNotFoundError:
        print(f"файла нет: {p}", file=sys.stderr)
        return 2
    except UnicodeDecodeError:
        print(f"не UTF-8: {p}", file=sys.stderr)
        return 2
    if not text.strip():
        print("пустой файл")
        return 1
    print(f"строк: {len(text.splitlines())}, символов: {len(text)}")
    return 0

if __name__ == "__main__":
    sys.exit(main(sys.argv))
"""

Что нового по сравнению со скриптом выше:

  • main(argv) -> int — вся логика в функции, которая возвращает код. Её можно вызвать из теста напрямую: assert main(["x", "empty.md"]) == 1, без запуска отдельного процесса.
  • if __name__ == "__main__": — этот блок выполняется, только когда файл запущен как программа, а не импортирован. Без него import stats в тесте сразу запустил бы проверку файла.
  • sys.exit(main(...)) — передаёт код операционной системе. В терминале его видно командой echo $? (Linux/macOS) или echo %ERRORLEVEL% (Windows, cmd).
  • file=sys.stderr — ошибки идут в отдельный поток. Если перенаправить вывод в файл (python stats.py a.md > out.txt), сообщения об ошибках всё равно будут видны на экране.
  • p.exists() из исходного скрипта заменён на try/except FileNotFoundError — между проверкой «файл есть» и чтением файл могут удалить, а try честно ловит именно ошибку чтения (и заодно битую кодировку).

Аналогия из жизни техника. Индикатор на приборе: зелёный, жёлтый, красный. Человек может прочитать надпись на экране, но автоматика смотрит только на цвет. Код выхода — это цвет индикатора для других программ.

Мини-упражнение. Расширь скрипт: если передано несколько путей, он проверяет каждый, печатает строку на каждый файл и возвращает наибольший из кодов (то есть 2, если хоть одного файла нет; 1, если есть пустые; 0, если все в порядке).

<details><summary>Решение</summary>

import sys
from pathlib import Path

def check(p: Path) -> tuple[int, str]:
    try:
        text = p.read_text(encoding="utf-8")
    except (FileNotFoundError, UnicodeDecodeError) as e:
        return 2, f"{p}: {type(e).__name__}"
    if not text.strip():
        return 1, f"{p}: пустой файл"
    return 0, f"{p}: строк {len(text.splitlines())}"

def main(argv: list[str]) -> int:
    if len(argv) < 2:
        print("использование: python stats.py ФАЙЛ [ФАЙЛ ...]", file=sys.stderr)
        return 2
    worst = 0
    for name in argv[1:]:
        code, msg = check(Path(name))
        print(msg, file=sys.stderr if code == 2 else sys.stdout)
        worst = max(worst, code)
    return worst

Path("ok.md").write_text("строка\n", encoding="utf-8")
Path("blank.md").write_text("", encoding="utf-8")
print("итоговый код:", main(["stats.py", "ok.md", "blank.md"]))
print("итоговый код:", main(["stats.py", "ok.md", "blank.md", "missing.md"]))
# ожидаем: итоговый код: 1
# ожидаем: итоговый код: 2

max по кодам работает, потому что коды упорядочены по серьёзности. Это маленькое, но сознательное проектное решение: порядок кодов — часть контракта, его стоит записать в docstring.
